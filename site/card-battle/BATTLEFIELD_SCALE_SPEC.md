# 卡牌战棋：自由尺寸战场规范（取消固定尺寸档位）

状态：设计规范（现有16×6战斗代码尚未按此重构）。2026-11-15。

## 核心结论：不设小中大固定尺寸

**整个游戏只统一一种尺寸单位：一张人物卡的基础战术卡位（1卡）。** 每场战斗根据玩法决定实际可交互的卡位集合，不设 12×12、32×24、64×48 等强制规格，不得再发明 9 档、3 档或“超小型”固定等级。

- 地图平面范围由 `width` × `depth` 动态决定。允许 **1×1、2×1、3×2** 等极小场景，也允许 8×8、20×12、任意长度的街道和跨多区块的海空世界。
- **可交互战术区 ≠ 整个3D舞台大小**。2×1俄罗斯轮盘可以只有两个可坐/可互动的卡位，但镜头中仍然能有完整桌椅、房间、灯光、周边NPC、天气或外景；场外场景不需要人为扩展成12×12个空格。
- 战术区可以是矩形、八角形、房间走廊组合、岛屿、断续平台等任意形状；内部每个有效位置都有真实坐标。外圈/空隙可由碰撞边界、不可通行地形、海水、断崖表示，绝不使用没注册的“废弃空格”充数。
- 地图尺寸不等于镜头尺寸。小场景可全图入镜，大场景只显示交战区；远景保留真实3D环境和统一光照，战略视图可缩放巡查。
- **世界层和玩法层分开**。日夜、天气、地形、建筑、道路和场外第三方巨龙等存在于3D世界中；战棋卡位只是可以战术交互、占用和寻路的空间数据。

## 场景案例（非固定规格，不是尺寸档位）

| 场景 | 典型战术面积示例 | 如何按玩法确定实际范围 |
|---|---|---|
| 俄罗斯轮盘、双人桌前死斗 | **2×1** | 一人一个卡位；桌子、房间和旁观者可在卡位之外 |
| 一对一擂台、小型格斗 | 4×4 或 6×6 | 按移动/击退规则和场边碰撞决定 |
| 八角笼死斗 | 6×6 或 8×8 | 围栏裁切外缘、围栏可碰撞；按参战人数决定 |
| 单房间室内战 | 5×4 至 12×8 | 房内家具、门洞、掩体和射程决定 |
| 多房间/走廊 | 任意多边形组合 | 房间与走廊单独定义后连接，不强制大矩形空白 |
| 皇宫大厅 | 如 20×12 | 按王座、柱廊、回廊、门口距离决定 |
| 街道巷战 | 如 30×12 或弯折多段 | 按街区长度、巷口、屋顶可达性决定 |
| 户外广场 | 如 24×20 | 按控制点与设施建设空间决定 |
| 河桥、山崖、湖泊 | 如 40×24 以上 | 按需要的绕行、过河、制高点、落差决定 |
| 攻城与城市战 | 多个连续区块 | 按城墙、据点、内外区域和进攻路线决定 |
| 海空战 / 地下洞穴 | 任意水平范围 + 多个高度层 | 飞行航线、海面/水下、洞顶/洞底、视野与遮挡决定 |

**表中的后九个数值仅是空间估算样例，不是预设、限制或必须逐个实现的规格。** 每场战斗可直接根据玩法设置合适的宽、高、轮廓、可用面和层数；无需新增“级别”。

## 只保留一套地图引擎

1. **通用战场定义**：`battlefield = {bounds:{width,depth}, shape, topology, surfaces, layers, objects, deploymentRules}`。`bounds` 可为2×1，也可很大；可交互的 `surfaces` 可以仅有两个位置。
2. **一卡单位**：人物默认1×1；设施可1×1、2×2、3×3、多格不规则组合；桥梁按长度拼建，火车、舰船、巨龙是多格占地与3D外部事件。
3. **空间与网格严格同源**：支持正交或隔排半格交错；显示的石板、可放位置、顶层绿色合法标识、指针选取、寻路都计算自同一个坐标模型。绝不能像旧石街一样只交错砖缝、卡位不交错。
4. **没有无用空位**：地形内部所有地址都能交互/检查；实体墙、深水、悬崖等限制放置属于明确规则，不是随意留下无法使用的固定列。小场景可只定义2个可交互位置。
5. **多高度和特殊地形**：同一水平位置可以有桥面、河床、洞穴、屋顶、列车甲板或多层空域；层与层通过楼梯、坡、桥、洞口、跳跃、飞行等实际连接，改变地形要更新寻路。
6. **区块不是地图规格**：大地图内部采用16×16一类区块进行合批、裁剪、加载或更新；区块仅用于性能，地图不必是16的倍数，不会把2×1战场强迫补成16×16可玩格子。
7. **镜头按场景和操作状态选择**：俄罗斯轮盘镜头贴近桌面，八角笼能看到围栏，战棋镜头跟随交战区，战略镜头观察更大地图；人物卡在战斗镜头中保持清晰。
8. **共享3D环境**：现有WebGL真实光照、阴影、世界时钟、日夜、天气、雾和场景模块沿用同一套接口，场地变大或变小都不复制系统。

## 实现边界

这次只更新设计规范，不谎称已经改动游戏战斗引擎。旧16×6棋盘暂时运行；真正实装时先去除固定 `cols:16,rows:6`、人物/设施硬编码列，再让坐标生成、绘制、鼠标选取与物理交错对齐，并保证绿色合法位置在地面表面上方清晰可见。

**最终原则：不是“最少三级尺寸”，而是“零个固定尺寸档位、一个卡位单位、一套自由尺寸和多层3D地图引擎”。**
