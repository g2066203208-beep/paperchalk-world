# 共用角色建模程序 V1.0
用户要求：程序化建模永久写入 GitHub，新角色不复制旧页面、不重写建模系统。当前是静态核心第一版，旧版不覆盖。
## 入口
- index.html：三个历史角色同一查看器、原画对照、白模、线框、头部、JSON 导出。
- core.mjs：公共 buildCharacter、foldedCard、paintGrid、audit、render。新角色用共享 V48 基础（608点606面），通过局部坐标偏移、逐面材质、独立模块与UV贴图生成。基础不修改。foldedCard 输入每束独立三维横截点，禁止纬圈壳代替发束。paintGrid 为统一像素绘制工具，默认256画布与4像素逻辑块，实际密度需检测。
- characters.json：清道夫与医生共用源核对后提取，和早期V46的440点基线不同。枪手为原像素网格/逐面UV导入，不强换拓扑。医生V04仅为否决对照，禁止将其壳状发型当模板。example是新角色配方示例。
- textures.mjs：复用原枪手 atlas 与清道夫 V09 表情程序、医生旧脸；清道夫/医生旧身体程序材质本次仅保留基础色，不宣称原渲染逐像素一致。
## 新角色制作规则
1. 读立绘与批准资产；复制 characters.json 内 example 配方，只改角色数据，不复制HTML或渲染器。身体衣服同一可见网格，局部偏移保留原点索引。白模先验收服装轮廓。
2. 发型用 cards，每束指定左/脊/右控制点及流向，统一生成四边形和UV；不允许头盔壳替代发束。
3. 全身256×256 UV图集，统一目标80纹素/模型单位；需实际测密度。逐面bodyUV、bodyTextures由公共渲染器最近邻采样，禁止用世界空间噪点替代。眼眉嘴差分独立。
4. 公共改进先运行 node tests.mjs，再对比原画、正侧背、实际GIF。不能以静态拓扑通过当无穿模。
5. 下一阶段统一 V48 关节修形、动作/IK、布料、自交碰撞。当前未迁移正式动态系统，浏览器部署未验证。
