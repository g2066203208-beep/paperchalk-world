# 地牢电梯 · 3D 双镜头与小店布局 V0.2

- 原托管游戏主菜单「地牢电梯 · 3D 场景」 → `/dungeon-elevator/`。
- 标准1920×1080横屏：**左侧大主画面**、**右上角实时小镜头**、**右侧下方商品区与电梯操作区**。
- 点击右上角小镜头（或按V）：交换主副镜头。两个独立的 Three.js WebGL 渲染器渲染**同一**3D电梯盒子，非静态截图。
- 门口视角：半高营业门在近层、全高安全门在其后面；独立开合。门外 B0 已有五张手绘2D纸片组成的城市街道：天际线、左右街楼、路面和路灯；B1及以下是上下岩层与中间开口。
- 内部视角：转身查看空的真正3D电梯内部，目前不放柜台、不放乘客立绘。
- 顶部基础状态：楼层、金币、电力、耐久、承重、乘客数量。
- 右侧货舱：六种轻量演示商品，选中查看单价，地表可补货；逐层生成可成交的顾客需求，可售卖并实时更新金币/库存/承重。
- 大型上下行按钮、双门控制、紧急回地表（一次性）和乘客/任务/维修说明入口。
- 双门未关、超重或电力不足禁止行驶；下潜耗电；地表可维修。

## 范围与未完成项

此版本只验证双镜头、3D空间中的2D纸片搭景、地表街景与地下岩层过渡以及**最小交易流程**。B0是**从电梯门口看到的城市街道停靠景**，并非可自由行走的整座城市。美少女顾客立绘、各地下楼层的独立建筑装饰、复杂交易议价、救援/接送/运货委托、永久升级和排行榜尚未加入。UI内的货物示意图标不是已绘制的正式商品美术，不能当成完成的美术资产。

## 测试

`tests/dungeon-elevator-browser.mjs` 在真实1920×1080 Chromium + WebGL 下验证两块同时存在的3D画布、点击小镜头交换、窗口位置、门锁、超重、下潜、B1实际成交与紧急返航，生成PC与手机实际游戏截图，覆盖B0城市开门、B1岩层停靠、上下行及回到地表。GitHub Actions：`.github/workflows/dungeon-elevator-proof.yml`。

Three.js r180 使用项目内 `../sphere-maze/vendor/three.module.js` 与配套 `three.core.js`，不依赖CDN。
