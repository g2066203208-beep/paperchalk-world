# V27｜30fps 战斗导演：每一帧可查、可改、可验收

2026-11-06。用户指出：战斗中心是对高速攻击瞬间的电影化表达，而不是角色站在中心展示一秒。原 V26 的 1500ms（中间 880ms 静止）的错误方案已被删除。

## 重要的证据边界

原用户视频在上一会话记录为 **1272×702、23.3 秒、30fps、699帧**。GitHub 只有前次分析留下的四个入场/退场帧标记：入场 79 / 178 / 315 / 416；退出128 / 228 / 368 / 470。**这次会话和仓库均未找回真实视频或699张原图**。因此本文件的 V27 各帧是**原创样板导演轨道**，不是声称逐帧等同《暗黑地牢》。严格还原原作必须先得到原片。

## V27 实装：把演出真正交给逐帧调度

`ring-arena-director.js` 导出 `FPS=30`、`FRAME_MS=33.3333`、`FRAME_COUNT=21`、`DURATION=700ms`、`TRACKS`、`sampleFrame(attack,index)`。各通道为22个显式数值，包含第21帧的结束状态。每个 WebGL 渲染刷新通过同一时钟量化到帧号（60/120Hz屏幕也取同一帧），损帧时伤害事件仍只按阈值结算一次。

| 帧区间（0-based） | 时间范围 | 实际结果 |
|---|---:|---|
| 0 | 0ms | 原队列 |
| 1 | 33ms | 双人立即开始移动，镜头开始聚焦 |
| 2 | 67ms | 平移途中切换攻击图/蓄势 |
| 3 | 100ms | 平移中挥击；目标尚未进入共同中心深度 |
| **4** | **133ms** | **命中（-12，一次）**、受击图、局部FX；双人仍未完全就位 |
| 5–8 | 167–267ms | 命中后短暂慢镜感：主角回待机，目标的后退比攻击者晚一帧达到峰值 |
| 9–14 | 300–467ms | **约200ms的可读余韵**，并非原 V26 的880ms站桩 |
| 15–20 | 500–667ms | 双人分别按独立轨道迅速归位，镜头FOV单独恢复 |
| 21 | 700ms | 固定左机位、全部原始锚点和 L2D 恢复 |

镜头仅作轻量FOV与lens shift变化。由于缺少原视频逐帧测量数据，**没有凭空启用旋转/倾斜和额外全屏闪光**。

独立轨道：
- `hero[0..21]`：攻击者到中央 / 归队
- `victim[0..21]`：受击者到中央 / 归队
- `camera[0..21]`：镜头变焦和位置偏移；不再跟两个角色使用一条曲线
- `lunge`：出招前冲（峰值第4帧）
- `recoil`：目标受力后移（第6帧峰值）
- `hitFlash`、`fx`：短时局部反馈（不整屏闪）
- `damage`、`damageRise`：命中数字显隐和上移，14帧后退去

## 在实际游戏里逐帧检查

开发专用链接：

`https://g2066203208-beep.github.io/paperchalk-world/?scene=ring-arena&directorQA=1&frameInspector=1`

1. 游戏调试区滑杆是 0–21 的逐帧样本，左右按钮、播放、按键←/→。
2. 原视频区是独立 0–698 的帧索引：用户可用文件输入选择本地 MP4，浏览器将以 `currentTime=frame/30` 跳转。这个功能**不代表原作源视频已上传到 GitHub**。
3. 若用户提供原始 699 张图片或可读取 MP4，应从真实图片统计每个片段的人物坐标、立绘切换、前后冲、受击、出场、背景的投影运动，然后覆盖现有 TRACKS 数值；未知字段不填假数据。

## 验收

- `tests/ring-arena-director.test.cjs` 验证22帧、每一独立轨道、碰撞在到达中心之前、短留白、迅速退出与恢复原摄像机。
- `tests/ring-arena-browser.mjs` 验证真实 WebGL + 专用帧调节器在帧3未命中、帧4已命中、帧10 hold、帧21 完成。
- `tests/ring-arena-storyboard.mjs` 用真实 Chromium 截取完整22张 PNG、写出逐帧 timeline.json，通过 GitHub Actions artifact 下载。
- **仍未满足的艺术层**：缺真实原视频699帧；部分角色无专用受击图；换图时轮廓可能跳变；背景遮挡/光影/角色3D细节缺逐帧分析。CI PASS不代表美术已复刻原作。
