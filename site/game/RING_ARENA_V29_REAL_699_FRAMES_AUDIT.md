# V29：实际《暗黑地牢》699帧与本游戏战斗演出的逐帧审查

审查依据：用户本人上传的 `darkest_dungeon_original_699_frames_30fps.zip`。解压验证共有699张连续JPEG，每张为1272×702，原始采集时间戳30fps、23.3秒。本轮确实打开并检查原片每一段的入场前后与退场前后帧，不再依赖旧聊天转述。

**范围**：模仿节奏、聚焦方式、立绘生命周期、慢镜观感、退场和镜头结构；不会声称不同游戏美术素材实现逐像素的同图复刻。

## V29游戏真实实现时间轴（每帧独立控制）

总计 **58帧间隔 / 59个采样位置，30fps，1933.333ms**。默认单次攻击是一段演出，不能把原片所有23.3秒误当成一次技能时长。

| 游戏帧 | 时间 | 系统状态 | 视觉表现 |
|---|---:|---|---|
| 0 | 0ms | lock | 队列构图 |
| 1 | 33.3ms | swing | 两角色快速向中央运动，攻击图开始表现、镜头大幅聚焦 |
| **2** | **66.7ms** | **impact** | **原片A/B/D发生命中或MISS的相对帧；游戏在双方仍移动时结算一击** |
| 3–8 | 100–267ms | reaction | 两角色到达30%/70%中心安全位，受击者回弹，局部FX与伤害字消退 |
| **9–48** | **300–1600ms** | **hold** | **40帧中央战斗姿态留驻，不是主角/敌人换回待机图站桩** |
| 49–55 | 1633–1833ms | recover | 7帧由中央退回原始世界锚点，期间仍保留攻击/受击图 |
| 55 | 1833ms | recover | 原始锚点已到，最后一帧仍是动作图 |
| **56** | **1867ms** | settle | **只有回到原位之后才恢复原始Live2D待机图** |
| 57–58 | 1900–1933ms | done | 镜头彻底恢复固定左机位、原角色与原始L2D |

原片内命中A/B/D发生在进入中央第2帧，C在第3帧，默认游戏采用前者。未接入无伤害MISS规则；目前单张斧击卡结算一次12点伤害，不能假称已经拥有四种技能完整战斗系统。

## 此轮落实的具体技术

- `site/game/ring-arena-director.js`：分离角色、受击者、镜头、前冲、后退、局部闪光、伤害文本9条帧轨道。每一帧按30fps量化，掉帧时伤害不会重复结算。
- 真实摄像机FOV从微弱-6deg调整至-16deg，并用单一WebGL摄像机同画布绘制场景和演员。演员中央安全脚底锚点在宽度30%/70%位置，绝不靠CSS伪全屏人物海报。
- `site/game/ring-arena-runtime.js`：背景演员保留但柔和模糊与压暗，中央舞台相对突出。退场全部角色维持稳定的世界空间尺寸，由单一3D镜头回缩处理透视变化。第一次测试时额外缩小人物让主角缩进左下角，已在V29b复核后删除额外缩放；动作素材本身从未修改。
- **立绘门禁**：人物返回原始坐标（f55）之前，无论是否已经受击，绝不切回默认待机；真正切换是f56。镜头在f57以后结束。
- `tests/ring-arena-director.test.cjs` 测每帧阶段与锚点，`tests/ring-arena-browser.mjs` 测真实WebGL渲染和姿态，`tests/ring-arena-storyboard.mjs` 保存游戏59张逐帧截图及JSON时间轴供原片并排对比。

## 仍需继续的美术差距（验收不能回避）

1. 原片战斗采用专门制作的平视攻击姿态与受击姿态，当前主角的独立斧头插画构图/轮廓和背面L2D差异仍很大；无法靠时间曲线完全解决。
2. 原片四种攻击方向和MISS/伤害各异，我们游戏目前只有单角色斧击演出与敌2专属受击画作。
3. 原片有低饱和石室材质与景深、美术和UI一致的电影化构图；当前绿色符号墙3D环境和画师绘制人物仍风格不完全协调。
4. 实际色差、光影、背景动效与最终Live2D动作权重仍需要单独艺术审查。本文件不能把程序测试PASS等同于视觉完全一致。
