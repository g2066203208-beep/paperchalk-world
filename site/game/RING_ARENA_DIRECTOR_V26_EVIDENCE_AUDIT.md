## 2. V25 当前可精确计算的导演时间轴（不是原游戏原始数据）

`DURATION=400ms`, `REDUCED_DURATION=260ms`；所有参与演出的角色和镜头共用 `stageStrength=smooth((t-6)/151)*(1-smooth((t-181)/175))`。

| V25 事件 | 真正代码驱动的区间 | 问题 |
|---|---|---|
| 平移进入 + zoom | 6–157 ms | 进场速度从零加速再减速，**镜头和角色死绑同一条 ease** |
| 几乎固定中央构图 | 157–181 ms（仅24ms） | 仅约0.72个30fps帧，视觉上不形成独立的稳定舞台段 |
| 平移撤退 + zoom out | 181–356 ms | 退场175ms，姿态/背景没有独立的速度通道 |
| 主角攻击静帧 | 50–146 ms | 只有一次完整图片替换；缺真正蓄势/发力/挥击/收招逐帧切换 |
| 命中伤害 | 第117ms一次 | 伤害早于中央就位，可用；但它是任意设的样板时间，非原视频实测 |
| 目标受击静帧 | 117–211 ms | 带斩击的美术受击图一直静止，至211ms突然恢复待机 |
| 额外局部攻击FX | 约115–162 ms | 受击图本身已有红斩击，因而实际画面在额外FX结束后仍保留巨大的静态攻击光效 |

| 完成/返回待机机位 | 400ms | **和原参考中1.6–1.8s的演出观察区间不同**，但不能据此推出原攻击动画必为1.6s |

## 3. 真机截图中的问题（证据 A）

- 100ms：主角立即替换为整幅粉黑色巨型攻击插画，攻击者轮廓变大；围观敌人仍在中心后面，一位 NPC 的头部/身体与动作图重合，交锋不够独立。
- 130ms：主角攻击图、2号男敌受击图、红色斩击、白色 `-12` 同时出现；目标向后运动尚缺明确的脚步/身体重心连贯性。
- 170ms：主角立刻切回背面站姿，目标仍是被斩击包围的巨大受击图，视觉上从完整攻击插画骤变为原 L2D；**原图保留正确，过渡形状与锚点衔接不正确**。
- 190ms：与170ms构图几乎相同，缺少明确可感知的后退衰减、髋肩受力与反冲趋势。
- 返回：队列归位正常，摄像机回单个固定左机位；软件回归 PASS 证明的是状态返回，不是艺术还原。
- 所有帧：背景是矩阵式绿色符号弧壁的程序渲染，未体现按攻击回合独立的背景镜头枢轴、分层视差或聚焦模糊；**背景场景材质和暗黑地牢美术风格的差异不是本次动作调度的唯一问题**。

## 4. 镜头与背景系统硬缺项（证据 B）

| 调度维度 | V25 真正实现 | 原视频复核后所需的控制通道 |
|---|---|---|
| 缩放 | FOV outer 56→50°，inner 52→46°；只跟 stageStrength | 与攻击前后景别独立定时，必要时焦点偏移 |
| 摄影机移动 | `eye/focus` 在行动中固定 | actor-focused focal target / dolly / screen-offset，且不破坏回场原机位 |
| 旋转/俯仰/侧倾 | 没有随演出变化；`pitch=0` 写死 | yaw/pitch/roll 分开，只有原片有证据才启用 |
| 震动 | director 计算了 `shake` 但 runtime **没有应用** | 一次性随命中时钟驱动的偏移/轻微旋转，不是无限 CSS 动画 |
| 背景旋转 | 场景世界统一固定镜头，`uTime` 只让墙面的绿色符号流动 | 区分全局相机枢轴与背景独立视差（两者不能当作同一属性） |
| 景深与模糊 | 没有按演出帧控制背景 blur/focus | 单独层或轻量 shader，可开关且需要实机性能检查 |
| 非参战角色 | 世界坐标不动，最大 `uDim=.65` | 不能挡住对战主体；用可见轮廓/遮挡规则而不是只判断固定锚点 |
| 尺寸透视 | 同深度 + 动作图透明范围归一化 | **按人体高度与脚底锚点**统一攻击与待机贴图，杜绝同角色尺度跳变 |

注意：外部资料可证明原作确有 zoom/部分 tilt/背景 pivot，但没有证明**每种攻击都同时具备每个效果**。必须按四个片段分别量测，不可固定启用。

## 5. 正确的事件分离（设计契约，待原片逐帧确认后写毫秒）

1. `ENTRY`：攻击者与目标各从原队列向中央投影锚点移动，允许不同速度曲线，不允许由一个共用 k 粗糙地决定所有运动。
2. `POSE`：待机→准备→攻击→收招；每个切换以实际原视频帧号标注，切换前后脚底和头部尺度/方位保持连续。
3. `HIT`：出招动作和镜头变化可以在进入中央之前发生；需要记录源片中第一帧受击、伤害 UI、音效、闪帧的**各自真实时间**，不能默认同一帧。
4. `RESPONSE`：攻击者的前移、目标的受力后仰/后移分别绑定到角色，记录方向、最大位移、峰值时刻与复位时刻。注意目标局部美术动画的身体后仰不必等于世界坐标后退。
5. `CENTER_HOLD`：可存在稳定的双人中央构图/受击余韵；**不等于先到中央后开打**。时长必须从原片采样，UI停顿与动画本身要分离。
6. `EXIT`：动作与特效结束后角色归位，背景/镜头退回待机；需要独立于进场的退出曲线，不能沿用同一个 smooth 系数。
7. `SHOTS`：镜头位置、yaw、pitch、roll、FOV、lens shift、背景独立运动、光照/色调/blur/局部特效必须每条独立采样，不改原图。
8. `TYPE`：近战、远程、受击、暴击、未命中、友方效果、敌方回合不得统一套一个“斧柄横扫”的400ms模板。

## 6. 要达到真正逐帧还原必须补回的原始数据

原视频二进制或699张全帧 PNG（本轮不可获得）是不可代替的计量标准。拿到后逐帧输出：

`frame,time_s,attack_id,actor_id,pose_id,foot_x,foot_y,head_x,head_y,visible_box_w,visible_box_h,anchor_x,anchor_y,camera_scale,camera_dx,camera_dy,yaw_deg,pitch_deg,roll_deg,backdrop_dx,backdrop_dy,backdrop_scale,background_blur,foreground_luma,hit_fx_alpha,damage_ui_alpha,event_flag,confidence`

采用固定背景角点跟踪剥离摄像机变换，再跟踪人物脚底/头顶/躯干 ROI，明确世界位移与屏幕放大的区分；至少标记四段每次 **动作转换前后各3帧**。任何无法从帧图判断的音效和真实3D相机参数标注 `unknown`，不能从静态画面虚构。

## 7. 本轮结论与修改约束

- **已经证实**：V25 的机械性大问题是中心停留短（24ms）、人物图形切换突兀、单条曲线控制角色和镜头、镜头无动态 tilt/shake/pivot、背景固定、前冲与后退缺动作层的连续反馈。其“全部测试PASS”并非原视频还原质量 PASS。
- **尚未证实**：原参考4个片段每一帧的精确 pose、各人速度、镜头各轴角度、命中帧及背景模糊/光效；原始帧当前无法重读。
- **不允许**：把录屏1.6–1.8秒直接当成动画1.6–1.8秒；把“中央构图存在”误读为“到中央才开打”；把“已经完成进攻”误读为“一抵达中央立即离场”；用整屏红白闪光和多余文字掩盖基础画面调度问题。
- **本次只提交证据审计**。不再凭空修改真正游戏的 V25 毫秒参数、角色原图、游戏镜头或已批准的 L2D。
