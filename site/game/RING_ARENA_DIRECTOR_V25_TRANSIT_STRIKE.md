# V25｜攻击在平移过程中完成：中央不是站定后开打

## 用户纠正（2026-11-06）

**到画面中央时，战斗已经完成。** 上一个 V23/V24 的先集结到中央、中央蓄势、出招、受击、退回顺序是错误的。不能把“中央对战区”理解成先走到场地再开始战斗。要用原立绘/动作立绘的连续平移，在转场过程里完成挥击和命中。

## 正确时序（本作可调样板，非宣称原作引擎参数）

- 0–12 ms：选择攻击者与目标，锁定原世界坐标。
- 12–50 ms：双方开始向同一个中央对位区平移。
- 50–80 ms：主角在**运动中**进入攻击准备姿态；不能中央站桩蓄力。
- 80–117 ms：主角在**运动中**挥击，目标也在运动。
- **117 ms：伤害结算与打击音效，只触发一次；此刻双方尚未到达中央。**
- 117–146 ms：击中帧与受击姿态，仍在移向中央。
- 约 157 ms：双方到达中央锚点；**攻击已经结束，主角已退出攻击姿态，局部斩击 FX 已结束。** 只保留短暂受击余韵。
- 181–356 ms：两人共同平移归位，不发生新的伤害/出招。
- 400 ms：精确回到原队列站位和原固定左机位。

## 渲染与安全约束

1. 战场不切成大立绘海报：角色在真实 WebGL 世界同一个舞台，脚底固定地面，只有参与者位移。
2. 保留原始 L2D、动作原图和原世界坐标；动作贴图仅在临时 GPU staging 中整理透明外边界。其余角色不动、不消失。
3. 不在中央等待蓄力，不在中央重新起手，不叠加整屏闪白/黑幕。
4. 进场过渡、出手、伤害、受击、局部 FX 和回位采样自同一时钟；低帧率不能重复伤害。
5. Chromium QA：100 ms 要看到正在挥击且未到中央；130 ms 已受击结算；170 ms 已在中央且主角处于非攻击姿态、HP 已下降；结束时复原。
