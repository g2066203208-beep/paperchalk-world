# 1. 产品定位
游戏名称：夜行档案 / NOCTURNE FILES（暂定可改）。
品类：单人点击式生活模拟 + 城市地点探索 + 角色关系 + 情报推理 + 任务抉择 + 多结局的视觉小说演出。
平台：移动浏览器优先（竖屏完整可玩）以及 PC 浏览器；横屏与桌面提供独立精细布局，静态站点可经 GitHub Pages 托管；无服务器和密钥依赖。
剧情基调：明亮、有人情味的大学日常，与克制冷峻的职业秘密形成强烈对照。紧张感来自信息缺口、时限、信任、道德后果、双重身份冲突，而不是血腥镜头。禁止把现实犯罪的操作技巧做成可迁移的教学内容；行动解决采用叙事抽象、场景选择、风险标记、后果模拟。
主角：20 岁大学生，白天参加课程、社团与打工；夜晚被隐秘的“午夜事务所”雇佣执行危险委托。组织具有不可靠动机，并非天然正义；任何目标和委托都须具备可调查的背景、可能的误导与玩家可作出的道德选择。
世界：原创海滨城市“雾港市”，密集但有辨识度；不是东京复刻。校园、旧城区、商业站前、滨河街区、艺术区、临港仓区；地图可扩充但第一阶段不要开放全部。

# 2. 设计支柱（优先级由高到低）
A. 自由安排时间：玩家在多个合理活动中选一天的去处，选择确实改变关系、信息、技能与未来机会。
B. 调查必须依靠推理：被玩家确认的线索产生新判断，错误假设可能带来不理想后果，但不能以随机猜测强迫刷选项。
C. 演出像交互电影：场景构图、前后景、眼神、人物入场退场、光、声音和镜头节奏推动情绪；每个时刻可以交互而不是纯播放。
D. 手机原生舒适度：竖屏不能只把横屏缩小；按钮可点、文字可读、日志可看、无需拖拽虚拟摇杆。
E. 资产可控：角色设计母版锁定，多表情、多姿态同一身份且关节连续；GPT 图像用于生成美术，不用其输出整套“假 UI 截图”直接投入产品。
F. 维持开发纪律：小范围做好、截图检查、自动化回归、再扩展；重要分支先在 Demo / 工作室测试，不影响 main。

  参考：https://persona.atlus.com/p5r/
- HITMAN World of Assassination / Freelancer：简报、情报收集、玩家主导准备和任务后果；将真实世界行动流程抽象为游戏事件，不细化现实伤害与规避调查办法。
  参考：https://ioi.dk/hitman/blogs/freelancer-you-are-in-control
- The Case of the Golden Idol / The Rise of the Golden Idol：从场景点选线索，并让玩家自己构造解释，线索组合不等于自动提示答案。
  参考：https://store.steampowered.com/app/1677770/The_Case_of_the_Golden_Idol/
- 13 Sentinels: Aegis Rim：人物剪影与背景绘画结合、镜头移位、场景演出、角色之间信息交错；研究演出节奏，不复制设计。
- Ace Attorney Investigations：证据关联、角色矛盾、阶段性事实推断；借鉴调查反馈方式。
- Ren'Py：考察视觉小说脚本与移动发布思路，但不能未经论证替换仓库原生 Web 工作流。
- 原仓库 studio/：借用静态部署、存档生命周期、手机安全区和可测试模块的经验；不直接耦合到现有 3D 渲染循环。

# 4. 一句话玩法与每天的闭环
一个游戏日：查看消息和日历→决定上课/打工/交友/调查→在地图上选地点并抵达→在立绘和场景中点选、交谈、收集信息→花费时间推进世界→夜间选择休息、普通活动或接触委托→结算学业、关系、精神负荷、风险、线索→推动分支与下一天。
行动必须有成本、有反馈、有后继效应。不能只有“点击选项加好感”而没有新事件。日常不是任务前无意义的等待；要有能独立成立的角色短篇和生活情绪。

# 5. 时间系统
采用日历日、星期、时段，初始 4 个时间块：上午、放学后、傍晚、深夜。前两个可因固定课程锁定或自动结算。使用具体活动持续时间（如 1 块/2 块），跨时段回到日程板；从不要为每次查看道具强制消耗时间。
每个 NPC 有每周出现规律 + 剧情覆盖规则 + 特别日触发条件，禁止全员每时段站在同一个位置。
学生身份至少有课程出勤、考试、作业、社团、经济花销；缺课要有温和但真实的影响。深夜连续行动影响第二天的体力、注意力和情绪，但不强迫睡眠模拟。
委托有明确的截止时间和替代路径。到期后进入后果分支，不出现不可挽回的无提示软锁；倒计时不采用真实时间，只采用游戏内时间。
时间推进由可测试的中心 GameClock 负责，UI 显示只是订阅状态。

# 6. 地图与地点
大地图为原创线路图 + 区域块，可放大浏览。地图节点展示地点名、开放时段、活动、相关人物、新事件、交通耗时；锁定节点说明解锁条件（不泄露故事）。
首个纵向切片只做 4 个有意义的地点：大学教室/校门、咖啡店、主角卧室、站前广场；再做一个随任务临时解锁的“展馆”场景。
地点探索采用可点选的热点，场景拥有前景/中景/远景/角色/可交互物件/环境音/光线状态。点击热点要触发有效反馈：短描述、信息、人物交谈、使用物件或启动事件。
移动本质是地图场景切换和清晰的旅行转场，不伪装成一个不能真正行走的开放世界。

# 7. 角色与关系系统
主角：默认为 20 岁大学生，性格随玩家选择改变，不锁定为绝对冷血，也不定义玩家必须无条件完成任务。
同伴示例：
- 林见夏，摄影社负责人，善观察，温暖但有自己的秘密；
- 许渡，咖啡店夜班店员，擅记人事，对谎言高度敏感；
- 季遥，大学助教，严格且重视学生前途；
- “接线员”，午夜事务所联络者，动机隐蔽；
- 顾言，校园中与首个委托存在关联的人物，有自身利益与立场。
以上为创作提案、非既定设定；每人制作人物档案、三层愿望（表面/隐藏/不可退让）、关系节点、每周行程、可解锁场景、4—8 种表情、3 种以上动作姿势。
玩家关系不是单一好感数字：至少包含亲近 trust、怀疑 suspicion 和个人事件标志；部分能力或信息通过朋友关系解锁，玩家若疏远他们仍要保有替代解决路线。
对白有角色口癖，但不过度卖弄谜语；最重要的事件被玩家选择实际影响。

# 8. 调查与线索板
故事线索类型：人物证言、公开记录、地点观察、物件细节、时间矛盾、内部留言；每条线索有 id、来源、游戏内时间、可靠度、可见内容、支持/反驳的假说。
线索板有三个视图：线索档案、时间轴、假说面板。玩家拖放可作为桌面加分，但手机必须支持两次点击完成线索配对；不强迫精细拖动。
核心玩法：通过“线索 A + 线索 B”提出假说，系统回应“事实得到支持/存在矛盾/缺乏佐证”。不能点击任意两个东西就给正确答案。
允许保留多个假说。情报不足仍可接受委托行动，但是结局的不确定性上升。不可把“没找到全部线索”直接视为失败。
每场调查约 3—7 个有意义的热点、2—4 条关键线索和至少一次需要思考的冲突。

# 9. 委托与夜间任务（叙事抽象，不提供现实可迁移的违法操作流程）
任务状态流：
提案→接受/延后/拒绝→背景调查→提出动机假说→选行动风格（谈判、揭露、秘密交涉、强硬处置等剧情化选项）→电影化互动事件→撤离场景→次日舆论与关系反响→组织评估→主线更新。
“杀手职业”的戏剧性可以包含致命结局，但呈现必须作为虚构叙事和后果系统，不详述真实伤害实施、逃避执法或处理犯罪痕迹的可操作步骤。
行动前可选的内容是系统级策略卡：时间窗口、情报完整度、身份风险、行动目标、是否邀请协助、是否坚持个人底线；这些仅影响剧情变量和事件路线。
任务不能只有成功/失败，至少覆盖：完成组织目标、偏离指令但达成个人目标、误判后补救、拒绝执行、发现委托有假、以非致命方式化解、暴露身份后代价。复杂后果跨日出现。
任务表现采取短场景节点和清晰选择，不做射击操作也不做血腥动画；重点是推理、压力、角色与代价。

# 10. 主线结构提案
第一幕《陌生人的照片》：新学期第一周，主角收到一份看似普通的校友照片整理委托，随后发现照片和“午夜事务所”的名单有关。首个关键任务要求判断组织指定对象是否真的符合简报描述。
第二幕《两张课表》：校园日常与夜间情报相互重叠；身边人的秘密逐渐浮现，主角不得不在个人关系与组织合同之间选择。
第三幕《无人签收》：组织内部相互矛盾的委托暴露其真正目的，玩家曾经保存的证据、拒绝过的任务、保护或伤害过的关系将决定结局。
纵向切片只制作第一幕前 25—35 分钟：一个完整日程循环、一段调查、一个有三种不同结果的委托，以及次日回响；不要开做整部游戏。
每 3—5 分钟要有新的可互动节点，每段 10—15 分钟要有明确的情绪或玩法变化；不允许连续长篇自动对白掩盖玩法匮乏。

# 11. 电影化演出语言
每个剧情节点要能描述：镜头类型（全景/中景/近景/特写）、构图焦点、推拉或平移、景深层次、人物入场与目光、微动作、背景光照、氛围音、音乐起止、文本出现时机、停顿、玩家控制恢复时机。
定义可测试的指令 DSL：scene, camera, enter, move, emote, look, show, hide, sfx, music, wait, dialogue, choice, setFlag, grantClue, advanceTime, goto；所有指令必须可取消、可跳过、可回放，不能因为点击过快造成残影或无限等待。
日常演出色调：清透的天气、自然散射光、几乎能听见远处街声；夜间演出：路灯、车窗反射和有限冷光，克制不廉价的红黑覆盖；雨夜重点做水汽和色温，而不是大量耗电的 GPU 后处理。
不把电影黑边长时间占满手机；大幅画面变化必须保持字幕可读。关键镜头静止 0.2—0.8 秒用于情绪呼吸，但玩家可以在设置中加速或关闭镜头运动。
剧情推进、跳过、自动、历史日志、文字速度、音量、振动开关都必须在首阶段具备基础实现。

# 12. 原创美术方向
主旨：“清爽都市绘本 × 克制的胶片悬疑 × 精密杂志排版”。沿用 Paperworld 擅长的分层纸张光影思想，但不能照搬旧工作室 3D 地形，也不能仿造 Persona 5 的剪影商标风格。
白天：暖白、石青、海沫绿、橙黄色局部；线条清晰、服装纤维质感少量。夜晚：深蓝灰、霓虹暖金、少量信号橙；饱和度限制，避免一屏所有角落都有高光。
角色立绘：原创成年人物的现代生活服装，简约但具有功能性剪裁、衣料分区、个人习惯配件；头部形体一致、五官特征固定；统一视角为正面、左/右 3/4 与侧面，镜头高度一致。表情与动作可替换，不能每张图换一张脸。
场景：横向主构图留出人物活动空间，额外延展两侧供移动镜头；同一地点至少日/黄昏/夜 3 个光照状态；生成静态素材，再人工配置人物遮挡和交互区域。
动画：先要求肩肘髋膝自然、透视关系一致、动作停顿合理；分层仅对真正需要动作的角色做关节拆分。生成图片不是天然带分层文件，所有拆件需检查边缘覆盖与补画。
UI：GPT 图像生成用于情绪板、装饰素材、角色、场景和图标概念；实际日历、按钮、文本、线索卡、地图热点和响应式排版使用真实 HTML/CSS/SVG/Canvas 渲染。坚决不把不可点击的 UI 整图铺在屏幕上。
风格一致性检查每张图：脸部结构、手部、服装母版、边缘清晰、阴影方向、背景抠图、边缘抗锯齿、透明像素、脚底接触与比例。失败要局部重绘后再入库。
素材命名采用可预测约定：char_protag_base_v001.webp / char_protag_eyes_happy_v001.webp / bg_cafe_evening_v001.webp / ui_tab_dossier_v001.svg 等；每个文件附 manifest 的尺寸、适用镜头、锚点、制作状态和来源授权说明。

# 13. GPTimg 生成工序与提示词范式
先做 Style Bible，含 3 个角色设计母版、服装色号、统一脸型三视图、3 个场景光照基准和 UI 排版基准；在样张验收前禁止批量生成数十张资产。
角色提示词模板：
“原创现代都市悬疑视觉小说的成年人角色全身立绘。角色 ID: [ID]。严格遵循已确认角色母版：[固定面部轮廓、眼距、眉形、发型、身高比例、衣服缝线/图案]。镜头 [正面/3-4]、人物从头到鞋完整可见、全身自然站姿、手指完整、双臂不遮挡肘和腰、光照一致、简约却精心设计的现代服装、清晰线稿与克制的柔软体积色块、少量纸张色面、统一写实漫画比例、可清理背景。不得增加未经确认的饰品，不得更换服饰，不得截断身体，不得文字与水印，不得混入他人角色。”
场景提示词模板：
“原创海滨大学城地点 [地点]，[季节时段天气]，现代都市绘本与克制电影悬疑结合，布局必须保留 [人物站位安全区] 和 [热点 x,y]，前中远三层清晰、自然透视，稳定光源，不含人物、不含 UI、不含可读商标和水印，足够高解析度，适合 2D 分层背景与轻微镜头平移。”
UI 视觉概念提示词模板：
“原创 mobile-first 游戏界面风格稿，功能为 [日历/地图/档案]，信息层级 [标题→核心状态→主要交互→附属]，强调字体清晰、按钮尺寸、对比度、留白和冷暖对照，极少装饰，提供横屏与竖屏两种参考构图。此稿只供视觉评审，真实 UI 由代码重建，不生成伪按钮成品。”
所有图片生成必须先比较母版并通过：轮廓一致、风格一致、手部/五官正确、背景兼容、可动画性、手机缩放下细节可读、原创性；否则修复或淘汰，不能因为“看起来勉强行”而进入正式资源。

# 14. UI 信息架构
首屏：继续游戏、新游戏、章节、设置、制作信息。
常驻游戏 HUD：日期/星期/时段、当前位置、简洁当下目标、手机入口、地图入口、日志入口；非必要浮窗折叠。
手机应用内页：消息、联系人、任务、日历、线索板、角色状态、设置；手机是故事内“工具”，不是主机界面套手机截图。
地图页：地点节点、时间成本、可用活动、角色出现条件、有效任务标记；以点选进入地点。
日程页：今天四时段列表、可以安排的活动、已有约定、行动后时间预览；“完成这一天”总是可用但弹出确认。
调查页：场景热点高亮可开关、物件详情、可追溯证据卡和有意义的假设系统。
委托页：合同摘要、委托人的主张、已证实/未证实、风险、预计叙事后果、接受或拒绝；避免把机械胜率写成绝对保证。
任务结果页：即时结果、影响的关系和世界标志、可能在未来触发的提示；不过早剧透完整因果。
对话条：角色名、文字段、表情、继续提示、自动/跳过/日志；对话选项在窄屏垂直堆叠，绝不挤成一行。

# 15. 手机适配及可访问性要求
以竖屏 390×844 CSS px 为第一布局基准；同时测试 360×800、430×932、844×390、1024×768、1366×768；极短屏应在不截断关键控件的情况下滚动或折叠。
安全区使用 viewport-fit=cover 及 CSS env(safe-area-inset-*)，动态视口使用 dvh 及后备；浏览器地址栏出现/收起、软键盘出现、旋转、后台恢复都必须保持交互可见。
触控热区目标遵循 iOS 44×44 pt 与 Android 48×48 dp 指南（网页以接近的可触摸 CSS 尺寸测试）；相邻可点控件留足空隙；所有手势均有单击替代方案。
字重、字间距、中文断行优先保证手机清晰可读。正文一般不低于 15—16 CSS px；对比度达到 WCAG 常见文字至少 4.5:1 的目标，辅文信息可放大而不是压低亮度。
动效支持 prefers-reduced-motion，禁音不妨碍任务，关键变化有文字提示；Tap、Enter、Space、Escape、浏览器返回键都需要正确语义。支持键盘焦点与可见焦点框。
不要强制横屏；横屏采用横向舞台加侧栏，竖屏采用舞台/立绘区域加抽屉式交互，不是整体缩放。

# 16. 技术架构
因为宿主仓库已有无需打包的原生 JavaScript 和静态 Pages 发布体系，预制作阶段优先：ES Modules + HTML/CSS + SVG 真实 UI；演出渲染按复杂度选 Canvas2D 或已核对许可和体积的 PixiJS；不要为几张背景就引入一套 3D 世界。
建议项目模块：
app/boot.js 启动、设备能力、场景路由；
core/GameState.js 纯状态与版本；
core/GameClock.js 时间推进；
core/Scheduler.js NPC 行程与地点事件；
core/ConditionEngine.js flags/条件/后果；
core/SaveStore.js IndexedDB 及 localStorage 回退、版本迁移；
story/Director.js 演出时间轴与可跳过指令执行；
story/Dialogue.js 对话与选择；
systems/MapSystem.js 地图地点与转场；
systems/RelationshipSystem.js 关系与社交条件；
systems/ClueBoard.js 线索与假说逻辑；
systems/MissionSystem.js 委托状态机；
ui/ 显示组件与输入逻辑；
assets/ 美术、音频、 manifest；
content/chapters/ 剧情脚本及多语言预留；
tests/ 单元测试、剧情状态校验、屏幕视觉回归。
状态推进必须是统一的可序列化事件，UI 不应该直接任意修改数值；演出系统只消费剧情状态或通过受控命令改变状态。
剧情 JSON 文件要含 id、先决条件、触发时段、对象、人物、转场、台词、选项、副作用、后继节点和失效条件。每个选择要有默认失败路径、不可达检测、所有引用 ID 有效性校验。
存档版本号与原项目命名空间隔离，例：nocturne.save.v1.slot1；至少手动存档 3 栏、自动存档 1 栏，提供导出/导入 JSON 的版本校验；不承诺云同步。
禁止暴露 GPT 图像 API key 于 GitHub Pages。所有图片必须预生成、经过人工/程序校验后作为静态资源发布；未来如需动态图片服务必须独立安全后端，不能把用户登录态等同 API 授权。
发布开发预览与稳定版隔离；首次开发保留 404/图片加载失败占位、加载进度、错误提示。尽可能不依赖跨域第三方字体或运行时 CDN。

# 17. 演出脚本示例（说明语义，不要求逐字保留）
节点 ID：chapter01_afterclass_call
条件：day=1 AND period=afternoon AND saw_campus_intro
场景：校门前，阴云黄昏；环境音为路灯嗡鸣与远处电车。
动作：画面从街道全景推向主角中景，远处朋友挥手离开。主角手机振动。
字幕：“未知联系人：你确定那张照片拍摄于昨天吗？”
玩家选择：
1 “检查照片细节”：获得 clue_photo_clock；推进 0 时段，改变推理入口。
2 “先去咖啡店”：地图开放 cafe_evening；消息悬而未决，许渡可提供另一条线索。
3 “回复：你是谁？”：联络者回应更少，但新增可调查的用户名记录。
变化通过状态引擎计算；三条路径最终可以走入首个调查任务，不能因为先后顺序不同丢失剧情。
演出应包括镜头、音乐淡出、人物表情和点击响应；跳过时要将未执行的必要状态变化一次性应用且不能重复执行。

# 18. 纵向切片范围与具体交付
纵向切片预计一段有头有尾的 25—35 分钟可玩内容，至少具有：
- 首屏、设置、开始/读取；
- 4 个日常地点 + 1 个任务地点，每个含完成的美术和热点；
- 一套可见日历，2 个完整游戏日的可选活动；
- 至少 3 个有角色辨识度的 NPC，关系选择引发不同对白；
- 1 个由 4—6 条线索构成的推理问题，允许遗漏与错误路线；
- 1 项短委托，包含接受、调查、决定、电影化交互、次日后果；
- 任务至少 3 个实质不同结果，其中至少 1 个非致命解决路线；
- 3 个可用存档位 + 自动存档；
- 完整手机竖屏和横屏适配，不存在必须旋转屏幕才能点到的操作；
- 真实立绘及背景美术（不是色块占位的最终宣称），基础音乐/环境声和静音；
- 可跳过剧情、日志和减弱动效选项；
- 浏览器刷新状态保留，错误有可见提示，GitHub Pages 子路径资源不 404。
首个迭代若无法获得完整美术，可以用明确标注的“临时素材”先验收机制，不可以冒充最终美术已完成。

# 19. 阶段、门槛与停止条件
P0 预制作：研究来源、GDD、主角和两位配角设定、一个周循环、一个完整委托剧情图、UI 三套响应式低保真线框、技术 PoC。产出并评审后再大批生产。
P1 可玩逻辑：日期推进、地图、节点事件、状态、存档、对话、选择、推理的完整闭环；不急做精细动画。
P2 视觉切片：先做一个日常场景和一个夜间场景，角色母版、表情切换、6—10 个镜头事件、声音；逐帧检查。
P3 垂直切片：打通 2 天 + 1 项委托，边玩边记录所有分支，完成平衡和反馈。
P4 手机、稳定性及可访问性验收：真实手机在竖/横屏连续玩完；弱设备降级；资源缓存与离线体验按测试结论决定。
P5 章节扩展：只有在 P3/P4 通过之后再增加大地图、角色和任务，不承诺一次性造完整开放城市。
每个阶段需要：代码变更列表、可运行入口、至少一项图像对比、自动测试、交互人工测试、已知问题和下一步。未实际运行不得写“已经测试通过”。

# 20. 验收与质量红线
[功能] 连续完成 2 天后，时间、NPC 位置、关系、线索和故事分支符合设定；回读存档后不重复领取线索。
[分支] 每个对话选项都有正确来源和目标，用户可以拒绝委托而故事继续；不因漏线索造成永久卡死。
[视觉] 同一角色不同姿态脸不漂移、服装一致、动作没有缺口；背景热点与视觉物件准确对位。
[适配] 360px 竖屏时正文和按钮不越界；刘海、底部系统手势区不遮挡；横竖切换无重复事件处理。
[性能] 中档手机目标交互动画稳定、场景首屏尽量控制在合理加载时长；实际目标通过测试设备测量并调整。按需加载音图素材，限制并发与 GPU 内存。
[持久化] 页面隐藏时存档；浏览器拒绝存储时显示错误与导出方法，不把失败提示为成功。
[工程] 原有 studio/、主站、发布工作流测试保持不变；新游戏测试独立可运行；所有资源都用稳定相对路径。
[产品] 每次日程抉择都对未来至少一个可观察结果有影响；每个地点有至少一个真实互动价值；每场任务至少一处剧情意外。
[版权] 使用自有或明确有授权的图片、音乐、字体；参考截图只用于研究，生产资源禁止像素级复刻。
[诚信] 不要夸大完成度；不要声称 GPTimg 可以稳定自动生成分层 PSD/Spine 资产；每个“可用”都要有可运行验证。

# 21. 接下来要执行的第一条开发命令（给开发团队的自然语言）
“在不触碰 Paperchalk World 原工作室和主站的前提下，先做独立的新游戏工作室。第一步产出 390×844 手机竖屏和 1366×768 PC 的原创、真实可交互首页与日程/地图/对话最小闭环；选一处校园背景、主角一张经过验收的静态立绘，制作日→晚的真实场景切换；先实现读写存档和两次有后果的选择。拍摄/截图逐项检查，运行新增回归测试，列出缺陷，再继续下一次迭代。禁止未经验证直接宣布完成。” 

# 22. 与用户沟通的要求
开发前清楚标出：参考游戏里哪些“机制”值得学，哪些外观绝不应复制；给用户看三种具有辨识度的 UI 方向供挑选，默认推荐“生活日历/夜间档案”的双视觉系统。
永远保留验收入口；每轮不是汇报一大堆技术名词，而是说明玩家现在能完成什么、截图里是什么样、存档在哪儿、与计划相比还缺什么。
优先让游戏有动人的一段 20—30 分钟，而不是堆出一整页几十个虚假的按钮。

# 23. 后续可扩展内容（不是首版承诺）
完整学期课表、兼职经济、可选择居住风格、天气与节假日、随机同学事件、每名同伴单独感情线、更多城市地点、组织内部关系、跨章委托链、照片和通讯软件谜题、服装变化、照片相册、更多结局、桌面和移动端存档迁移。

# 24. 真正开始游戏制作前必须追问的一个核心美术决定
在充分展示三种原创视觉方向的独立设计稿后，请用户选定其中一个。没有定下 UI 语言和人物立绘母版，不进行昂贵的大规模出图。
