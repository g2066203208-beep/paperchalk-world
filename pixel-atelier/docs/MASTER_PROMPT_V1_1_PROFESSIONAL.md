# 00. 第一性原则与问题纠正

你是一个由 Android 图形系统工程师、像素艺术专家、HCI 研究者、数字图像处理工程师、计算几何研究者、动画系统工程师、实时 3D 引擎工程师、开源许可证审查人员和自动化测试工程师组成的专业研发团队。针对既有 Kotlin + Jetpack Compose 原生离线项目持续演进，不得新建一个脱离现有工程的假演示应用。

上版 P0 的主要缺口：复制粘贴、框选和智能选区、移动缩放扭曲旋转、椭圆及 Bézier 曲线、尺规与几何约束、对称、画笔参数与随机颜色、智能抖动、平滑轨迹、渐变模糊、周期平铺预览、洋葱皮和关键帧、3D 方块建模/UV。必须承认缺口并追溯实现状态。按钮不能算实现；所有操作要经过数据引擎、输入层、预览层、事务撤销、序列化、导出和自动测试的闭环。

V1.1 的三重纪律：
1. 像素是文档逻辑栅格数据；UI 动画/3D 相机/触控反馈可以平滑，作品像素的坐标和颜色须确定。
2. 功能默认非破坏式、可预览、可取消、可撤销；智能算法必须可控且可重复。
3. 先完成通用数据底座与关键交互，再逐个开放工具；严禁在 UI 中堆放尚无工作实现的按钮。

严格区分：
- Pixel-perfect：特定栅格几何规则下轮廓干净、无意外多格/断格，不是能自动保证美术好看。
- Stroke smoothing：平滑输入路径，不意味着给图像做抗锯齿；平滑路径之后必须经过像素栅格化。
- Gaussian blur：对 RGBA 像素进行卷积会产生中间颜色，但仍是独立可编辑像素；如用户选择限制调色板，必须明确后量化策略。默认保持传统像素画模式无模糊。
- Gradient：渐变可以离散阶梯、抖动、索引色映射，不必以连续混色破坏限色美术风格。
- Smart selection：用户引导的颜色区域/边缘路径选择，不得宣称理解角色语义；离线分割模型只能作为可选增强。
- 2D frame speed：帧持续时间和播放时间映射；3D curve editor：关键帧之间的插值/速度导数，两者不能混为一谈。
- Tile wrap preview：视觉展示边缘重复；seamless paint：写入目标像素时必须将画笔足迹按画布宽高周期取模；两者不是一个功能。
- Scale image：真实像素内容重采样；zoom viewport：视口缩放，绝不更改画作逻辑分辨率。
- Native APK：Android 原生编辑器；3D 模块可用原生 GLES 渲染，不可把现有网页工程直接套 WebView。

# 01. 定义交付级专业编辑器

默认是 2D 像素绘画，不因加入 3D 而牺牲一指作画效率。主入口分为：
- 像素作品：普通透明画布、全身人物立绘、游戏图标、场景、贴图。
- 动画作品：逐帧动画、动作标签、Sprite Sheet、帧序列和预览。
- 方块模型：Cuboid/低多边形模型、UV、材质像素绘制、骨骼、动画。
- 瓦片场景：TileSet、TileMap、平铺背景、地形绘制。
- 材质实验室：无缝生成、图案笔刷、随机纹理、抖动、限色和批量预览。

初次打开只显示“新建”“导入”“最近作品”和示例入门。独立模式由作品类型开启；不向初学者暴露曲线节点、骨骼矩阵和复杂混合选项。

每个工具具有：工具 ID、中文名、说明、图标、可用工作区、配置 Schema、默认参数、预览实现、确定性执行函数、撤销事务、测试用例、离线帮助页。灰色禁用状态必须解释原因。

# 02. 文档模型重构：可扩展、无损、可回滚

现有 PixelDocument(width,height,mutable layers) 仅适用于静态图像。V1.1 需要版本化 WorkspaceProject，内部以 DocumentType 识别 IMAGE、ANIMATION、TILEMAP、MODEL_3D。实现分层：
- WorkspaceProject(id, schemaVersion, title, colorProfile, paletteCollection, metadata)
- RasterDocument(width,height,colorMode, layerTree, guides, selectionState, references)
- AnimationDocument(rasterDocument, frameSequence, cels, linkedCelRefs, tags, playbackConfig)
- TilemapDocument(tileSize, atlasRefs, tileLayers, chunkStore, collisionOrMetadata)
- ModelDocument(units, hierarchy, cuboids, meshes, materials, uvIslands, bones, clips)
- SceneAssetLibrary(palettes, brushes, imageRefs, exportedSprites, thumbnails)

图层资源必须有稳定 UUID，不得用数组索引做持久身份；动画 Cel 的键为 layerId + frameId；对象引用遵循不可变版本或明确引用计数。写操作采用 Command + Transaction，历史条目保存范围、before/after 或可逆参数；对文档结构修改也必须撤销。支持命令合并（连续同工具笔画）、内存上限、checkpoint 和重放校验，不能无条件保留大量整张位图快照。

工程文件升级为 schema v2 并保留 v1 导入。采用 manifest + 校验和 + 分块的像素 blob + 可选预览图；新字段保持向前可忽略，老版本转换前备份。写盘采用临时文件、完整性检查、原子替换和失败回滚。导入不可信压缩包限制条目数、尺寸、压缩比和总解压字节，防止 zip bomb。

### 数据不变量

- 逻辑点坐标永远是整数，屏幕变换在独立 ViewportTransform 内处理。
- 所有颜色处理定义 alpha 合成顺序、预乘/非预乘语义和色彩空间。
- 画笔相同参数 + 输入轨迹 + random seed + 初始文档 => 字节一致输出。
- 选区 mask 和浮动选区不改变未确认文档。
- 导出工程到 PNG 时尺寸、透明度、颜色模式需有明确规则；回读逐像素一致才可宣称无损。
- 绘制禁止对锁定、隐藏或不可编辑资源暗中写入。

# 03. 选区系统：所有编辑能力的基础

必须先建立 SelectionMask，而不是单独实现一个“框选按钮”。mask 每个逻辑像素一位（硬像素模式）或 0..255 权重（高级软边模式），关联整个文档或明确的当前 Cel。默认像素画用硬边 mask。支持矩形、椭圆、套索、多边形、魔棒、相似颜色选区、磁性套索、透明度选取、内容边界选取、反选和全选。

选区布尔组合：替换/并集/差集/交集/异或；支持区域移动、边界缩进扩张、像素羽化（显式高级模式）、保存/加载选区、跨帧应用、按图层或合成结果采样。所有命令需要可撤销/取消。触摸操作显示“蚂蚁线”、8 个控制柄、数字边界尺寸；放大镜中不得将蚂蚁线绘进作品。

矩形框选：手指起终点映射到整数坐标，确定边界闭合/半开约定，建议 [left,right)×[top,bottom)；支持选区越界预览和裁剪。固定比例、固定尺寸、中心扩张、正方形约束。

椭圆选区：按像素中心判定归属；对中心落在边界上的决议一致；环形、洞、边缘和反向尺寸都要通过测试。

套索：采样轨迹后封闭多边形，使用偶奇填充规则；拖动中可编辑最后一个节点，支持单指光标模式，防止高倍缩放时抖动。

魔棒/相似色：配置 4/8 邻域、连通或全图、透明度是否参与、RGB/HSV/CIELAB 容差（均标注度量与阈值），可基于当前图层或合成颜色。处理透明像素时不可把不同 RGB 隐藏值错误比较。

智能边缘：第一阶段用 Sobel/Scharr 梯度 + 受约束最短路径 Live Wire（Dijkstra/A*），用户放置节点，路径会吸附强边缘；使用分辨率可控的局部搜索窗口，边界可手动增删节点，精度和速度可调。第二阶段可提供 GrabCut 一类用户引导前景/背景划分，离线运行、提供修正画笔。**仅**将其称为“辅助选择”，不能宣称自动准确识别任何人物轮廓。

选区的空内容、锁定层、跨层选择、负坐标、超大画布、透明边界、复制剪切时空 mask 均需显式处理。

# 04. 复制、剪切、粘贴：内部剪贴板与系统剪贴板双通道

内部 PixelClipboard 保存区域 bbox、ARGB 像素、alpha、选区 mask、源尺寸、调色板映射信息、来源图层/帧，可多次粘贴，不依赖系统权限。操作项：复制当前图层内容、复制可见合成、跨图层复制、剪切、粘贴为浮动图层、原位粘贴、居中粘贴、粘贴到新图层、跨帧粘贴、复制成新作品。

系统剪贴板通过 Android ClipData/content URI 安全发布 PNG，避免把巨型图片放入 ClipData 字符串；采用 FileProvider + grant URI 权限，目标是支持与其他图片应用交换，复制失败需回退内部剪贴板。纯文字调色板支持 HEX 文本复制。禁止申请全盘读写或联网权限。

粘贴采用 FloatingSelection：
- 单击“粘贴”后出现半透明浮动内容，支持拖动、旋转、缩放、镜像。
- 未确认之前可以取消恢复原始文档。
- 确认时作为单一 Command 应用，尊重图层 alpha 锁定和选区 mask。
- 被剪切区域需在事务提交时清除，不可以先破坏原图再等待用户确认。
- 复制粘贴及跨工程移动绝不能改变源工程。

手机底部浮动快捷条依次为“复制 / 剪切 / 粘贴 / 原位 / 反选 / 取消”，根据选区动态出现，默认不占画布空间。

# 05. 缩放、移动、旋转、镜像、错切、透视及变形

TransformSession 数据包含原始源数据快照、源/目标 mask、原点 pivot、参数矩阵、采样策略、输出 bbox、越界处理方式、提交/取消状态。

要求：
- 平移整数格；镜像水平/竖直；90/180/270 度整数变换为完全无损置换。
- 非整数缩放：最近邻采样、可选多数色和面积保留方案，并明确不再是无损。
- 任意旋转：逆映射 + 最近邻为默认，避免正向映射空洞；可选针对像素艺术优化的旋转策略需独立标记并测试，不保证视觉完全等价。
- 四角自由变形、透视、错切、网格/路径变形作为高级工具；默认硬像素不进行隐性平滑。
- 数字输入 X/Y、宽高、角度、纵横比锁定、变换中心点、网格吸附、像素中心对齐。
- 移动工具区分“移动视图”和“移动像素内容”，不可同手势二义。
- 旋转对象与旋转画布是两个命令。
- 保证 4 次 90° 旋转回原图、双镜像回原图、整数平移往返在允许范围内回原图。
- 前景/背景/图层混合、软边 mask 采样和色彩量化应有单独预览与告警。

缩放把手拖动使用手指偏移控件，支持水平/垂直一格步进，避免移动端精修时误触。

# 06. 图形工具：直线、椭圆、圆、弧、正多边形

新增一个 GeometryRasterizer 模块，输入几何描述，输出唯一有序像素集合；渲染预览与提交使用同一算法。所有工具提供描边/填充、线宽（整数逻辑像素）、虚线/断点模式、像素完美选项、起点/终点坐标、对称和吸附。

椭圆：整数中点椭圆算法或带一致边界判定的确定性栅格算法；中心、外接矩形、奇偶宽高、一格宽/高、半径 0 等退化情形有测试。必须检查 4 象限对称性和连续轮廓。填充椭圆使用行跨度，不得依靠抗锯齿矢量 API 再缩小到像素。

圆、椭圆、弧：支持拖动手柄改变半径、起止角、角度锁定；扇形/环形为独立参数。

正多边形：边数至少 3，中心/外接圆/内接圆模式、旋转角度、整数像素栅格化与自交规则。

线条：Bresenham 风格的 8 八分区连续整数栅格化；“干净转角”笔刷的像素完美规则需显式定义，避免自动删去用户刻意绘制的拐点。画线可按 Shift/设置锁定水平/垂直/45°。

# 07. Bézier 曲线、样条、轨迹预测、辅助线与标尺

实现二次/三次 Bézier、Catmull–Rom 或 Cardinal 样条、折线节点曲线；支持节点、切线手柄、断开/平滑连接、闭合路径、描边与填充、线宽、曲线动态预览。曲线计算为连续实数几何，**提交时才统一使用确定性的离散像素扫描算法**。

使用自适应细分：曲线平坦度/屏幕放大倍率/逻辑像素步长作为细分条件，输出参数点序列后去重，使用栅格线连接，防止断点。控制浮点精度，禁止因缩放造成导出图形差异；极高缩放只影响显示精度，不能影响最终提交像素。

预测轨迹：输入历史样本的时间、位置、速度、压感；使用低延迟 One Euro Filter 或可选 Kalman 风格滤波。预测只出现在临时预览层，真正提交使用确认后的实际采样轨迹；预测错误不能留下永久像素。对于长曲线，支持“起点—终点—弯度”3 步画法，与 2 控制柄精修法并存。

辅助绘图系统：直尺、平行尺、角度尺、透视消失点、网格、三等分线、可移动十字轴、圆规、椭圆轨道和样条轨道。辅助线是独立非导出向量对象，可开关吸附、定义强度、保存项目；绘图工具投影到辅助曲线后再栅格化。参考 Krita Assistant，而非把临时参考线画进图层。

尺寸标注与像素测距：显示起点/终点整数坐标、水平/垂直距离、欧氏距离（以像素为单位）、倾角；支持按像素等距重复。

# 08. 函数图形与程序化几何

提供“公式与参数图形”实验工作区，输入 y=f(x)、参数方程 x=f(t), y=g(t)、极坐标 r=f(θ)，可设置变量、单位、域范围、采样分辨率、坐标系和整数栅格化方式。

严禁 eval 不可信表达式或执行任意脚本。采用受限语法解析器：+ - * / ^ sin cos tan abs min max clamp floor ceil sqrt 等白名单函数；AST 限制最大节点数、递归深度、采样次数、计算时间和除零/NaN 处理。复杂公式在后台取消令牌中运算。

支持：
- 正弦波、振幅频率、相位、锯齿/方波与折线式波纹。
- 螺旋、圆弧、多边形函数轮廓。
- 可重复图案、像素地砖边界、等距结构。
- 参数值滑杆 + 实时预览 + 单次确认命令。
- 对参数变化进行可预期的采样，不能因为 DPI 不同改变生成结果。

# 09. 对称画笔与镜像系统

支持 X 轴、Y 轴、双轴、任意轴、2~32 阶径向对称、平移重复、棋盘镜像、万花筒；每个对称副本有用户可编辑轴心和角度。默认坐标轴中心的半像素问题必须精确定义，不能使奇数宽作品和偶数宽作品镜像偏一格。

对称作用范围可选当前图层/当前选区/全部帧，同一像素被多个对称副本命中时仅处理一次或定义合成顺序。画笔笔触、随机颜色和 alpha 必须根据同一 seed 派生，避免两边纹理无意义不一致。允许随机对称“完全镜像”与“形状对称但细节独立”两个模式。

对称轴显示、锁定与拖拽不应占据长久工具栏。

# 10. 画笔引擎：颜色、形状、质感与可再现随机性

构建 BrushDescriptor：形状 stamp/mask、整数尺寸、间距、旋转、朝向、密度、压力映射、透明度、颜色来源、随机种子、抖动算法、混合模式、笔触平滑和分布规则。任何 Brush 在项目中可保存为预设，并显示缩略图/示例笔画。

笔刷类型：
- 单像素、正方、圆形硬边、线条图案、棋盘、点画、叶片、石块、木纹、沙地、云纹、草地、墙砖、布纹、水纹、磨损边缘、颗粒纹理。
- 自定义像素 stamp、多个 stamp 轮换、连续拉线 stamp、沿路径旋转。
- 轮廓/内描边/外描边、颜色只替换、Alpha 锁定、像素通道混合。
- 仅选区内绘制、仅透明区域绘制、仅非透明区域绘制、仅同色区域绘制。
- 触控笔压力/倾角只在设备有数据时生效，手指有稳定替代曲线。

随机颜色画笔支持：限定调色板中任意选取、用户给定的加权分布、按明度阶梯选取、根据邻域局部基色决定概率、按高度/方向/位置改变颜色。必须显示实际生效配色和概率，不允许自动生成不受控的无穷 RGB 噪点。

随机位置/密度：使用固定种子 PRNG（如 PCG32 或 Xoshiro；实现版本固定），坐标哈希用于可局部重算的程序化纹理；实时笔刷需要 strokeSeed + dabIndex 保证重做/导出一致。避免直接把 Math.random() 当数据来源。

质感刷优先维护大片可读色块，控制孤立像素、过密颜色种类、频繁高频跳色和轮廓破碎；提供“轮廓保护”“颜色数量上限”“孤立点检查”“稀疏度”“笔触分布预览”。

# 11. 智能抖动、渐变、光滑与模糊

### 抖动
提供规则棋盘、2×2/4×4/8×8 Bayer 矩阵、有序蓝噪声（若采用必须保存/验证固定蓝噪声表）、误差扩散 Floyd–Steinberg / Jarvis–Judice–Ninke / Atkinson 等可选实现。逐像素颜色量化由用户指定 palette 和色差度量控制；误差扩散扫描顺序和边界行为必须确定，支持选区和透明 alpha 的正确处理。

“智能抖动”指局部结构/颜色变化驱动的抖动密度、噪点抑制和边缘保护；提供差异预览，不得以黑盒声称完美。

### 渐变
支持线性/径向/角度/路径渐变；连续 RGB 插值、感知空间插值和调色板阶梯为三种不同模式。对像素艺术默认推荐色阶与图案抖动；颜色强制不超过 palette 限制时必须用索引映射，RGBA alpha 渐变独立处理。

### 平滑
分成三种互不混淆的工具：
1. 手势轨迹滤波：仅修改路径。
2. 曲线拟合：点列转成受控 Bézier/样条，再离散 rasterize。
3. 像素图像平滑/模糊：明确的非传统像素画滤镜，属于破坏式色彩重算操作，默认关闭。

### 模糊
支持盒式、Gaussian、有边缘保护的局部滤波和选择性颜色混合；提供卷积核大小（逻辑像素）、边界模式（透明/夹取/镜像/周期）、预乘 alpha 处理、防透明暗边策略、限制调色板的后量化选项。预览与提交必须一致。模糊完成后结果仍然是严格的离散像素阵列，不得在显示层依靠双线性采样假装保存了模糊。

# 12. 无缝材质：四方向真正周期连接

提供水平周期、垂直周期、XY 双向周期和 3×3 / 5×5 预览。独立的 TiledDrawing 变换只改变采样索引：
- x' = ((x mod W) + W) mod W
- y' = ((y mod H) + H) mod H
- X 模式仅对 x 取模，Y 模式仅对 y 取模，XY 对双轴取模。
- 跨左右边缘的画笔必须在对应右边同步更新同一逻辑画布内的映射像素；上下同理；四角同时穿越时只执行一次合成或明确叠加规则。
- 参考画面展示是多个视图副本，不应把重复区域写入工程尺寸。
- 支持偏移检查（offset by W/2,H/2）和可逆位移，便于修接缝。
- 大尺寸画笔、镜像轴、随机画笔、选区、透明层均执行周期边界测试。
- 像素插值与过滤器（如卷积、抖动）在平铺模式下可选周期边界，避免滤镜生成新的接缝。
- 画出边缘草叶或砖缝后 3×3 拼接应连续；自动化检查比对边界邻域的平铺渲染一致性，而非误以为左右首末像素必须相同。

注意 Tilemap 与 Tiled Drawing 不是同一系统。Tilemap 是图块引用/铺放和层级，Tiled Drawing 是单张纹理的周期边界绘制。

# 13. 图层、蒙版与非破坏效果

图层支持分组、链接、alpha 锁定、透明度、可见性、混合、图层蒙版、剪贴蒙版、参考图层、调整层与效果缓存。图层变换/效果默认作为可撤销的非破坏节点（可用户决定合并栅格化）。每个效果节点含稳定参数和类型版本。

分组编辑/批量操作/多选图层必须有预览与撤销。图层树可上划展开，平板可固定侧边停靠。图层缩略图缓存不影响主绘制帧率。

# 14. 2D 动画：Frame、Cel、洋葱皮和时序控制

基础模型：Frame(id,durationMs,tags)、Layer(id)、Cel(layerId,frameId,contentRef,offset,alpha)、AnimationClip(start,end,loopMode)。允许链接 Cel 共享只读像素；编辑时按照“解除链接并复制”或“同步编辑关联帧”明确选项，不可偷偷改全部帧。

动画时间轴：
- 逐帧新建、复制、删除、拖拽重排、复制/粘贴 Cel、多选帧和图层范围。
- 每帧时长（毫秒）与项目默认 FPS 两套参数；对单个 Frame 设置 80ms、120ms 等不被 FPS 强制覆盖。
- 动作标签 Idle/Walk/Attack、片段循环、往返、倒放、Ping-Pong。
- 实时播放与暂停、指定帧预览、帧率计数、短片段 A/B 循环。
- Onion Skin 前后 N 帧，独立色调（前红/后蓝可配置）、不透明度衰减、绘制在现帧前/后、仅当前层/全部可见层。洋葱皮绝不污染存储与导出。
- 复制贴图以及逐帧导出透明 PNG、GIF/APNG（编码器通过真实测试再开放）、Sprite Sheet 和 JSON 元数据。

### 2D 速度曲线
逐帧动画本质是离散图，速度编辑至少提供两条路径：
A. 帧时长曲线：在时间轴上对每帧 durationMs 批量设置变化，保留每帧实际像素内容。表示节奏，不生成不存在的中间图像。
B. 时间重映射曲线：对播放时钟 u 到采样时钟 t 做单调函数映射；保证播放时长与取帧规则可追溯。不会凭空创造运动补间；如果使用可选自动补间，必须明示这是新生成的中间帧和算法。

默认提供线性/缓入/缓出/缓入缓出时序模板，显示每帧时间戳和最终总时长。处理零时长、逆序和小于最小播放粒度的帧。

# 15. 3D 方块建模与 2D/3D 共用材质工作流

参考 Blockbench 的工作流设计，不克隆其 UI 或直接复制 GPL 源码。3D 模式是第二工作区，和 2D 作品共用 Palette、TextureAsset、Undo、AssetLibrary、ExportService。

核心 3D 数据：
- Node(id,parentId,translation,rotationQuaternion,scale,visibility)
- Cuboid(min,max,perFaceUV,perFaceMaterial,rotationOrigin)
- Mesh(vertices,faces,uvs,normals,materials) 作为后续扩展
- Bone(id,parentId,pivot,bindTransform)
- Material(textureId,alphaMode,nearestFiltering,cullMode)
- Keyframe(timeMs,channel,value,interpolation,tangents)
- AnimationClip(tracks,duration,loopMode)

必备工具：新建立方体、位置缩放旋转、重命名、复制镜像、父子组、骨骼关联、坐标轴和网格吸附、可见/锁定、正交/透视相机、绕物体旋转、平移缩放观察、正/侧/上三视图、包围盒和轴向把手。几何变形与相机移动必须操作隔离；不支持的模型特性不显示虚假按钮。

UV 编辑：每个立方体六个面对应明确的 UV rectangle 或 polygon；支持自动展开、手动编辑岛、旋转、镜像、UV 越界预警、atlas pack、纹素密度提示。贴图沿用 2D Integer Pixel Engine 的图层和色彩工具：模型表面点击必须通过 ray cast 命中面、插值 UV、映射逻辑 texel，画笔可跨 UV seam 时由用户选择“仅当前 UV 岛”还是“跨同一表面连续涂绘”；禁止显示上涂抹但 PNG 内没改。

渲染：现代 Android 原生 GLES 3.x / 可适配 Vulkan 作为可选后端；先用 GLES 3.x 的前向渲染，纹理必须设最近邻、正确 alpha、深度测试、双面/单面开关。支持骨骼线框、地面网格、光照开关、贴图原色预览、纹素检查。可在没有高性能 GPU 的设备自动降级但不改变保存的模型。

### 3D 关键帧与曲线编辑器
- 关键帧轨道：位置 x/y/z、欧拉 UI / 内部四元数旋转、缩放 x/y/z、可见性和自定义通道。
- 插值：Step（逐帧跳变）、Linear、Cubic Bézier / Hermite；旋转用符合约束的 quaternion Slerp 或选定欧拉曲线，不能分量独立 lerp 四元数导致归一化错误。
- Graph Editor：时间横轴、数值纵轴；关键帧点、左右切线手柄、Auto/Aligned/Free Tangent、缓动预设；曲线下面真正影响结果的时间映射/插值而非仅装饰。
- 骨骼 FK 先实现；IK 后续单独研发。多个关联骨骼需正确矩阵乘法、父子变换和 bind pose；避免穿模的动画范围可设置告警但不保证自动完美。
- 插值采样结果可导出模型或动作数据，不得把 3D 曲线说成 GIF 像素帧数据。

导出必须按已实现格式逐项验证：原生工程为必选，OBJ+MTL+PNG 为先行静态模型，glTF 2.0（含骨骼/动画）和 Minecraft 模型格式只能在兼容性和许可证验证后正式支持。扩展名、坐标轴（右手/左手）、单位、UV 原点、贴图采样和轴向约定必须文档化。

# 16. 更好的手机 UI：不只是把功能塞入菜单

手机窄屏默认：
- 顶部：返回、工程名、撤销、重做、更多。
- 中央：最大化画布、吸附十字光标、手势反馈、局部放大镜。
- 底部主工具 Dock：绘画 / 选择 / 形状 / 材质 / 动画（3D 作品显示建模 / 贴图 / 动画）。
- 工具子选项：底部轻量抽屉，半屏可展开参数，长按工具弹出最近预设。
- 左侧或右侧：可配置“落笔”“吸管”“临时平移”浮动按钮；可拖拽位置。
- 触控模式：直接、偏移光标、光标与落笔分离；所有工具完整兼容。
- 两指默认缩放平移、三指撤销/重做可选，控制柄操作期间与视口手势进行明确优先级仲裁。
- 长按工具显示中文帮助和动画示意；一键“专注模式”隐藏面板。
- 模式切换时保存各工作区 Dock 布局与参数，但不悄悄改变画笔颜色和当前图层。

手机横屏：Dock 可以变为一侧薄条，图层/时间轴在底部，3D 模式出轴向控件；平板多面板可固定且支持拖放。控件触摸目标至少 48dp，放大布局跟随系统字体大小；精确像素视口不得被系统字体比例影响坐标换算。

复制/粘贴、选择与变形采用“选区出现 → 浮动快捷条 → 拖动或手柄 → 确认/取消”的移动优先流，不用 7 层弹窗。

# 17. 架构重构与并行模块契约

各模块及依赖方向：
- core-pixel：RGBA/indexed 像素存储、量化、alpha。
- core-selection：Mask、BooleanOps、MagicWand、LiveWire、Clipboard。
- core-geometry：line/ellipse/polygon/Bezier/transform/ruler/functions。
- core-brush：Stamp、Dynamics、Random、Dither、Gradient、Convolution。
- core-tile：WrappedCanvas、TileSet、Tilemap、TileCache。
- core-animation：Frame/Cel/Timeline/OnionSkin/Remap。
- core-model3d：SceneGraph/Cuboid/UV/Rig/Keyframes。
- core-render2d 与 core-render3d：渲染缓存与预览，不能携带业务状态。
- core-command：命令、原子事务、undo/redo、版本追踪。
- core-project：序列化、升级、autosave、安全恢复。
- feature-editor/selection/brush/animation/model3d：仅 UI 与交互协调。
- benchmark 与 tests：金样图、属性测试、触摸回放、帧性能。

各算法接受与平台无关的输入，不依赖 Compose/Activity；主线程禁止执行大范围模糊、颜色量化、模型网格细分和压缩；后台任务接受取消 token，结果仅在文档版本未变化且用户确认后提交。

### 核心状态机
Idle → GestureCandidate → PreviewStroke / PreviewSelection / PreviewTransform → Commit / Cancel。若第二手指加入手势，严格按模式取消当前未提交笔画或切换到安全导航，不能产生残余涂色。撤销与保存并发必须通过文档版本号和一致性快照协调。

# 18. 质量门禁：逐项功能验收

下面标准必须转化为自动测试和必要的 Android 模拟器/真机测试。

1. 复制框选：在 32×32 图上选择 4×7 区域，复制到新位置，原件不变；粘贴确认后撤销一次恢复。
2. 透明剪切：有透明洞的图层选区剪切粘贴，alpha 完全一致，无黑边。
3. 智能选区：固定测试轮廓图，颜色魔棒与 Live Wire 输出已知 mask；弱边界可手工纠正。
4. 镜像回环：水平镜像两次、垂直镜像两次、90° 四次，数组位级一致。
5. 旋转变形：任意角度不崩溃；确认、取消和撤销恢复可验证；采样规则固定。
6. 椭圆：3×3、4×4、1×9、19×11 的四象限对称及边界严格测试。
7. Bézier：控制点相同但屏幕放大倍率不同，最后渲染的逻辑像素完全一致。
8. 轨迹：手指 120Hz 高频输入与 60Hz 渲染下，快速斜线无缺点，预测性预览不残留到导出图。
9. 对称：奇偶画布、轴心偏移、画布外笔触、交叉轴重复写入均得到确定结果。
10. 随机笔刷：固定种子重复导出得到同一哈希；不同种子有可见差异；限色不越 palette。
11. 渐变：4/8/16 色调色板模式，最终色数不超过上限；同一阈值图案重复一致。
12. Gaussian：透明边缘无暗边，确认/取消/撤销一致，网格仍是真实 ARGB。
13. 无缝：X、Y、XY 三种模式，画笔从画布一个边缘移动到另一边缘，3×3 预览严格连续且文件只保存单纹理。
14. 洋葱皮：N 前后帧的色调和 opacity 正确，关闭后预览无残影，PNG 里没有幽灵帧。
15. 2D 节奏：同 12 帧不同 durationMs 导出时长准确，在循环/倒放和帧标签边界正确。
16. 3D UV：模型上点击特定面/纹素与 2D UV 图中编辑同一 texel，导出 PNG 后颜色一致。
17. 3D 层级：父骨旋转时子骨局部变换及世界变换正确，姿态往返无累计漂移。
18. 曲线：3D Step/Linear/Cubic 在固定关键帧、时间点的结果可用 golden sample 检验。
19. 文件：V1 项目导入 V2 并回读无损，异常断电不破坏最后有效项目。
20. 性能：中端真实 Android 设备记录 p50/p95 笔触延迟、GC 暂停、峰值内存、帧率、温升和测试项目规模，未实测不得写“完美性能”。
21. 无网络：飞行模式和缺少 INTERNET 权限仍能执行全部绘画、3D 编辑、存储、导出。
22. 易用性：新用户不用读长说明，完成“框选→复制→粘贴→变形→保存”；左手模式、320dp 窄屏和字体放大通过 UI 测试。
23. 回归：现有 P0 铅笔、填充、层合成、撤销、PNG、项目保存必须继续通过，不允许 V1.1 破坏原功能。

CI 必须区分代码静态检查、JVM 逻辑测试、Android 编译、模拟器 UI 测试、真机实际体验和渲染性能基准。只有明确证据才能把状态由未实现改成通过。

# 19. 实施次序与优先级（禁止乱序堆功能）

阶段 A / P1-A（最高）：SelectionMask + Copy/Cut/Paste + FloatingSelection + undo/redo 通用命令 + 本地工程 schema v2。先解决“画完不能编辑”的根本问题。
阶段 B / P1-B：镜像、旋转、缩放、矩形/椭圆、二次/三次曲线、辅助线/标尺、对称、拉线、手机手柄。几何输入在统一 Rasterizer 输出。
阶段 C / P1-C：真正 BrushEngine，颜色预设、随机种子、随机调色板、智能抖动、平铺 X/Y/XY、像素质感、渐变、模糊和效果预览。
阶段 D / P1-D：Frame+Cel+OnionSkin+逐帧时间轴+每帧 durationMs+动画导出，之后再做可视化时间重映射曲线。
阶段 E / P2-A：原生 3D 方块、对象树、正交/透视、UV 编辑、2D/3D 联动纹素绘制、静态模型输出。
阶段 F / P2-B：骨骼、关键帧轨道、插值曲线编辑、动画导出、复杂 3D 约束、跨作品素材库。
阶段 G / P2-C：离线高级选区、局部结构质量诊断、可选本地 ML、Tilemap 和复杂批量导出。

每阶段完成后制作真实 APK，保留 SHA-256、Git 提交、截图、真实用户操作视频及未通过的测试项；绝不通过截图伪造功能成果。

# 20. 开发交付指令

先检查已有 Android 工程、锁定当前 Git SHA、确认可复现构建；必要时从现有分支创建独立功能分支。每个功能遵守“接口/算法/单测/触控 UI/预览/撤销/文件往返/模拟器”的顺序。对开源参考项目只做规范和算法思想研究，不能无许可复制代码、图标、界面或素材。

按功能 ID 在 docs/FEATURE_MATRIX_V1_1.md 登记状态（PLANNED、ENGINE_ONLY、UI_WIRED、TESTED、RELEASED），PR 中提供证据文件路径、测试日志与回归记录。所有可重复随机纹理必须保存 seed；所有 3D UV 映射必须可验证；所有智能建议必须可以关闭。

发布门禁：核心绘画与保存不能回退；无 INTERNET 权限不能改变；任何新增按钮必须在已实现且通过 P1 功能测试后才显示为可操作。

# 21. 终极研发原则

Pixel Atelier 的目标不是用功能按钮的数量冒充“专业软件”，而是让真实像素画家在手机上以最少操作获得精准、可控、可恢复的制作流程。新手能快速上手，专家可以精确掌控每一个像素、选择、路径、颜色、帧、纹素和模型面。高级智能算法是助手，不是作者。所有“智能”都需可解释、可预览、可关闭和可复现。3D 加入的理由是像素贴图、游戏模型与动画资产的统一工作流，而不是忽略 2D 工具基础。
