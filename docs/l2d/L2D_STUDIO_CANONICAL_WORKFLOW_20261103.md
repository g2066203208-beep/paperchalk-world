# Paperchalk World｜L2D 工作室标准全流程（正式制作规范）

**更新时间：2026-11-03 · 适用所有人物 · 自研 PartRig v1，不是 Live2D Cubism .moc3。**

本规范是唯一的制作、检查、保存和发布工作流程。取消“旧 V4 / 新版”工作模式切换，不建多套呼吸、风级、待机预设。V4 文件仅作已有角色的安全后备，不作为新角色独立绑定的最终交付物。

## 0. 人物身份与源素材

- 使用 `site/data/characters/registry.json`、`docs/characters/CHAR-XXX.profile.json` 和统一 `site/characters.catalog.json` 的**唯一角色 ID**。不要为了绑定新建第二个相同人物；内部模块别名只可供系统引用。
- 拍板的立绘原图、颜色、尺寸、脸和服装不得擅自重绘或重采样。游戏原位舞台 `1024×1024`，每层保留原始 `x, y, width, height` 和 Alpha。
- 所有图层必须有真实来源证明：`original-psd`（人工画出的独立部件、带遮挡区域补绘）、`derived-region`（从一张合成图按像素分区，不存在被遮挡的真实信息）、`concept-only`。**不能把 derived-region 冒充原始 PSD，不能凭空分出眉毛、眼皮、刘海或背面。**
- 未提供的背面不合成、不镜像、不显示“可制作完成”。需要背面真正的绘制资源。

## 1. 分层美术（不可省略）

1. 从原 PSD 或 ArtMesh RGBA 源图分离：后发、前发/刘海、发侧束、发饰、脸、耳、眼白、虹膜、睫毛/眼睑、眉、鼻、嘴、颈、上衣、袖/左右手、裙/裤、左右腿、鞋；先以角色真实造型定部件，非机械强行凑数。
2. 每一块必须独立 RGBA PNG，并保留**被上层遮住却会因运动露出的补画像素**。纯裁切区域只允许极小角度预览，严格标注。
3. 原始中性姿势合成必须与批准的静态图**像素一致**或解释受控的修补区域。检查透明洞、双描边、重叠衣领、裁切线、左右对称错位。
4. 用 `layers.json` / `assets.json` 记录每层 `id, file, x, y, w, h, opacity, visible, role, provenance`。保留叠放顺序，不得合成单一整图代替独立 PNG。
5. 对每层生成安全原位 UV 网格和明确的根部/末端骨骼；前发必须有发根约束，裙摆必须有腰部约束，手臂要有肩—肘—腕链；不拿独立呼吸变形替代人物本身骨骼。

## 2. 人体父级结构（核心验收）

```text
地面 Ground
├── 左右脚鞋（固定）
└── 两条脚踝→膝盖→髋关节的站立 IK
    └── 骨盆 / 腰（角色重心，不随胸呼吸直接漂移）
        ├── 左右大腿与裙腰
        └── 腹部→胸廓（局部扩张，不整个人缩放）
            └── 左右肩 / 锁骨
                ├── 左肩→左上臂→左肘→左腕→手
                ├── 右肩→右上臂→右肘→右腕→手
                └── 颈根→颈顶→头
                    ├── 脸、耳、眉、鼻、嘴、眼睑、眼白、瞳孔
                    └── 刘海根、后发根及发夹
```

- **父级先动，子级继承。** 子级独立摇摆不得让父级被反向牵走，头部可以有很小的颈部反向补偿，脸和五官始终共享头部变换。
- 胯部调节必须通过两条腿的膝关节求解到固定脚踝；鞋绝不移动。不要用“整个角色左右平移”冒充人体重心调整。
- 胸部呼吸是上胸局部扩张和微抬，带动锁骨/肩/手臂/颈/头保持相连；腹腰、膝、鞋及地面不参与呼吸缩放。
- 保留眨眼。独立眼白/睫毛存在时才可生成真实闭眼；若脸眼混为一张贴图，必须显示“无法独立眨眼”的制作限制，不能假称完整。
- **纹理原位约束**：零摆幅时所有部件回中性姿势，原本相接的颈肩、肩袖、腰裙和鞋腿不裂缝、无三角网格白缝、无异常扭曲。

## 3. 工作室控制（一个模式，一次保存）

默认画布播放新版 ArtMesh，无旧版切换按钮；右侧仅显示当前角色**确实具备的**几个滑块：

- 刘海、后发、裙摆独立幅度（0–2000%，但超限需观察穿模）；
- 手/手臂、肩、胯（0–800%），只有真实对应部件和骨骼时显示；
- 胸部呼吸（0–300%，0 完全关闭），摆动速度（25–250%）；
- 拖动即看实时人物，曲线连续、无弹跳换挡。
- 顶部「骨骼细调」只展开轴点、网格、独立关节及蒙皮调节，并且收起后**动画仍然播放**。
- 用 `PaperchalkPartRigCore` 同一个渲染器计算编辑器和游戏；不准写两份假动画、两份不同配方。

`保存到游戏`：先保存全部编辑的原始 ArtMesh PNG，再写入同一人物/方向的 `part-rig:ID:front|back` JSON 草稿。刷新工作室、进入同一浏览器同源游戏后读取完全一致的素材+骨骼。**这一步只是本机 IndexedDB 同步，不等于发布到 GitHub，也不跨设备同步**。导出完整备份后方可改动关键资产。

## 4. 正式发布与模块库自动接入

每名人物一个模块目录：
`site/assets/l2d/library/<internal-module-id>/{module.json,front.rig.json,front.png,parts/...}`。

- `module.json` 只引用确实存在的 `front` / `back`。rig `format=paperchalk-part-rig-v1`、`characterId`、`face`、`canvas=[1024,1024]`，每个 `textures[partId]` 对应尺寸相等的 PNG。
- 用 `scripts/build_l2d_library.py` 强验证有效 PNG、参数 JSON、路径、数量及 ID/方向。再经 `scripts/build_character_catalog.py` 合并到原角色，不建重复演员。
- 用户在工作室编辑好导出模块 ZIP，可将 ZIP 提交 `site/assets/l2d/inbox/`；CI 自动安装、验证、生成 `site/l2d-library.generated.json`，但本机修改不会未经提交自动写入 GitHub。
- 与现有演员 ID 相同的正式人物不得未经审核直接覆盖角色档案或旧 V4；通过严格授权的内部 alias 绑定原女主 `protagonist`、女二 `char-002`。原 V4 文件保留为故障回退资源。

## 5. 自动化验收门槛

**源码级**：每层 ID/纹理尺寸/Alpha/叠放/像素归属明确；骨架 parent/child 关系、手机/电脑布局、slider=0 状态、边界处理、危险路径/假图片/错人物一律拒绝。

**物理层**：脚/鞋在所有 `time` 精确不动，骨盆驱动膝关节，肩膀与颈/头/手连续，胸呼吸不抬鞋/动盆，指尖和裙摆无夸张拉伸；0 振幅与原画严格一致。

**渲染层**：1024 画布和游戏缩放同时检查，强制逐帧比较眼白/眉/鼻/衣领、刘海与裙角；观察至少 2–3 个动作周期，禁止可见网格/黑缝/露底。未经观察测试不得宣称“专业完美”。

**持久化层**：在网页调滑块→调整一个原始 PNG 像素→点击保存→刷新→游戏播放→验证同名演员、相同数据、原始像素仍存在；再换人物切回来，禁止交叉覆盖。

**自动化**：`.github/workflows/l2d-modules.yml`、`game-character-dev-tests.yml`、`character-editor-tests.yml`，以当前提交成功为准；旧提交绿灯不代表新提交已验收。

## 6. 女二（char-002）实际交付账本

- **批准资源**：`site/assets/characters/char-002/front.png`（原画 303×1024），只有正面；`scripts/build_char002_v4.py` 生成 128 帧可回退动画与 7 个保真像素区域。
- **基础独立网格模块**：`scripts/build_char002_part_rig.py` 从同一 ZIP 构建 `char-002-rig-v1` 并以 alias 挂到原来的 `char-002`，不新增重复女二角色。7 个实际区域：`shoes`、`legs`、`skirt`、`wave_hand`、`free_hand`、`head_hair`、`jacket`。
- **可用动作**：脚不动的骨盆/腿联动、两手/肩部联动、上胸呼吸、裙摆的少量变形、整体头部继承。区域边界使用保守默认值，避免露出合成图原本不存在的遮挡信息。
- **不是完成的真实 PSD**：`head_hair` 把头和头发合在一块，刘海无法真正独立晃动、眼睛无法可靠独立闭合；两臂原始像素由区域裁切而不是完整遮挡补画；没有原生背面 16 层。这些不能宣称“女二已经达到女主 17 层的同级艺术质量”。
- **升级条件**：将女二真正 16+ 层正面 PNG/PSD 连同隐藏部位补画导入工作室，逐层校验并绑定独立眼睛、脸、刘海、后发、裙摆、左右手；保留 `char-002` ID 和用户保存，升级同一模块而不是创造另一位女二。

> 官方技术参考：Live2D Cubism 的 parent-child deformer、rotation/warp deformer、ArtMesh skinning 是人体父级设计的交叉校验依据；本项目自身格式和实际可用功能以代码/测试结果为准。
