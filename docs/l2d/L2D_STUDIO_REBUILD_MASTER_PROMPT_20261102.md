# Paperchalk World｜L2D 工作室彻底重构：主执行提示词（2026-11-02）

> 本文是交给 Codex／工程代理直接执行的任务书，不是产品宣传文案。用户要求的是能制作、编辑、播放、保存并在游戏中实际运行的专业 2D 分层角色绑定/动画工作室。发现根因，实施代码，跑真实浏览器，交付画面、测试、GitHub 记录。严禁把静态 PNG 整图晃动、V4 逐帧 WebP、假的骨骼示意线称为真正可编辑 L2D。

## 0. 执行身份、权限与最终目标

你是一支由高级前端图形工程师、2D 角色绑定师、技术美术（TA）、游戏运行时工程师、交互设计师、QA/SDET、性能工程师组成的实施团队。请在仓库 https://github.com/g2066203208-beep/paperchalk-world 的最新 main 上执行，不要凭旧快照覆盖新改动。本提示词写入时检查到 main 为 0a49e38417fc9490aeb74d0566f2d3ea33f6380b；开始工作时必须再拉取、核对最新 SHA、最近提交和正在运行的工作流。优先保全已有角色图像、原始 PSD 及游戏数据。可新建 feature 分支并提交 PR，经测试后再合并；每个阶段有可查看的 GitHub 提交、验收证据。

唯一目标：把 /site/character-editor/ 从“旧绘画网页＋V4 动画修补器＋附加的程序化形变预览”重构成专业、稳定、易上手、可扩展、全部人物通用的 **2D 分层网格/骨骼/变形器/物理/动画工作室**。必须达到从导入真正的 PSD、对齐图层、自动生成可编辑初稿、手调网格和绑定、设置参数、制作关键帧、准确播放/暂停/拖动时间轴、保存/导出、在游戏里以同一模型和动画播放的完整闭环。

产品 UI 以中文为默认，遵守动画软件的成熟工作流。重点是“进入后立刻知道接下来干什么、每次点击都有可见结果、播放随时可靠、保存不会丢内容”。不能用一堆浮动按钮和长段说明代替专业交互。

### 1.1 已从代码确认的高优先级缺陷：必须复现和修复

**P0-01 PSD 主画布被 V4 存在标志阻断。** stage-motion.js 的 frame() 中有“clip()?.isV4 就返回 null”的条件，tick() 也要求“!clip()?.isV4”；而 studio.js 的 isV4 只表示当前角色加载过 V4 资源，即使 hasNativePSD() 使 useV4() 返回 false，这个标志仍可能为 true。结果：中央画布进入静态 PSD 绘画路径、右侧小画布独自运动；用户认为“L2D 根本不能播放”。必须将“可用的文件类型”“当前主动渲染器”“当前播放状态”彻底区分，实测真人物 PSD 在中央画布播放。不能仅改 UI 文案。

**P0-02 三套播放状态和多个动画循环互相竞争。** studio.js 有 playing/frameLoop，l2d-mode.js 有 paused/rig.start()，stage-motion.js 有 state.playing/tick()，runtime.js 有自己的 sync()；存在至少三个播放按钮、多个 requestAnimationFrame、独立冻结时间、独立帧号。必须统一为唯一 AnimationClock/PlaybackController。只有一个时间源，支持 play/pause/seek/step/speed/loop，渲染全部订阅状态；任一控制器不能悄悄覆盖其他控制器的暂停/播放。

**P0-03 重渲染反复触发重建绑定。** l2d-mode.js 用 hook('render',()=>schedule())，schedule() 清除并重启 125ms 的定时器，每次调用 setLayers() 都新建合成画布、setImage()、扫描图像 alpha，然后再渲染。频繁 ed.render() 会造成计划饥饿、掉帧、响应迟钝、图层状态迟迟不刷新。必须改成事件驱动 dirty flags：只有资产导入/图层像素变更才重建纹理，只有网格拓扑改变才重建 GPU buffers；每帧仅求值参数、更新顶点和画面，不得逐帧重解 PSD/重扫 RGBA/重新建完整 1024×1024 数据图。

**P0-04 当前不具备真正可编辑 rig 项目。** rig.js 的硬编码 psdTarget(x,y,part,t) 根据中文/英文部件名分配既定正弦形变，所谓骨骼线只是按固定坐标描画；不能直接编辑关节、拓扑、权重、参数关键形、运动曲线。必须将 rig 数据模型化并实现可编辑，不准把“显示骨骼按钮”当作绑骨完成。

**P0-05 导入与存储体系重复而脆弱。** index.html 的 pixelatelier-character-v1、studio.js 与 game bridge 的 paperchalk-dev-characters-v1、localStorage 动作参数三套数据分散；浏览器清缓存后丢工程，无法稳健跨设备恢复。导入 PSD 的 index.html/importPsd 内部 catch 吞掉异常，调用者可能随后按不存在的 16 层继续处理；ZIP 为自行解析，明确拒绝 data descriptor，存在兼容限制；外部 ag-psd CDN 故障会导致导入失败。统一项目容器、事务和错误传播，取消“操作成功”虚假反馈。

**P0-06 编辑结果与游戏模型状态不一致。** 工作室可能在浏览器里保存 sourcePart 但游戏加载另一份 V4；未导入原始 PSD 的 char-002 仓库只提供从扁平原画切出的 7 个编辑区域。必须实现工作室/游戏同一可加载结构：同一份 rig、同一动作、同一物理参数、同一图层顺序、同一帧时间；旧 V4 只能明确标注为 Legacy Baked Clip，绝不能假装支持真实骨骼编辑。

**P0-07 测试没有覆盖真实终态。** 原有 CI 侧重脚本语法、截图、单张绘画、V4 128 帧，以及浏览器合成的 16 个测试矩形。合成矩形用来做单元/E2E 流程可以，但无法代替真实 16 层 PSD 的像素/形变/完整游戏表现验收。必须补真实素材可用时的 end-to-end；如果 GitHub 当前没有该二进制素材，必须公开标记“真实 PSD 测试待资源提供”，不可捏造测试通过。

## 3. 新工作室的产品交互定义（专业但不繁琐）

目标是“新手 3 分钟看到真实播放，熟手拥有完整控制”，不是复制 Cubism 或 Spine 的所有复杂界面。项目入口包含“最近工程 / 新建角色 / 打开工程 / 导入 PSD 或分层 ZIP / 查看演示”，每个入口实际可工作。初次导入有五步向导：“1 选文件 → 2 检查图层 → 3 对齐部件 → 4 自动绑定初稿 → 5 进入编辑/试播”，每步随时可返回，不丢原始像素。显示 import progress、图片预览、图层数、文件尺寸、遮罩/组结构、缺失/重复部件和已识别部件角色。导入错误应显示文件名、异常原因、重新尝试和安全退出；不准静默卡死。

桌面统一五区：
- 顶栏：人物选择、前/背面、工程名、已保存/未保存、撤销重做、保存、导出、应用到游戏、调试状态；“保存”和“应用到游戏”语义分开。
- 左侧：可搜索层级树（图层/网格/变形器/骨骼/参考图）、缩略图、显示/隐藏/锁定/独显、层级与顺序；拖放换层、右键菜单、多选/重命名、空层提示。
- 中央：尽可能大的实时 GPU 画布、等比缩放、全身/面部/当前层聚焦、透明棋盘格/舞台背景切换、辅助线/轴点/网格/骨骼开关、画布拖动/缩放、旋转操纵器；任意预览状态不得遮住原图或裁掉脚。
- 右侧属性检查器：按当前选择上下文显示“对象变换、网格、权重、参数、约束、材质、表情、物理”；只出现当前任务相关的控件，数值输入可精确编辑并支持拖动，恢复默认并可撤销。
- 底部：可折叠并调节高度的专业时间轴/关键帧 Dopesheet；左侧轨道列表、中央帧刻度/关键帧/曲线切换、右侧循环/速度/FPS/范围/录制/自动关键帧；底部状态条显示 FPS、当前播放时间、选中对象、渲染模式、未保存提示、错误诊断入口。

左侧使用工作模式切换：①“素材/图层”②“网格”③“绑定/变形器”④“参数/表情”⑤“动画/时间轴”⑥“物理/测试”⑦“绘画精修”（精修为模块，不再占据默认首页）。模式是同一个工程/同一个实时主视口，不是七个割裂网页；切换后保留角色、时间轴位置、画布缩放、选中部件。各模式只有 1—2 个明确主操作。

默认进入导入完成后的“动画预览”模式，能立即自动播放 Idle（如果没有 Idle，先自动生成一个标注为“可编辑初稿”的小幅呼吸/眨眼/发丝摆动动作）。唯一主播放按钮必须实际控制中央画布；空格播放/暂停，左右箭头单帧，Home/End 跳头尾，J/K/L 反播/停/正播（可按用户设置调整）；拖时间轴立即显示准确姿态；P 可以保留为快捷键但不要冲突；Esc 退出全屏/当前工具。键盘输入焦点在文本框中时不截获快捷键。所有按钮有 tooltip 与禁用原因说明。

自适应：1280—1920 宽屏默认完整工作区；窄屏将时间轴和图层收成抽屉，移动端以“预览、挑选和基本改参”为主，复杂网格操作允许在触摸设备提供辅助提示但不能导致页面横向溢出。支持笔触/鼠标/触控：单指操作当前工具、双指缩放/平移，支持 pointercancel、触摸丢失恢复、高 DPR、ResizeObserver、浏览器缩放。可选可停靠面板布局，保存界面设置，不把所有工具塞进第一屏。

## 4. 中立、版本化、可移植的数据模型

建立 packages/l2d-core、packages/l2d-renderer、packages/l2d-studio、packages/l2d-io（如仓库体量不适合多包，使用同等职责的清晰目录）；编辑器和游戏运行时共同导入 l2d-core 的评估器，不允许工作室一套 psdTarget、游戏另一套硬编码。

创建明确的 project schema，字段至少包括：
- formatVersion、projectId、title、characterId、view(front/back)、canvas(width,height)、units(pixels)、fps、timebase；
- sourceFiles（用户原 PSD 的可选原样归档、checksum）、assets（PNG/WebP 原始 RGBA、尺寸、像素源 crop/offset、hash）、atlas（仅发布优化资源）；
- groups 与 parts（稳定 ID、name、sourceLayerId、order、parentId、visible、locked、opacity、blendMode、clipping/mask、transform、pivot、tags/role、textureId）；
- meshes（vertex positions、UV、triangles、边界、约束、可选软选择）与蒙皮 weights（每顶点对骨骼权重归一、索引有效）；
- bones/rotationDeformers/warpDeformers（唯一 ID、父子关系、bindPose、restPose、local/world transform、pivot、constraints）；
- parameters（id、显示名、min/default/max、值、二维 keyform mapping、组合/优先级、参数组）；
- motions（id、duration、fps/timebase、tracks、keyframes、interpolation、events、loopMode）、expressions、poses；
- physics（固定时间步、物理链、质量/阻尼/刚度、限制/碰撞、复位和随机种子）；
- gameBinding（角色 ID、slot、render scale、脚点、朝向、动作状态映射）。
分离源艺术（永不被 rig keyframe 覆盖）、rig 数据（独立修改）、动画 clip（可复用）、游戏绑定（可切换）。类型校验使用 JSON Schema + TypeScript 严格模式/运行时校验。数据迁移须有版本号和单元测试；工程 ZIP 可无损重新导入，导出必须包含所有可编辑属性，不能只导 PNG 和三个呼吸值。

导出格式命名自有项目格式，例如 .paperchalk-l2d.zip（含 project.json、assets/**、预览图、必要元数据）及轻量运行时 bundle；导出 PNG 序列/透明 WebM/GIF 是补充格式。不要伪造 .moc3/.cmo3/.skel 的兼容性；若未实现真实互通，则标为“不支持”，而非换扩展名。纹理集需可选择无损 RGBA，生成 atlas 带 padding/extrusion/抗出血，检验还原像素和层顺序。需要数据哈希和已删除资源垃圾回收。

## 5. PSD、分层 ZIP 和真实原画的严格输入策略

所有 PSD 导入始终先解析到临时模型、校验成功后再一次性事务提交；不得先清空用户工作区再报错。解析保留画布、层级组/顺序、裁剪矩形、可见性、不透明度、透明度、位图和能支持的蒙版/混合；遇到不支持的 PSD 特性必须报告“已退化/待人工处理”，保留可用图层；非 1024×1024 也须支持项目级实际尺寸，而不是强制塞进 1024×1024。ZIP 用成熟库（如 fflate 或 JSZip），处理常用 Deflate、data descriptor、Unicode 文件名、路径遍历防护、zip bomb 限额、重复文件名和图片解码出错；禁止手写只吃一种 ZIP 的解析器。对大 PSD 使用 Web Worker/OffscreenCanvas（若支持）和可中止操作；进度清晰，崩溃前不会覆盖已有文件。

用户提供的女二号 CHAR-002 原素材是 **1024×1024、真实 16 层 Photoshop PSD、仅正面**，不能将仓库里的 front.png 扁平 303×1024 图片或 7 块基于单张图生成的区域假装为这 16 层。原层角色与大致部位由后到前：
01 后发/马尾(back_hair)；02 双腿(legwear)；03 鞋袜(footwear)；04 百褶裙(bottomwear)；05 真实颈部(neck)；06 校服外套(topwear)；07 手臂/挥手(handwear)；08 耳朵(ears)；09 面部(face)；10 鼻子(nose)；11 嘴巴(mouth)；12 眼白(eyewhite)；13 眉毛(eyebrow)；14 瞳孔(irides)；15 睫毛/眼睑(eyelash)；16 刘海(front_hair)。存储稳定 ID 和真实图层局部 crop+原位 x/y；不把这些 16 层再次合成为不能编辑的一张图。不要凭中文层名猜测隐藏部件；分类建议须可人工纠正。没有真实侧面/背面/闭眼贴图时明确提示：不自动伪造新视觉素材；可以做合理的遮挡式眼睑闭合初稿，要求由实际素材与 QC 验证。女二不是女主，不得混用二人的 PSD/脖子/眼睛素材。

## 6. 真正的 ArtMesh、骨骼、变形器与绑定操作

实现编辑器可视化的具体功能，不是只画骨架。
1. 网格：按 alpha 边界自动生成紧凑三角网（支持洞、头发细丝、透明边），提供网格密度/重点区加密、自动三角剖分、人工加/删/移动顶点/边、锁边、平滑、翻转修复、交叉/退化三角检测、一键复原与镜像。所有编辑实时作用于主画布，可隐藏网格查看实际艺术。
2. 轴点：肩、肘、腕、颈、头、胸、骨盆、髋、膝、脚踝、发束根等根据真实角色设置；智能默认+人工拖拽与精确数值，屏幕像素/世界坐标转换准确。根部固定、脚点不漂浮；手臂幅度与肩部连接柔和，不可裂开肩。
3. 骨骼层级：建立父子关系、局部/全局变换、FK，必要时 IK（手腕/脚）及关节角度约束、骨骼权重画笔、自动权重初稿、权重归一与预览。骨骼不是强迫每个眉毛/瞳孔都挂同一整体旋转；面部相关部件有统一头部 parent 但可独立表情。
4. Warp/Rotation Deformer：任意部件/组设网格笼、旋转变形器，支持嵌套、变形传递、局部坐标、对称编辑、冻结/复位；可在参数不同 keyforms 下手动改顶点并插值，避免正弦驱动覆盖用户设置。
5. ArtMesh 层序与遮挡：后发在身后、刘海在人脸前、瞳孔在眼白后/睫毛后、脖颈由真实 PSD 只有一套、外套与裙摆顺序正确；支持局部 clipping/mask/glue/edge feather 必要时使用，避免露白缝、黑边、重复脖颈、眼球穿过眼皮。
6. 参数：起码支持 HeadAngleX/Y/Z、BodyAngleX/Z、EyeOpenL/R、EyeBallX/Y、MouthOpen、MouthForm、BrowL/R、Breath、ArmPose、HairSway、SkirtSway，并将每个参数的真实绑定对象和 keyforms 可视化。默认值/范围明确，坐标上限按素材允许范围限制，不要为了 30° 标称旋转强行拉伸变形。
7. 物理：发束/裙摆/衣摆独立惯性、弹簧/阻尼/碰撞/上限；头、躯干和发梢相位自然有延迟，脚底和稳固衣服局部不随意晃。阻尼可由动画参数和关节速度驱动，抖动停止后应逐渐归零而非永续魔法正弦。
8. 处理纹理边缘：前后纹理 UV/剪裁不会在网格边界裂开；在遮挡部位没有可见画素时，用真实可见素材和有限姿态范围保持合理遮挡，禁止人工生成未经用户批准的“假脖子、假背面”。

每个工具必须支持点击选中→可视高亮→拖动改变→属性数值同步→撤销→保存→刷新回放后相同。提供显式编辑态与预览态，编辑时不用强制暂停全部页面，主视口仍可实时切换“当前参数姿态 vs 参考原图”。

## 7. 动画系统：必须真正能播、可逐帧、可制作与编辑

一个 PlaybackController 管理全局与每段 motion：time（浮点秒）、frame、duration、fps、speed、loopMode、playing、range、track mute/solo、event cursor。使用 performance.now + 增量与 fixed-step physics，但 seek(t) 独立 deterministic evaluate(t)，不能依靠浏览器动画 WebP 自动推进；逐帧 24/30/60fps 均与确定的关键帧完全一致。播放时一个 RAF、一次状态更新、一套 renderer，不要将 texture rebuild 绑定到 render()。

Dopesheet 功能必须包括：
- 轨道树（对象、变形器、参数、骨骼、可见性、表情、事件），折叠分组；
- 新建/移动/复制/批量选择/删除 keyframe，自动关键帧开关、关键帧吸附到帧与游标、范围框选，拖拽实时更新；
- 常量/线性/贝塞尔/S-curve 插值、图形曲线编辑器、左右切线/缓入缓出、曲线值标尺；
- 头尾循环、PingPong、一次播放、过渡 crossfade、速度倍率 0.25/0.5/1/1.5/2、定点 seek，播放时当前时间和播放按钮永远对应真实状态；
- 预设 Idle、Blink、Talk、Look、Nod、Wave、Startle、Breath 等：只从真实部件产生合理动作，无法完成的动作显示“需要补素材/需要绑定”，不可无中生有；
- 表情和动作可叠加与混合（animation layers）、参数权重、优先级；动作结束自然过渡 Idle，支持“游戏状态机”动作图 Idle/Talk/React/Walk（Walk 若无逐姿素材可明确仅做有限摆动，不宣称真实步行）。

要求 0、duration/2、duration 和任意 t 的 seek 测试一致；Pause→1秒→同帧同像素；Resume→连续；来回拖动不留残影；Loop 边界姿态可无缝；多次切换角色不会旧 RAF 继续画新角色。需要中央大画布即时预览，右边只能是参数面板/可选小窗而非“只有小窗在动”。可以在预览状态直接拖眼球、抬头参数杆并看到即时效果。

物理使用固定步长（例如 1/120 秒）、累积时间上限、边界处理与 reset/seek 策略。对离线导出、游戏运行时、测试重放提供相同 seed 和预热条件；解决帧率差造成的运动差异。确保图层状态与实际渲染帧一致。

## 8. 渲染、性能与设备适配

目标架构：PixiJS v8 的 WebGL2 Mesh 作为第一目标（可选性能验证后 WebGPU）；2D Canvas 为资源不足时的明确兼容/功能降级路径，不要将逐三角 Canvas2D drawImage 循环当作长久高性能方案。GPU 纹理上传只发生在纹理变化时，顶点/UV Buffer 仅按 dirty range 更新；复用贴图、网格、空间索引，减少 draw calls 和纹理切换。渲染可用分辨率自适应、DPR 上限、动态降级物理链/材质画质；不通过牺牲角色质量来强行“全时 60”。

参考验收：在指定基准浏览器/机器上，一名 1024×1024、16 层可编辑角色、约 1k—3k 网格三角的 Idle 预览，目标桌面接近稳定 60fps；中档手机目标 ≥30fps（数字为目标，不是未经实测的既成性能）。实测帧时间 p50/p95、CPU、GPU、纹理内存和峰值内存；操作/拖时间轴反馈不明显延迟。Chrome/Edge 优先，Firefox/Safari 提供明确支持矩阵。WebGL 上下文丢失与恢复、标签页隐藏/恢复、节电/低内存、窗口缩放、全屏切换都可正常工作。至少建立 10/16/30 图层三组压测工程，防止所有截图都只用空角色。

## 9. 统一存储、导入导出与游戏绑定

存储以单个版本化工程为真相来源：可以用 IndexedDB 大 Blob/OPFS（按特性检测），保存事务校验、dirty flag、可靠自动保存、防写入竞态、崩溃恢复、撤销历史压缩；保留旧 DB 数据迁移向导，不自动删除旧用户项目。严禁每次绘画都复制整个 16 层 PNG base64 快照。项目导出/导入必须完成 round-trip：import→edit→save→reload→export→new browser import→像素/层级/参数/动画一致；严格检验资产数量、hash、尺寸、历史关键属性。超配额要明确提示导出备份，禁止显示“保存成功”但数据未真正写入。

与游戏同源：编辑时有真实“游戏预览”按钮；中央或并列视图显示角色在实际 game player/enemy 容器中的比例、脚点、所选面；保存后“应用到游戏”只写被确认的 characterId/view/slot 绑定，在游戏页面同一模型引擎加载并播放，支持回到工作室保留所选时间/角色。前/背面不存在的素材严禁假造；切换失败要留在当前有效面，不跳到女主或空白。静态 PNG 可以作为“静态立绘”导入，但不得自动升级为“可编辑完整 PSD rig”。旧 WebP 仅作“Legacy：不可逐层编辑”模式，允许保留历史结果和迁移导出，但不干扰新编辑器的真实播放。

资源要能在 GitHub Pages 静态托管。可引入 Vite/TypeScript/ESM 编译，最终输出仍部署到 site 目录，确保旧游戏正常；不要暗中改成必须运行私人服务器的产品。文件结构须稳定、URL 加构建 hash 防缓存，不再手工维护几十个 query string 版本标签。记录构建可复现：package-lock/pnpm lock、Node 版本、CI workflow、导出产物清单、缓存策略。

**S3（真正可编辑绑定）：** 自动网格初稿、拓扑编辑、joint、权重、Rotation/Warp Deformer、参数、正交坐标、剪裁遮罩、实时 GPU 渲染；不再依赖硬编码名称正弦变形当主模型。每一种工具附一个可自动检查的实际示例。

**S4（动画与物理）：** 时间轴、Keyframe、Dopesheet、曲线、录制姿态、动作预设、发丝裙摆物理、确定性 seek/replay、完整预览与导出。先完成 Idle/Look/Blink，再做 Talk/React 等，不搞 100 个不能播放的空预设。

**S5（游戏闭环）：** 编辑器与游戏使用一个 evaluator/runtime，统一角色绑定及动作状态；对主角/NPC 同样适用；发布 Pages 后执行实际浏览器验收。

**S6（可选增强）：** AI 分割/自动绑定建议、代理 API、性能极限、项目模板库、额外导出格式。只有 S1-S5 全验收、许可核查后进入。

每个阶段结束需要一个 checkpoint：
- 改动文件和实际功能（不是计划）；
- 测试命令、真实测试结果、动作录屏/GIF/连续截图；
- 不可用功能及精确阻塞原因；
- Github commit/PR、CI 与 Pages URL；
- 下一阶段清单，最多 3 项关键风险。
如某能力当前技术/许可证/资源所限不能完成，坦诚标注，绝不能用假的占位动画或不相关的他人模型冒充。
