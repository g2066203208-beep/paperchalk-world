## 已在代码里落地

1. **不遮挡人物的操作布局**：逐件绑定面板从人物主画布上移到右侧检视栏。默认只展开静止/真人待机/轻风/强风及四项重要倍率；速度滞后、轴点、关节和网格保留在进阶折叠区。移动端角色保持可见，录制和调整时不被控制面板盖住。
2. **骨骼数据可靠保存**：所有关节/待机调整以不可变快照进行队列化 IndexedDB 写入；顶部「保存并应用到游戏」强制等待最新参数提交后才返回。切换角色也先提交未保存工程。
3. **原始部件精修真正用于骨骼**：游戏桥接器通过同一角色 ID 读取绘画编辑器的原位 PNG 源部件，逐 ID、数量和尺寸校验后替换各自运行时纹理。与本机绑定草稿并用，编辑头发的像素会随头发 ArtMesh 动，而不是作为固定的画面补丁浮在上层。
4. **排除旧呼吸短暂闪回**：主角启动时不先启动过时的程序化呼吸；安装独立部件播放器时可显式暂停旧回退动画。若模型损坏，仍可回退到已批准 V4。
5. **准确的导出判断**：即使所有“整层运动”设为零，只要真实独立骨骼处于有效动画状态，一键打包模块就不会误报“没有动画”。新模块需提交 ZIP 到 GitHub inbox 才会永久发布。
6. **预览面积**：进入逐件绑定后重新计算画布适配；移动端仅保留角色选择、保存和当前必需控制。骨骼播放按钮放入侧栏，避免舞台工具条覆盖人物面部。

## 端到端复测

- `.github/workflows/character-editor-tests.yml`：手机/桌面布局、默认与进阶控制、独立关节变形、保存退出后恢复 V4、前后视图与绘画工具。
- `.github/workflows/game-character-dev-tests.yml`：真正从工作室**点击顶部保存** → 返回游戏 → 验证保存的待机参数；在 CI 浏览器中模拟修改原始后发 PNG 一个真实像素，再确认游戏中该像素出现在正确的源部件纹理内。
- `.github/workflows/l2d-modules.yml`：独立 ArtMesh 加载、V4 保留、真实眉毛/鼻子/眨眼像素审计、ZIP 自动安装。
- 以 GitHub Actions 对**该次提交**的运行结论为准，不能以旧提交的成功冒充新提交的验收。
