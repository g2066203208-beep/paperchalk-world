# 夜港：从网页管理面板转向真正精品独立游戏 — 参考研究与重做准则

日期：2026-10-28。状态：**研究方案，尚未按此实现新游戏**。当前 `main` 上已发布的旧式周结算网页管理原型并不满足用户要求。本文件只存于 `research/immersive-underworld-game` 分支，避免无测试地覆盖正式版。

## 纠偏

失败的方案：五个照片卡，点击「接委托／招募／开店／下周」，现金与地盘数值变化，但玩家从未真正站在街道、走进店铺、看到雇员工作，缺少角色行动、实时反馈、可探索的空间和系统性事件。这是一张网页模拟经营表，不是完整游戏。

**真正目标**：白手起家的犯罪题材 *生活模拟 + 城市沉浸沙盒 + 经营成长* 游戏，所有核心成长都先在可移动的场景中体验，再逐渐解锁组织管理；并非尽可能复制某款具体商业游戏。

## 实际作品研究（官方页面与 Steam）

### Big Ambitions — 生活-经营融合，主参考
- 官方：https://www.bigambitionsgame.com/
- Steam：https://store.steampowered.com/app/1331550/Big_Ambitions/
- 学习：角色在 3D 俯视城市里走动、租铺、进入商店、摆放设备、招员工、建立供应链、驾驶车辆。钱不是点按钮跳出来；角色先亲自做事，雇员与业务系统使经营渐渐自动化。
- 不学：把整座纽约地图和繁多产业在首版一口气做完。首先完成一个真实营业的小店。

### Streets of Rogue（第一代）— NPC 与环境涌现互动，主参考
- Steam：https://store.steampowered.com/app/512900/Streets_of_Rogue/
- 学习：俯视可移动人物、可进入建筑、行人生活、NPC 反应、可拿取物品和多种解决问题的方法。任务应该有多条处理路径。
- 不学：把「每个 NPC 都像真人一样智能」写在设计方案里而没有具体规则。先让 8 个 NPC 的活动和反应可验证。
- 注意：Streets of Rogue 2 在 2026-10-28 仍显示 Coming Soon，不能假装它已经正式发售。https://store.steampowered.com/app/2165810/Streets_of_Rogue_2/

### The Precinct — 斜俯视黑色电影城市美术
- 官方：https://www.theprecinctgame.com/
- Steam：https://store.steampowered.com/app/490110/The_Precinct/
- 学习：夜景霓虹、雨后湿路的反光、空间层次、警车与市民运动、昼夜天气和较少的屏幕固定 UI。
- 不学：玩家在该游戏扮演警察，我们要用自己的黑帮主角和活动体系，不能照搬故事和美术素材。

### Schedule I — 先亲手做，再组织扩张
- Steam：https://store.steampowered.com/app/3164500/Schedule_I/
- 学习：玩家本人参与生产与交付、租空间、认识客户与招伙伴，逐步让一线事务自动化；赚到第一笔钱有实际操作过程。
- 不学：它是第一人称 3D 开放世界，完整复制的范围和手机性能成本都太高；不照搬具体商品或玩法细节。

### Definitely Not Fried Chicken / Basement — 反面边界
- https://store.steampowered.com/app/1036240/Definitely_Not_Fried_Chicken/
- https://store.steampowered.com/app/340150/Basement/
- 它们的房间功能、员工分工与生意结构可以借鉴；但如只做指令点击、读图标，仍会违背此次「游戏不是网页经营按钮」的要求。

## 建议的原创游戏方向

**2.5D / 斜俯视可行走城市生活沙盒**。单一连续小街区，玩家可以自由行走、进出 3 栋建筑（出租屋、便利店、台球厅）、观察行人、谈话、搬货、亲自接小活、经营店铺。先有玩法手感与世界自洽，再扩展到势力、地盘和组织管理。

核心体验循环：
1. 早上从出租屋醒来，玩家直接控制角色上街（不是点击「开始一周」）。
2. 先接街边任务或进店帮忙，亲自移动、取货、整理、对话并获得报酬；NPC 有实际的移动、排班与购买行为。
3. 可以租下小店，布置柜台、进货和营业。顾客真的进店挑选付款，有缺货、关门、等待和流失；不是「每周 +150」。
4. 招第一个伙伴后，能看见他从住处走来上班、值守、完成工作，玩家可跟随或重新分配任务。
5. 竞争帮派在邻街巡逻；地区关系和声望影响邻居的态度与是否愿意合作。警方根据可见事件作出反应，而不是无缘无故加「关注度数字」。
6. 随着玩家实力提升，从亲手完成一次工作到管理多个真实运营场所，地盘变化在街上有视觉反馈。

## 专业制作边界

**不要**：每周结算按钮作为核心、五张照片代表整个城市、不可操控的角色、按按钮就增长的影响力、堆成一列的功能框、假装没有截图就通过测试。

**首个可玩垂直切片：**
- 一小段可探索的街道，斜俯视镜头、适度景深与雨夜光照；自有原创材质与风格，不复制商业游戏资产；
- WASD / 手机虚拟摇杆操控，接近物品时出现一个明确互动提示；
- 3 座可自由出入建筑，通行、相机遮挡、碰撞、NPC 寻路；
- 8 名不同职能 NPC，有排班（店员、顾客、路人、伙伴、对手和警员），并可观察至少一天的活动；
- 一家店实际营业：开门、补货、顾客挑选、队列、收款、收店；完整收支账本是从行为记录生成；
- 一名可招募员工执行工作；一次竞争势力事件引起 NPC 真实反应；
- 自动存档恢复人物位置、店铺库存、NPC 状态、钱和游戏时间。
- 两个设备验收：电脑键鼠和手机触控（竖屏优先要可用，横屏优先保证玩法视觉效果）。
- GitHub Pages + 原 Android WebView APK 的自动访问机制保留，网页本体应当用真实实时渲染/碰撞/互动实现，而非 DOM 中摆五张表。

### 技术方向（实施前还需渲染原型验证）
A. 低多边形 3D 城市 + 正交斜俯视相机，基于 Three.js / WebGL，实体碰撞与角色动画。视觉接近精致桌面城市模型，适合建筑、路灯和物件的空间存在感。
B. 精心绘制的 2D / 2.5D 俯视城市，基于 PixiJS / Phaser 等游戏渲染系统。更容易控制 APK WebView 帧率和素材成本，但需要专业化美术资源，不能自动把程序方块称为精美像素画。

两者先做相同规模一小段街景的真实运行原型，在 390×844 和 844×390 手机视口实测，比较可读性与帧率再决定。不要在没有视觉目标的情况下乱写巨量 UI。

## 与此前的照片偏好如何衔接
用户喜欢旧界面右侧**地点照片卡**，尤其照片的写实氛围；这一点是值得保留的视觉偏好，但**不能让照片卡代替实时可探索的城市**。照片可转入地图上的地区档案、过场镜头、联系人笔记或载入画面。主画面必须是能走进去互动的实时游戏世界。

## 验收
- 可以不打开任何经营表格，至少玩满 10 分钟。
- 录像必须看到人物移动、进入建筑、与 NPC 对话、实际执行业务、人员上下班和其他人受到影响。
- 游戏数据由真实实体行为推动，不是 UI 随意加数字。
- 有真实 GitHub Actions / 浏览器测试，提供运行视频或截图；尚未完成时不能声称完成。
