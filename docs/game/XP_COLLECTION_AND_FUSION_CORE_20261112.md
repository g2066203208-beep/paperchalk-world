# 七人阵营小游戏｜XP 收集与融合核心规则 V0.1

> 2026-11-12 用户口头确认的核心规则。**本作以收集、选择和合成 XP 为主玩法**；不是普通升星游戏，人物卡为 XP 载体。此文件是策划规范，尚不意味着游戏运行时代码已完成。

## 一、已确认的 XP 槽位数量（正式决策）

| 人物等级 | 固定 XP 词条数量 | 来源 |
|---|---:|---|
| **一级（小兵）** | **3 条 XP** | 获得小兵时携带三条 XP 词条 |
| **二级（进阶人物）** | **4 条 XP** | 从两个小兵中继承 **3 条 XP**，并由融合道具提供 **第 4 条 XP** |
| **三级（高级人物）** | **5 条 XP** | 从两名材料角色中继承 **4 条 XP**，并由融合道具提供 **第 5 条 XP**（三级具体消耗配方仍待定） |

不允许因词条类型重复而越过该等级 XP 槽位上限；二级四条、三级五条不能变成随意叠加六条或八条。获取 XP、搭配 XP、在融合时优化 XP 组合是游戏的核心。

## 二、融合时 XP 的选择规则（正式决策）

1. **两名参与融合的人物卡的 XP 全部展示在同一个选择面板**，能看到每条 XP 的名称、所属类型及效果；由玩家选择最终继承的 XP。
2. **同类型的 XP 只能保留一条。** 如果 A 的「进攻：伤害提高」和 B 的「进攻：攻速提高」都属于进攻类型，必须在这两条之间选一条；不能同时保留，也不能让系统自行合并为一条或者随机替玩家选。
3. 不同类型 XP 不因类型而相斥；实际选择数量受目标等级槽位约束。**融合道具带有自身 XP 类型和词条，其新增的 1 条也必须参与同类型唯一性检查**；道具的具体种类由之后的道具表定义。
4. **一级 → 二级：** 两张一级小兵各携带 3 条 XP，候选最多 6 条。玩家从人物材料中**选择恰好 3 条不同类型 XP**，再消耗**一件带 XP 的融合道具**，由道具提供**第 4 条不同类型 XP**。因此二级固定拥有 4 条；不允许从小兵直接选满 4 条后再额外叠道具。
5. **二级 → 三级：** 延续同一结构：先从材料人物的 XP 中**选择恰好 4 条不同类型**，然后用**一件带 XP 的融合道具**提供第 5 条不同类型 XP，生成 5 条 XP 的三级人物。**注意：二级→三级的具体人数、等级及其他消耗配方尚待用户确认**；这里确认的是 XP 的 4+1 结构。
6. 必须保留每条 XP 来源，融合预览明确显示目标人物会有哪些 XP，不得只给随机结果。

### 例子

一级小兵 A：`攻击型·破甲`、`防御型·格挡`、`速度型·先手`。
一级小兵 B：`攻击型·连击`、`经济型·战利品`、`治疗型·回复`。
融合道具「染血戒指」：`吸血型·生命汲取`。
合成二级时先从小兵中选**三条不同类型 XP**，例如 `进攻·破甲`、`防御·格挡`、`经济·战利品`，再由道具加入 `吸血·生命汲取`。最终 **3+1=4 条**。若挑选了与戒指同为吸血类型的角色 XP，则必须换一条，不能同类型同时保留。

## 三、尚未定案的边界问题（不能凭空视为已确认）

- **不足 3 个角色来源的不同类型 XP 时怎么办？** 如果两张一级小兵的 XP 总共不足 3 类，则不能完成「角色继承 3 条」步骤；是否允许特殊洗词条/补充材料仍待定。若道具 XP 与已选 3 条同类型，必须重新选词条或换道具；不能产生 4 条中有相同类型的结果。
- **二级和三级外观/职业：** 用户已确认有小兵职业、身材、随机性格；它们与 XP 是不同字段。主体与材料的职业/身材/性格如何影响最终人物，仍可讨论，不能自动等同 XP 类型。
- **XP 类型全集、每类具体词条、道具词条设计、道具掉落与稀有度、重掷/保护、同阵营/跨阵营限制**：均未最终确定。融合道具作为新增 XP 来源这一角色已明确，但每类具体道具尚未定稿。

## 四、用户明确的其他小游戏边界

- 战斗全部由人物卡参与，自动攻击，最多七名上阵。
- 身材为萝莉型/少女型/成熟丰满型三种小兵独立美术人物；随机性格另算。人物卡上存在职业及 XP 等多个维度。
- 融合道具直接提供目标等级的**新增 1 条 XP**，是四/五号词条的关键来源；它不是只给数值加成或无意义的加槽钥匙。遗物可另设局内永久 Buff，但不得抢占角色 XP 继承机制的核心地位。

## 五、正式设计原则

不要再把合成解释为“自动继承素材一个固定特长”、把 XP 当成单纯经验条、把道具视为单纯数值加成、或把职业/性格/身材直接当成 XP 词条。不得更改已确认的 **一级 3 / 二级 3+道具1=4 / 三级 4+道具1=5** 结构和**同类型只能选一条**规则，除非用户明确修订。
