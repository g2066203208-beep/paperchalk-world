# 森林第一关｜统一3D卡牌视角与实物部署规范（2026-11-13）

## 2026-11-14 最新通用演出规范：场景所有建模物体灵动缩放出现与消失

**用户明确要求：不是瞬间显示/隐藏模型。** 所有可创建、移除的3D场景物件（人物卡、设施、树木、灌木、地形方块、物理牌堆与手牌）遵循统一的缩放生命周期。

- **生成**：从接近0缩放到1，经过约1.08～1.15的轻微弹性过冲再落回1；地形/树木从**底部锚点**生长，不能飘在半空中。
- **消失**：先缩小到接近0并淡出，然后才释放/删除渲染实例；敌人被击败后不再用固定计时器直接删除模型。
- **事件触发**：地形挖掘、抬高后要短暂缩放弹动，但地形的真实高度、碰撞和卡牌部署坐标仍由地形引擎负责，不能跟着视觉放大更改战术判定。
- **卡牌**：七堆同款实体牌每一张3D卡入场有错峰弹性；手牌抽出先沿牌面法线抬起、再越过牌堆飞向手部，避免穿模；手牌打出或清空有短促的缩小消失。
- **统一模块**：`site/card-battle/engine/object-animations.js`（enter、exit、pulse、sample、finished、reset）。每个物件稳定ID，渲染侧根据进度缩放真实WebGL网格，不是CSS UI动画。所有重复物件共用同一模块。
- **性能与可访问性**：支持 prefers-reduced-motion；动画有严格时长，缩放只影响显示不改变碰撞逻辑，移动端限制过渡对象数量并复用卡牌纹理。
- **验证**：`tests/object-animations.test.cjs`，以及 `tests/forest-level-01-browser.mjs` 的出现/退出/地形弹动与桌面手机点击回归。


## 2026-11-14 最新要求：七个同款3D牌堆并排，不要孤立结束卡

**本节覆盖文档中之前的“第一关只留一个牌堆”和“七槽大盒子”规则。**

- 第一关森林敌我各 3×3、我方一张伐木工人物卡仍成立。
- 屏幕下沿必须横排**七个独立的真实3D牌堆**，先采用相同的尺寸、正面朝上的临时卡面和统一的平放透视，不能有连体木箱、七个卡槽或笨重底板。
- 七个牌堆都是独立可抽取的原型牌库，各 10 张，初始牌面及顺序一致；玩家抽其中一堆，不会让其他牌堆同时减少。后续七职业的真实卡池再分别替换。
- 伐木工人物卡初始放在战士牌堆顶端，由玩家手动部署到九宫格空位。**开局手牌 0 张；部署后也不自动摸牌**。只能手动点击牌堆一次抽一张。
- 手中最多10张3D卡，任意选择打出，第一次出牌后普通摸牌锁定；结束回合清手牌。
- **删掉右侧孤零零的“结束回合”实体卡**。当前保留 Enter 快捷键结束回合，正式移动端结束回合交互单独设计，不能再混入第八张独立牌。
- 保留人物与行动牌使用战场同一个WebGL模型、实际厚度、动画、卡牌正面，不改回网页UI。
- 需要同时检查1920×1080桌面、390×844手机：7堆同一水平线且全部在屏幕内，人物卡可见可拿取，10张手牌不破坏战场可读性。

对应代码：`site/card-battle/engine/scene-card-hud.js`（七堆底部布局，-1.18弧度的统一平放角度），`engine/profession-decks.js` 的 `prototypeAllClasses`，`ui/forest-hand.js`；实际截图和端到端测试由 `tests/forest-level-01-browser.mjs` 产出。


## 2026-11-14 最新实装优先级：第一关只留一个正面3D牌堆（不得回退）

用户最新明确否决七槽连体盒在**第一关**的展示：先做好最小可玩的画面，只有**一个农民战士职业牌堆**。未来完整配队才考虑七职业的同时展示，当前森林1v2严禁出现七个空槽。

- **唯一可见牌堆**：底部中央一个有真实厚度的3D行动牌叠，薄底托而非大木盒，使用战场同款 `drawCard()` 模型。最上层与各层行动牌全部为**正面**，顶牌随真实牌序变化；不得恢复卡背贴图。
- **初始人物**：批准的萝莉伐木工人物卡放在牌堆顶端，清楚显示完整立绘；玩家点击拿起或拖放，亲自部署到我方3×3空格，不自动上阵。
- **初始行动手牌0张**。人物部署完成后仍是0张，必须玩家点击牌堆才摸第一张。任何“部署后发5张”代码或提示都是错误版本。
- **摸牌**：未出第一张前不限摸牌次数直至最多10张；每点击实体牌堆取顶牌1张；一旦打出一张，普通摸牌锁定；已摸到手里的任何牌都能自由选择打出；结束回合清空手牌。
- **手牌表现**：3D纸牌正面面向玩家，最多10张按靠近镜头的弧形错叠排列；不能改回网页按钮，也不能把手牌重新按职业堆叠。桌面和390×844竖屏手机都应实际测试点击和渲染。
- **镜头**：场上敌我各3×3总共18个格，战场高于底部唯一牌堆，不能让牌堆和手牌遮住可交互格；移动设备需自动根据窄屏距离调相机。
- **UI与美术**：不开大块木板或网页HUD，也不把教学提示条盖在人物立绘上。原画路径和人物卡引擎保持不变。
- 实装模块：`site/card-battle/engine/scene-card-hud.js` 的 `drawSinglePileBase`、`ui/forest-hand.js` 的 `openingDraw:0` / `onDeployment()`、`engine/profession-decks.js` 的 `remainingCards()`。浏览器验证：`tests/forest-level-01-browser.mjs`；只有测试和实际截图都通过才算这一阶段完成。


## 2026-11-14 追加硬规则：面向玩家正面必须敞开、贴屏幕底边

**玩家明确否决正面封闭木墙**。卡盒是一个长条实体、七个真正的凹槽，不是七个隔开的独立盒子，也不是一个遮住牌堆的高前挡板。

- **必须沿屏幕下边缘一字展开**，宽度接近屏幕全宽；不能漂浮在战场上方或底边留明显空带。
- **朝玩家的前侧只允许极低防滑挡沿**，其他前侧全部敞开；后壁和两端可保留足够高的支撑，6个内部隔板采取“后高前低”，不得阻挡牌堆朝向玩家的侧面。
- 7个槽都有深色底衬，空槽明显看见凹槽深度与底面。每盒的职业名和剩余张数刻在底部的实物铭牌上，不使用额外网页UI。
- 每张行动牌都以战场卡牌的同一立体卡模型逐张绘制，并沿**牌面法线**产生真正可见的叠层厚度；数量减少，实体侧边高度随之减少。
- 开局人物卡压在战士牌堆最上方，后续从盒子拖到我方3×3的位置；不得被任何高木框挡住。
- scene-card-hud.js 以 drawConnectedTray 生成唯一连续底盘和六个共享隔板；物理前壁应为很薄的 frontOpening=low-lip，通过真实Chromium截图核对，不可以只看测试标志就算美术合格。

## 2026-11-14 最新布局确认：一体式七槽卡盒（不可回退）

用户明确要求：“做成大卡盒，一排连在一起，像筹码盒一样，一排七个位子放在屏幕下端”。

- **不是7个分散的小盒子。** 底部必须是一整块连续的、真实3D的长条卡盒主壳体，共用长底座、前后边框与左右外壁，**只有6道内部隔板**切出7个槽位。
- 七槽各自代表固定的七个职业。槽底有绒布质感，前沿有职业铭牌。整体造型参考实体筹码收纳盒，不能变成7块分立网页矩形。
- 职业盒内的卡牌必须逐张调用战场同款3D牌模型；用完后的空槽仍属于同一个实体盒，不允许隐藏整槽。
- 开局伐木少女仍是**放在战士卡槽顶端的独立人物卡**，玩家手动部署到我方3×3后才能正常摸行动牌。
- 手牌属于前景近摄像机区域，独立3D扇形，最多10张，可任意出牌；不能与底部连体盒混成一整片不透明UI。
- 2026-11-14 对应实装：`engine/scene-card-hud.js` 的 `drawConnectedTray`；不再调用老版每槽一个独立 `drawBox`。浏览器测试需验证 `connectedTray === true`、`trayBodies === 1`、`compartments === 7`。
- **视觉验收不等于代码测试通过**：保留截图审查，尤其看卡盒是否过高、遮挡战场或人物卡。


> **最新用户要求优先级高于旧代码：** 不要网页UI/暗色整块卡牌工具栏。七职业各一个**真实3D开口盒**，盒里每张行动牌有独立厚度和实体；第一关伐木少女人物卡**真实叠在战士盒顶部**，必须手动拿起并部署到我方3×3格之后才开始战斗。最多10张手牌在视野前景如真实拿牌一样形成扇形，并可以**任意挑选**打出。盒子、人物卡、战场卡、手牌全部使用同一个WebGL卡片模型，材质一致。
>
> 《邪恶铭刻》（Inscryption）可供研究的是其**物体交互语言**：桌上牌库、贴近玩家的部分重叠纸牌扇形、鼠标悬停抬出一张、点击后移动至战场。**不要直接照抄它的角色、卡面、木屋材质或UI图标。** 我们自己的主题是森林、农民组织、七职业、敌我各3×3。

## 视觉错误的硬性禁止

- 禁止下半屏整块不透明纯色矩形当「手牌背景」，不要将3D场景与网页卡牌UI上下硬分屏。
- 禁止用七个只画边框的扁平HTML盒子/矩形占位槽代替真实3D开口卡牌盒。
- 禁止用DIV、CSS卡片、SVG纸牌代替游戏内真实WebGL卡牌。
- 禁止10张手牌做成没有重叠、完全无透视的线性按钮栏，也不能把摸出的手牌按职业堆回成只准打顶牌。
- 禁止自动把伐木少女部署到战场，或在部署前自动摸出行动牌。
- 禁止七张人物卡参与每回合行动牌重洗。
- 禁止为视觉好看就遮住敌我3×3的可点击格子。

## 物理视觉与动画结构

- 卡片统一：`site/card-battle/forest-level-01.html` 原生 `drawCard()` 的圆角3D卡面、边框、侧壁几何与纹理；场上角色/盒内行动牌/玩家手中牌是同一个底层模型。
- 卡盒统一：`site/card-battle/engine/scene-card-hud.js` 实体木盒底板、四壁、角件、职业铭牌。每盒有独立3D卡片叠层；根据牌库实际剩余量减一层，而不是贴一个「厚牌堆」贴图。
- 扇形手牌：近摄像机、可互相遮挡、居中弧形排布，鼠标悬停所指卡片抬升/前倾/放大；10张牌也必须能任意抽选。
- 抽牌过渡：单张卡由所属盒漂浮、翻转/滑入玩家前景手牌，禁止突然出现。
- 部署过渡：开局人物卡顶在战士盒；点击拿起并点击我方格子，或者直接拖到格子。合法空位高亮，落格动画；此后解锁战士行动牌。
- 摸牌规则：未出第一张牌前任意职业盒摸到总手牌10张；第一张打出后普通摸牌锁定，特效除外；回合结束清空手牌。
- 场景：敌我各3×3共18格，森林；场景改动动画与土屑粒子走 `engine/voxel-animations.js`，卡牌受同样的地形高度影响。
