6. resolveBattle(true) 立刻进入 victory/战后页面，没有敌方清场和金币/奖励转移镜头。
7. buy(index) 单击就扣钱，无法先查看商品而不购买。这是已被原作开发者指出并修正过的 UX 类问题。
8. 援军主要 push 进入 b.foes，缺少入场队列、预告、位置锁定、卡牌落位演出。
9. move(uid,slot) 只交换 slot；重抽只更新数组；动作时缺少卡牌稳定身份和连续轨迹。
10. 现有 sound() 基本是短电子提示音，不是纸牌/木头/铃/冰/攻击分层的材质反馈。

# 03. 总体架构：规则 / 事件 / 时间轴 / 持久视图 / 存档

实现四层：
A. InputController：把鼠标、触摸、键盘转成高层命令（PLAY_CARD, MOVE_UNIT, REDRAW, SHOP_INSPECT, SHOP_CONFIRM 等）。
B. PureRules：确定性计算战斗结果，以事件流形式发布；
C. PresentationDirector：消费语义事件，以 timeline/FX/audio 系统播放一整套连续镜头；
D. SaveManager：在逻辑安全点记录权威状态和待完成事件事务，刷新能恢复且绝不重复发奖励。

推荐事件格式（示例）：

~~~ts
type GameEvent = {
  id: string;
  transactionId: string;
  phase: string;
  sequence: number;
  type: string;
  actorId?: string;
  targetIds?: string[];
  fromSlot?: number;
  toSlot?: number;
  before?: Record<string, unknown>;
  after?: Record<string, unknown>;
  payload?: Record<string, unknown>;
  durationHintMs?: number;
};
~~~

动作必须将“已计算规则结果”和“什么时候在屏幕展示”分开。伤害不能在动画蓄势帧就显示扣血；死亡不能在致命命中前从 DOM 被删除。演出结束后一定与规则引擎的权威状态一致。

统一状态机：
MENU_IDLE → CAMP_IDLE → LEADER_SELECT → ROUTE_MAP → SCENE_TRANSITION → BATTLE_PREPARE → ENEMY_ENTER → ALLY_ENTER → DEALING → PLAYER_READY → TARGETING → CARD_RESOLVING → TURN_RESOLVING → DEATH_PENDING → BATTLE_VICTORY / RUN_DEFEAT → REWARD / RESULTS → ROUTE_MAP / CAMP。

商店独立：
SHOP_BROWSING → SHOP_INSPECT → SHOP_CONFIRM → SHOP_PURCHASING → SHOP_BROWSING / SHOP_LEAVING。
其中 SHOP_INSPECT 绝不改变金币，SHOP_PURCHASING 由唯一交易 ID 确保只扣一次。

### 动画导演 API

~~~ts
director.enqueue(gameEvent);
director.play(sequenceId);
director.pause();
director.resume();
director.setSpeed(0.5 | 1 | 1.5 | 2);
director.skipToSafeCheckpoint();
director.cancelTransaction(transactionId);
director.isBusy();
director.timelineTimeMs();
~~~

动画每一帧使用 requestAnimationFrame 的统一时钟；逻辑 tick/表现时钟分开，后台标签恢复后不能瞬间把所有动画跳过并错误结算。用稳定的卡牌 ID + keyed DOM 或常驻对象层；位置交换使用 FLIP，而不是整页重绘。

演出锁不允许无限阻塞：操作可以预先反馈，合理输入排队；购买、重复出牌、死亡中操作等危险命令禁止并明确提示。动画被跳过时仍要在安全点设置全部数值、物件位置和下一阶段状态。

# 04. 画面尺寸/布局先固定，再加动画

强制测试分辨率：1920×1080、1366×768、844×390、390×844、1024×768、360×740、430×932、1280×720、2560×1440，分别考虑 DPR1/2/3、浏览器 UI 与安全区。

基础战场：**左我方、右敌方，上下两条战线，每侧每条战线三个可放卡位，总 12 格**。所有卡拥有稳定 slot ID，竖屏可以折叠显示为每条战线我方三张与敌方三张，但不可改变攻击规则。

横屏初值：顶栏约 4%–6% 高，主战场约 70%–74%，手牌台面约 22%–26%；这只是我们工程初值而非原作像素取样。手机横屏根据实际高度压缩顶栏，让 12 张卡、HP/ATK/CD 和五张手牌同时完整可操作。

现有源码浏览器审计曾测到的单位卡：1920×1080 约 218×258 CSS px；844×390 约 94×104；390×844 约 110×126。**新动画必须兼容这些几何约束，不能为了特效放大后把其他卡遮住**。每张卡的静态布局、拖动位置和攻击动画目标必须从 SlotAnchor 获得。

统一 UI 层级：
BACKGROUND（雪林） < GROUND（地面） < SLOT_MARK（空格） < UNIT_CARD（单位牌） < CARD_EFFECT_BEHIND < CARD_EFFECT_FRONT < DAMAGE_TEXT < HUD < INSPECT/SHOP_DIALOG < DRAG_PREVIEW < SYSTEM_MODAL。

所有视角、手牌、卡牌的 BoundingBox 在 resize/orientation change 后重新测量。尤其不要把落点逻辑与上次设备宽度绑定。角色原画必须保存原始比例，卡框窄且不压脸，属性形状/颜色具备独立识别。

# 05. 统一毫秒级交互原则

**以下均为我们提出的初始工程目标，不是冒充 Wildfrost 实测原动画时间。** 根据实机录像和手感再逐步调整。

- pointerdown → 按压高亮或抬升：目标 50ms 内，p95 不超过 80ms；
- 拖牌跟随：目标 1 帧、峰值不超过 2 帧的视觉延迟；
- pointerup → 合法放置确认视觉反馈：80ms 内；
- 非法落点返回原位：120–200ms；
- 抓起卡牌：60–90ms，scale 1.04–1.07，抬高 8–14px；
- hover：90–160ms，微倾斜 0.5–1.5°，邻卡不应被全部遮住；
- 释放部署：180–320ms，小幅压缩/回弹，清楚的纸牌落地音；
- 同伴换位：180–280ms，两个卡牌同时 FLIP，互不突然穿透；
- 详情放大：150–230ms；关闭：100–180ms；
- 受击命中停顿：约 50–100ms 设计范围，具体根据攻击种类和录屏调整；
- 可选正常/快速/降低动态效果，每种速度**同一 seed 最终逻辑状态必须完全一致**。

操作手感必须“立即反馈 + 动作短、清晰、具有重量”，而不是全部操作都用 400ms ease-in-out 慢慢滑动。动画起步迅速、命中短促、收尾轻巧。所有关键声音对齐动画事件，不能仅在事件开始时发出电子嘟声。

# 06. 完整开场：菜单 → 营地 → 选领队 → 地图 → 战斗

菜单（建议 600–1000ms，可跳过）：
- 首帧有完整稳定背景，不出现空白页面；
- 0–180ms 环境光、雪景细节建立；80–300ms 标题短距离落位；
- 150–520ms 主功能按钮依次以 40–65ms 错峰出现；
- 玩家无需等待全演出结束才能操作菜单；
- 每个按钮都具备按下 50–90ms 小幅压缩与确认音；不抢视觉中心。

村庄场景：
- 场景切换保留旧视图直至新视图准备好；
- 建筑自身高亮成为点击对象，不再用四个大网页按钮代替可游览村庄；
- 进入建筑时镜头朝该建筑移动少量，门口/房屋界面连贯出场；
- 回村有独立的返回镜头，不能一切直接跳屏。

领队选择：
- 三张领队卡依次 80–110ms 错峰进入，选中抬升 10–16px；
- 详情面板在稳定位置显示 HP/ATK/CD、专长、当前卡组；
- 确认后领队卡向地图入口方向收回，提示“准备远征”；
- 无法双击触发两次新游戏，返回保持合理选择状态。

地图行进：
- 路线节点和虚线/实线与真实可达性一致；
- 选择分支后先锁定选择，旅行者标记沿曲线 350–650ms 前进；
- 到达节点才打开事件场景，不能地图按钮点击即瞬间刷新成另一个 HTML 页面；
- 三区过渡拥有原创视觉统一的短转场，数据持续保留。

战斗开场（建议总 800–1400ms，可快进）：
- 0–120ms 新背景和地面装载；
- 100–350ms 敌方第一张牌从右侧/远处雪雾滑入，末端轻回弹；
- 250–540ms 第二张敌牌错峰入场（间隔约 100ms）；
- 370–630ms 领队卡从左侧进入我方合法阵位；
- 480–730ms 已召募伙伴依次出现；
- 650–1050ms 五张手牌依次从牌堆飞出，35–70ms 级联；
- 900–1220ms CD/援军钟/重抽钟出现并完成短提示；
- 约 1200ms 进入 PLAYER_READY，允许拖牌操作。

所有动作可以提前跳过，跳过只快速完成视觉，不得重复发牌、增援、重置 HP 或触发自动攻击。恢复存档不得重新播放“新开局”并多抽卡。

# 07. 战斗出牌、回收、重抽：不是简单数组变化

**手牌拖动**：
抓牌时抬升、微旋转、源位置保留虚影。移动时按实际 pointer 坐标流畅跟随。合法单位被细线或局部高亮提示；非法目标灰化。落点不合法时卡牌沿原路径 120–200ms 回弹，状态不变，给出短促提示，不出现满屏 Toast。

**出牌**：
确认后手牌从手牌带移向技能/目标点，目标线跟随；根据技能类型播放不同施放动作。发起动画→命中帧→显示更新 HP/护盾/CD/状态→回收进弃牌堆；不允许在点击帧瞬间把牌从画面移走。

**我方卡换位**：
预览原位和目标位，松手后两张已部署卡同时 FLIP 或有明确避让轨迹；结束后更新目标预览和攻击方向。拖动与长按查看详情不能冲突；不支持落点永不消耗回合。

**伙伴回收**：
收起牌体、轻翻转、飞回队伍牌堆/弃牌口；不播放死亡效果。回收后目标顺序立即依引擎规则重算，动画中不允许其他攻击错误命中已回收的旧位置。

**重抽钟**：
已充满免费 / 未充满会消耗回合，表现不同。点钟后现有手牌 150–260ms 分批收回，钟摇动和纸牌洗牌声，再以 30–65ms 错峰重新发出；最后一张手牌未落位前不能点中不存在的物件。缺牌/牌堆耗尽要有可解释的结果。两种重抽的回合成本和动画不能混淆。

**援军钟**：
提前显示将到来的一波，倒计时临近时高亮、短震动并给出即将入场的视觉线索；不应“数值跳到了 0，敌人瞬间从空中生成”。敌方格全满要进入可解释的排队/变体规则，绝不覆盖别的单位。

# 08. 自动攻击：真正的单次攻击镜头时间轴

现有 takeTurn() 一次性计算全部敌军和友军攻击，必须改为产生可顺序播放的 semantic events。任何复杂技能都必须遵循“宣告 → 蓄势 → 前进或投射物 → 命中停顿 → 数值变化 → 命中特效/状态 → 归位 → 下一事件”。

建议普通一次攻击耗时 360–650ms，按动作复杂度调整：

| 相对时间 | 画面动作 | 必须同步的语义事件 |
|---:|---|---|
| 0–65ms | 攻击者的 CD/攻击徽章点亮，轮到自己行动 | AttackDeclared |
| 65–140ms | 攻击牌向后退 3–7px，轻微蓄力 | ChargeStart |
| 125–225ms | 近战前冲 8–18px 或远程轨迹/弹道发出 | AttackTravel |
| 195–250ms | 目标实际命中，短暂 hitstop（3–6 帧） | AttackHit |
| 230–380ms | 护盾先结算，生命变化，伤害飘字上升 20–40px | ShieldBlocked, DamageApplied |
| 280–460ms | 目标回弹、攻击者归位，碎纸/雪粒自然衰减 | ImpactRecover |
| 380–620ms | 如果发生冰冻、反击、死亡等，转入依赖事件 | StatusApplied, ReactionQueued |
| 结束 | 下一张单位攻击 | AttackCompleted |

这里的毫秒是工程设计参数，**不是 Wildfrost 源视频已经测过的时长**。实际录屏对照后的修订写入统一时间表。

**一定保证真正的攻击目标正确**：前排逻辑、上下两条战线、自动攻击顺序、角色移位后的目标、范围攻击、嘲讽/反击的目标都由同一个规则接口给出，不能只在动画层选择最近的 DOM 节点。出手帧应高亮对应 UnitId，不能靠 name 查找，因为可能有同名单位。

**攻击牌具有纸牌重量，而非二次元人物动画**：我们目前大多是静态 Anima 插画，因此主要操作牌体 2.5D 倾斜、速度变化、轻短的冲刺、遮罩/轨迹、接地阴影和镜头反馈；不能假装已经有完整角色帧动画。更换素材后不需要重做时间轴。

### 打击强弱分层

- 普通命中：局部明度闪 1 次，目标后退 3–7px，牌体缩放 0.98 → 1.03 → 1，飘字 400–550ms；
- 破盾：优先让护盾边缘弯曲/碎裂，HP 仅发生实际穿透变化；
- 重击/暴击：加 2–4px 视觉震荡、约 50–100ms hitstop 和双层短促拟音；不做满屏白闪；
- 反击：必须从受击方指向攻击者，有清晰次序，双方身份不混淆；
- 连击：每击有单独命中与数值事件，间隔建议 70–125ms，可提速但不丢计算；
- 免疫/抵抗：视觉上显示抵抗或护盾，不能用红色扣血特效冒充抵抗；
- 闪避：位移和错过目标的轨迹必须不同于命中，不减 HP；
- 反伤/毒伤：分别有自己的来源 ID、效果类型与死亡归因。

### 镜头反馈

镜头震动可以按攻击类型设计最大幅度：
- 轻攻击不超过 1–2 CSS px；
- 强攻击不超过 3–5px 且 100–160ms 收敛；
- 连续攻击叠加必须限幅，绝不能因三个 hitstop 而长时间无法操作；
- 降低动态效果选项必须保留命中边框、伤害文本，不抖屏。

# 09. 单位受伤、死亡、阵亡和消散的全流程

死亡**绝不是** rule engine 过滤 hp<=0 后直接删除 DOM。规则可以判定已死，动画层必须保留一个短期可见的 VisualGhost 直至死亡表演完成。

状态：FatalHit → Hitstop → ZeroHPHold → CollapseOrFragment → Exit → SlotReleased。

建议普通死亡完整 430–800ms：
0–80ms：致死一击按正常伤害命中，目标牌从稳定位置轻微后倾；
80–160ms：停顿让玩家明确看见 HP=0，牌框光泽/颜色发生短暂变化；
160–330ms：牌体一角折起、沿地面方向小幅倾倒或破裂；
280–590ms：若为普通敌人，纸牌碎片与雪尘扩散、淡出；若为我方伙伴，收敛破碎，体现损失；
500–760ms：画面 Ghost 清理，槽位标记渐显，下一行动开始。

不能将普通击倒与“回收进牌堆”混成同一种效果。不能把生命值低于零的敌人继续当目标，也不能让其幽灵牌参与下一回合计时。

### 我方领队败亡：完整失败审理

领队 HP 达 0（或本项目的其他明确失败条件）只是失败判断触发，**不可立刻跳 result 页面**。

1. 完成致命攻击和减血显示；
2. 暂停其他会改变胜负的输入，将本回合剩余动作进行确定的终止或按规则结算；
3. 领队牌中心停住 180–320ms，周围场景轻微减饱和，其他牌不突然消失；
4. 领队牌沉入雪地、碎为纸片或翻覆（400–850ms）；
5. 背景音乐轻微收敛、局部风雪声延续，停顿 200–400ms；
6. 揭示失败标题和判定原因，播放明确但不过长的败北短镜头；
7. 根据完整战斗日志逐项显示最后三次主要事件、致死攻击者、攻击/防御/最终生命值；
8. 出现“返回村庄 / 查看战绩 / 重新远征”可操作选项；
9. 只根据真实权威状态提交本局失败，不得因刷新/连点重复记一次失败或重新领奖。

死亡过程提供跳过按钮（或长按跳过），跳过只跳视觉；结果必须仍正确，不能变成游戏继续。失败整体建议 1.0–2.1 秒；具体以真正的录屏和可接受节奏修改。

### 敌方首领死亡

首领死亡比普通敌人更有层次：最后一次打击→短暂停顿→卡面局部出现裂纹→牌体缓慢折起/翻倒→冷雾消散→战场只剩我方→胜利。注意**不是强行全屏播大爆炸**，雪境童话卡牌仍是柔和、精细、有重量的纸面语言。

# 10. 首领入场、变身、增援和通用召唤系统

### 普通敌军增援（预告 → 来临 → 出场）

援军钟应有可预测的数值和临近高亮，避免凭空出现敌人。

- T-1 回合：钟与敌方候选槽位轻闪，提示即将有敌军；
- 事件开始 0–100ms：确定敌方可用格，锁定合法目标槽；
- 100–250ms：右侧树影/雪雾中出现卡牌轮廓；
- 200–470ms：敌牌沿清晰弧线/短直线依次进入，错峰 60–120ms；
- 400–560ms：纸牌落位、略压缩 0.96→1.03→1.00，HP/ATK/CD 逐项清晰出现；
- 560–650ms：撤掉入场特效，恢复正常可行动状态。

不可覆盖已有单位。满场时按明示的队列/候选位置策略等待，不能放到虚空。死亡或胜利后的援军 queue 要清理，防止战后结算突然再入场。

### 通用召唤（角色 / 手下 / 设施 / 机械 / 魔女使徒）

召唤师可以**摇人、招呼手下、调来保镖或其他同组织角色**，而不是只有兽。统一 SummonEntity 接口，按类型套不同动画皮肤。
状态机：SummonRequested → SlotCandidate → SlotReservation → CastCue → Materialize → Land → Active。
角色从触发来源到目标格有明确轨迹/光效及轻柔落地；CD、生命、攻击等状态在最终入场时清晰显示；已被预约格禁止第二个召唤覆盖。
失败召唤不能消耗手牌。召唤在胜利或失败事件产生后须取消或按规则终止。召唤不能仅是在 DOM 直接增加一张卡。

### 首领登场和阶段

首领演出可以比普通援军多一个 500–900ms 的短特写，但最终必须落在与普通卡一致的可玩阵位，不能遮挡其他单位与手牌。具体流程：预告→背景局部暗→首领卡从合法方向进入→卡牌身份/机制显现→恢复控制。

需要有阶段 boss 时使用 Phase1 → Trigger → PhaseShift → Phase2，阶段切换要与数值事件同步。现有游戏若只有单阶段 boss，先如实列为未完成，不要造假说已具备二阶段。

# 11. 技能和状态特效：每一类必须独立、可辨识

冰冻：
- 150–260ms 投射冰晶或冰纹在目标牌四周生长；
- 目标 CD 的暂停标识明显，不能只变更 stunned 数字；
- 冰冻持续期间在动作排序前显示“冻结不能行动”；
- 解除时 200–350ms 小碎冰离开卡面，立即回到普通 CD 视觉；
- 绝不盖住脸/角色名字。

护盾：
- 防护施放出现环绕牌体的小型防护片，徽章数值增长；
- 命中先震护盾后显示 blocked 数字；
- 被消耗清零时 5–12 枚低成本小碎片迅速散开；
- 格挡 0 实伤不能显示普通扣血飘字。

治疗：
- 从施法者或道具向目标移动温暖柔光粒子，抵达目标时 HP 增长；
- 满 HP/超限不能出现虚假的治疗数字；
- 医生的恢复动作和卡牌动作保持统一风格，不出现廉价网页绿色发光整屏效果。

破甲/标记：
- 在目标盾牌或牌框边出现短促裂纹/墨迹划线；
- 真实数值加成的变更在标记落点时同步；
- 标记叠层必须清楚区分个数和存在时长。

枪击：
- 静态猎人原画保留，不需要 Anima 新动作；
- 牌体微后撤、短枪口白金点光、沿合法目标方向的高速弹道 80–140ms；
- 准确的命中冻结与敌人挨打效果、清晰数值、纸牌震颤；
- 不要喷射满屏模糊光束，也不要用整屏暴力红光表现普通枪击。

近战：
- 卡向前快进 8–18px，清晰斩击弧形短遮罩，准确命中后迅速回位；
- 伤害数字按命中帧生效，不提前扣掉；
- 不使用人物整张 PNG 非均匀拉伸做动作。

范围和连段：
- 先短预告影响范围和合法目标，再逐个目标出现打击事件；
- 2–5 次连击每次命中都有单独反馈与实际数值，不把 5 次伤害合成一个不明原因数值；
- 对同时阵亡的单位保留多个死亡视觉对象，但规则事件唯一。

中毒、燃烧、加速、弱化、反击：
- 每种拥有 begin / tick / expire 三类事件，以及统一边角小徽章；
- 颜色、粒子形态、声音触点与主规则一致；
- 有限递归机制防止互相反击产生无限事件链。

# 12. 胜利、战后清场、掉落、领取奖励与进下一站

胜利必须在敌军最后致命攻击**视觉完成以后**开始。
- 先处理战斗队列里仍需要结算的规则事件；
- 敌军阵亡 Ghost 退场，最后一个敌人的纸片碎屑自然消失；
- 战场变安静 150–300ms，玩家知道战斗结束；
- 纸牌/雪晶轻量奖章进入，不是空白结果屏替换；
- 获得金币从敌军位置或奖励盒子飞向金币库存，按真正变更值 tween；
- 显示战果与奖励卡，奖励依次升起 50–100ms 错峰；
- 玩家检查奖励、确认领取，奖励牌沿抛物线归入队伍/牌堆；
- 返回地图时小地图聚焦刚结束的节点，下一可选路径正确出现；
- 快进演出不能造成重复金币/重复加入道具。

注意之前源码 resolveBattle 中“战斗结束自动恢复大量生命”是为原型平衡加的规则，不能未经用户确认悄悄保持为新游戏最终规则。需统一游戏规则文档，明确哪类战斗有回血、回血动画在什么事件中发生、是自动还是由道具/奖励提供。

# 13. 商店全交易系统：查看、确认、付款、出货、售罄、退出

**最优先修复的 UX bug 之一：当前点击商品就执行 buy(index) 并扣钱。**

商店必须是一张真正场景：程序化木制柜台/货架、商品占位锚点、店员区、货币数值、牌组入口和离开按钮。美术资源现在允许临时图，禁止等待 Anima 才做。

店主至少有 idle / greeting / inspecting / sold / insufficient / farewell 六种语义状态。没有新的店主原画时只做牌体/位置/小姿态变化，不假装已有新动作图。

### 进入商店（建议 350–650ms）

- 地图节点转场，商店柜台先出现；
- 商品卡沿陈列锚点 50–80ms 错峰落位；
- 店主轻点头/抬牌，商品均可查看；
- 金币与背包始终可见。

### 第一次点击只查看（100–250ms）

点商品只让其抬起、放大并展示详情、价格、效果、玩家金币与购买前后预览。
关闭详情不会扣钱。打开详情可以看已售罄商品的原因，但购买按钮禁用。手机不允许误触查看就付款。

### 确认购买（建议总 600–900ms）

| 时间 | 动作 | 真实状态 |
|---:|---|---|
| 0–60ms | 购买按钮轻压缩 | InputAcknowledged |
| 60–130ms | 冻结唯一交易 txId、检查商品/余额 | PurchaseValidated |
| 130–300ms | 商品卡离开货架并旋转飞向背包 | CardTakenFromShelf |
| 270–480ms | 金币图案飞向收银区，金币数字 tween | GoldDebited |
| 350–570ms | 商品缩小归入牌组，牌堆小回弹 | ItemAdded |
| 470–700ms | 店主感谢动作/音效，货架出现售罄 | ProductSold |
| 700–900ms | 解除输入锁，允许下一次购买 | ShopReady |

购买在规则上一次性原子提交，不是音效播放过程中分多次改金币。购买动画只是呈现这笔已经被唯一 txId 确认的变更。中途刷新必须恢复正确库存、正确金币、正确牌组，不能重复结算。

余额不足时：
- 抖动金币徽章 2–3px，店主摇头或短提示 200–350ms；
- 商品保持原位；购买金额 0，入库 0，日志说明差多少；
- 不允许自动弹浏览器 alert 破坏游戏场景。

已经售罄：
- 能查看完整详情，但不能购买；
- 商品处保留售罄标签或空挂钩，不能删掉后一整排布局突然左右跳动。

取消：
- 返回、ESC、点击场景空处都应该关闭详情；
- 不扣钱、不消耗商品、不改变库存。

一系列连续购买：
- 同一商品双击、两指快速触摸、同时“买”和“离开”、刷新、跨场景回访，都不会重复扣款；
- 交易与存档有账本/唯一 ID；
- 交易历史可重放做自动测试。

商店除商品卡外，护符、稀有品、皇冠/扩展物品都应有对应槽位/售卖规则；保留自家世界观，不复制 Wildfrost 商品名称和店主美术。

# 14. 招募、宝箱、护符、工坊、篝火与路途中事件

### 冰冻旅人招募（建议 900–1500ms）

三位候选的身份、能力与阵营在战场外的事件场景中清晰可读。点选只是预览，确认后才领取。
确认后：冰晶局部裂开（150–330ms）→ 冰屑掉落（330–600ms）→ 伙伴卡亮出（600–900ms）→ 牌飞向队伍区（900–1200ms）→ 角色加入队伍状态稳定。
不可跳过的招募不应显示误导性“离开”按钮。重复点击不产生两个同伴，存档恢复后不能再次选择已领的奖励。

### 宝箱（建议 600–1100ms）

开箱先有卡扣/盖子 120–250ms 变化，再有暖光/粒子 250–450ms，奖励三张卡 450–780ms 错峰升起。首次点击不领取；确认后卡牌移动到牌组，关箱收尾 150ms。允许跳过开箱视觉，但不能重复取奖励。

### 护符

附着护符要有从库存到目标角色卡的清晰运动，护符落定有小叮声、短轻弹及数值变化对照。不能将“全局获得一枚护符”伪装成“已给任意卡装上”。若规则目前只支持领队强化，则 UI 必须如实说明。

### 工坊

显示升级前卡与升级后预览，同时摆在台面上；点确认后轻敲木台/金属，卡翻转后显示新数值。无升级资格的卡显示原因；原卡不因动画中断而丢失。

### 营地

火光轻变化、冷雪与暖光对比。恢复生命/搜寻物资互斥且有成本；治疗数字按动画抵达更新，不瞬间切换。已完成节点不能重复消费和奖励。

### 遗物、事件、额外商贩

同一事件基类管理 offer、confirm、reward、leave，但每个场景必须拥有区分性镜头和锚点，不可复用一个“淡青底+三张卡+离开”的万能模板当全部场景。

# 15. 整局失败、结果审理、结局与重开

必须分清：
- BattleVictory：单场获胜→奖励→返回路线；
- RunDefeat：领队阵亡或符合本作失败规则→战场失败镜头→失败审理/统计；
- RunVictory：完成三地区→最终首领死亡→完整胜利镜头→整局成绩。

结果页按真实权威日志给出：
- 胜利/失败、原因、最后致死攻击者和最后一次护盾/扣血；
- 击杀数、战斗场数、出牌数、累计伤害、回合数、金币赚取/消费；
- 获得或损失同伴、护符、牌组最终张数；
- 重要节点、当前地区、历史记录与解锁；
- 失败不能像胜利一样给出不存在的金币奖励；
- 重开必须清理旧场景动画、计时器、粒子、音频订阅与指针捕获；
- 返回营地的动画与继续旅程数据逻辑分开，任何按钮只触发一次事务。

失败镜头要有安静的收尾，不是直接黑屏，也不是无关的华丽颁奖。胜利镜头清晰、有温度、简洁，不要彩虹特效冲掉卡牌主题。

# 16. 音效系统、材料触感与可替换音画资源

**音效不是最后有空才加的装饰**。参考 Wildfrost 音效设计师公开的真实纸牌拟音工作方式：洗牌、摸牌、落牌、铃铛、冰晶碎裂、木头质感和轻微玩具音，使所有卡牌对象在操作中有重量。不可直接复制 Wildfrost 的音频或音乐文件。

AudioCue 至少定义以下事件：
MENU_HOVER, MENU_PRESS, PAPER_PICK, PAPER_DRAG, PAPER_LAND, DECK_SHUFFLE, DRAW_ONE, DRAW_BATCH, BELL_READY, BELL_REDRAW, WAVE_WARNING, ENEMY_ENTER, ALLY_ENTER, MOVE_SWAP, CARD_RETURN, ATTACK_WINDUP, ATTACK_MELEE, ATTACK_GUN, HIT_LIGHT, HIT_HEAVY, CRITICAL, SHIELD_BLOCK, SHIELD_BREAK, FREEZE_APPLY, FREEZE_SHATTER, HEAL, POISON_TICK, SUMMON, UNIT_DEATH, BOSS_ENTER, BOSS_PHASE, GOLD_EARN, SHOP_INSPECT, SHOP_PURCHASE, SHOP_INSUFFICIENT, CHEST_OPEN, CHARM_ATTACH, VICTORY, DEFEAT, SCENE_WIND_TRANSITION。

每个音效资产由 SoundDirector 统一管理：触发 ID、文件 manifest、音量、音调随机变化区间、最大同类重叠数量、混音优先级、音效延迟补偿。关键命中声应锚定实际 AttackHit 帧，不是用户点击时立即播放。

暂缺正式声音时允许先用**自有简单拟音**测试结构，且必须标记待升级，不得把一个单频电子嘟声当正式音效。用户手势尚未授权 WebAudio 时无声降级，不抛异常。不准让连续攻击 15 个同类声音同时最大音量播放导致失真。

音画同步初始目标：命中声与命中画面误差 p95 不超过 50ms（须通过录屏/录音实际计算），样本帧率和 WebAudio 输出缓冲不同要记录。移动端可选择关闭音效、只保留关键提示，支持 Reduced Motion。

触觉反馈仅在浏览器/系统支持且用户明确打开时启用，关键确认可轻震 10–25ms，不能每次鼠标滑过触发。

# 17. VFX、镜头与图层：动效要有主次、不能堆满屏

清晰的渲染层顺序：
1. 场景背景（远山、林木、天气）；
2. 地面/战场接地阴影；
3. 空阵位轻标记与合法目标；
4. 牌后特效（召唤、治疗光环）；
5. 角色卡与手牌；
6. 牌前特效（枪击轨迹、斩击、冰霜、冲击波、纸屑）；
7. DamageFloat 数字和状态徽章；
8. HUD（币、钟、返回、牌组）；
9. 卡牌详情/商店确认/结算；
10. 拖拽最上层，但不得盖住 modal 的确认按钮；
11. 系统级危险操作确认。

**严禁整个游戏每层都用 z-index:9999**。每层具体统一的 z-index 取值，并为 DOM/Canvas 的坐标变换提供转换函数。

FXManager 负责：对象池、生命周期、粒子物理、可重复随机种子、停顿/速度、遮挡、场景退出回收。桌面同时建议最多 100–140 个简单粒子，手机 35–65，实际以目标硬件 FPS 再调。绝不对全屏 1920×1080 常驻使用昂贵 blur 滤镜。

雪粒永远是背景层级；攻击粒子只有在命中帧出现，不能整场不停喷洒。特效图像即使临时几何也应有准确的施法源、弹道方向、目标卡坐标、消散方向与范围。

相机摇晃建议：
- 普通命中 0–2px；
- 破盾 1–3px；
- 重击 3–5px；
- Boss 阶段事件可瞬间 5–7px，但自动收敛；
- 多次攻击抖动应限幅，不能越来越偏；
- 降低动态效果只保留 0–1px 或完全取消摇晃，用卡框/数值来替代。

镜头不得自由旋转/夸张 3D 透视。保持正面 2D 卡牌战场，不让图像失真；有深度的感受来自纸张厚度、光影、运动和声音。

# 18. 手机、平板、电脑端交互细节

统一 9 组视口：
1920×1080、1366×768、844×390、390×844、1024×768、360×740、430×932、1280×720、2560×1440。

**移动端不能直接把整套桌面 UI 缩小**。游戏允许横屏左右两军并列，竖屏把同一条战线的我方三格和敌方三格分段展示，但逻辑 ID、前排与攻击判定不变化。长按卡放大后要能稳定阅读。

触摸操作至少处理：
- pointerId 与 setPointerCapture；
- 触摸离开窗口、pointercancel、页面滚动与双指操作；
- 拖动阈值推荐 8–14px；
- 长按 350–550ms 与移动检测协调，不能拖动被误判为详情；
- 释放无效目标时回弹，不消耗牌；
- 浏览器安全区、底部 Home Indicator、工具条高度变化；
- 重要 hit target ≥44×44 CSS px，可用透明命中区域扩张，但卡牌显示不一定等宽；
- 5 张起始手牌全部能选择，牌重叠时上层选择策略明确；
- 手指覆盖目标时有轻微指向线/目标发光，不能看不见要放的位置。

桌面端需要键盘：
ESC=关闭详情/取消拖动，1–7=手牌预选，R=重抽（如本作规则），Tab=焦点遍历，Enter/Space=确认，动画正常播放时空格可跳至安全检查点。游戏手柄可作为增强，不应在没有接入时宣称支持。

1440P/4K 不能无止境放大角色卡并破坏布局，应使用版心最大宽和背景呼吸空间；同屏 12 张牌、手牌、钟、HUD 均保持可读且不拥挤。

### 自动化覆盖场景

要按真实交互执行，不允许跳过按钮使用 engine 内部快捷方法伪装“真实流程全部通过”：

A. 菜单开局→选领队→进地图→战斗登场→第一张手牌；
B. 连续拖 5 张牌的合法/非法目标；
C. 伙伴跨上/下排移动，再攻击，目标和动画正确；
D. 计时归零、敌方/友方自动攻击和状态分层；
E. 免费重抽/消耗回合重抽，牌数和视觉位置都正确；
F. 触发冰冻、治疗、破盾、暴击、范围攻击；
G. 使敌方普通单位死亡，验证死亡 Ghost 和卡位释放；
H. 召唤新单位以及援军钟触发，确认不会占两个相同格；
I. 领队阵亡，完整败北过场到真正结算；
J. 击杀首领，战后奖励→地图，金币/道具一次性记录；
K. 商店查看→取消不扣币→确认购买→售罄→离开；
L. 金币不足/连续双击/买卖期间刷新，账本不错误；
M. 冰冻旅人/宝箱/护符/工坊/篝火流程；
N. 三区走到最终结算、回村和重新开局；
O. 12 张卡满场、7 张手牌、狭长视口、多指拖动与旋转屏幕；
P. 1倍速/2倍速/Reduced Motion 同 seed 的最终状态一致。

### 逐帧采样要求

每个关键 animation clip 截取：
起始帧、25%、50%、命中/数值更新、75%、末帧，至少 6 张，保留毫秒戳。特殊死亡、商店交易、卡牌滑动还应录完整视频。可运行 trace 记录 requestAnimationFrame 与实际 frame presentation，不用纯超时等待冒充录屏证据。

归一化视觉指标：卡牌中心坐标、尺寸、旋转角、透明度、文本 bbox、卡牌堆叠顺序、状态徽章是否遮脸、移动路径与目标中心、道具从商店货架到库存的轨迹。对自己的上一轮已批准截图可做图像差异/SSIM；对 Wildfrost 的参考图比较**布局和交互表现特征**，不做受版权保护画作的 RGB 逐像素相等判定。

对动画设定用约束而非只有截图像素：攻击轨迹必须起于正确 actor、终止于正确 target；伤害数字不得早于命中；死亡释放不得早于 FatalHit；商店扣款不得早于确认；援军入场不得超出合法 SlotAnchor；重复输入事务只能执行一次。

# 21. 状态空间穷举与特殊情况下的行为

必须建立自动生成用例库而非手工只挑简单例子：

- 手牌 0、1、5、7 张，重抽充满/未充满，牌库空，弃牌堆回洗；
- 对空槽、友军、敌军、被冰冻目标、死亡目标、护盾目标施放；
- 多张同名卡同时在场，使用 UID 而非 name 计算；
- 多次连击使同一敌人死亡，后续攻击是否重定向或停止遵循固定规则；
- 同一回合双方同归于尽，胜负优先级明确；
- 护盾恰好挡尽、部分挡住、毒伤绕过护盾等是否有对应视觉；
- 冻结到期与攻击倒计时同时归零；
- 连击引发反击、毒、治疗、召唤的嵌套事件，设置事件递归深度上限；
- 援军触发时所有格满、首领阶段已经结束、地图变更中出现延迟演出；
- 同伴回收时敌方攻击已宣告、但命中尚未发生；
- 点击商店商品、双击、长按、同时点击购买/离开、余额刚好/不足、刷新恢复；
- 失败期间操作其他牌、重开过程中有尚未完成的粒子/音效；
- 画面从竖屏旋转到横屏时正有一张手牌在拖动；
- 标签页切后台 60秒后回来，不能一次性无规则地补播整场动画；
- 快速模式、低帧率、不同随机种子/设备尺寸不改变最终游戏状态。

对每个边界输出：input_event_sequence、before_state、expected_rules_after_state、expected_animation_order、observed_after_state、pass_or_fail、trace_link。

# 23. 拒绝验收的具体条件

只要发生其中任意一项就不能标记“完成”：

- 开局没有真正进场与发牌，只直接渲染阵容；
- 攻击起手后牌突然瞬移，打击轨迹断开；
- 伤害数字早于击中，敌人挨打与扣 HP 不同步；
- 敌人死亡从数组删除后直接消失，没有死亡过场；
- 我方领队死亡直接展示结算屏而无致死/失败导演；
- 召唤就是 push 一张新卡，援军没有钟预告/落位；
- 技能只有数值变动，没有独特可读反馈；
- 免费重抽与耗回合重抽只有不同文字、无连续手牌运动；
