# 高速出币：厚重金币、撞击手感和 500 枚性能修复（2026-11-18）

> 用户反馈：金币“轻飘飘的不像金币”“巨卡”“感觉很薄”。本轮优先修实际物理和帧开销，不再继续盲目提高 Bloom。

## 原始症结
- 原始模型直径 `3×.135≈.405`、厚度 `.10×.135=.0135`，只有直径 **3.3%**，像纸片。
- 发射初速度偏大、随机旋转高达 50+/s，重力仅 24，恢复系数 .17/.30，薄币像纸片乱弹。
- 精确 `CANNON.Cylinder(10)` 互撞采用逐个凸体 SAT。旧版最多 500 枚、120Hz 和 **24 solver iterations**，集中落在盆里时大量持续相互碰撞，CPU 被物理瓶颈吃光；每帧 PBR+HDR 双尺度 Bloom 与全实时 shadow map 又增加 GPU 负载。

## 已提交的游戏修复
1. **一处共享实体尺寸**：`motion/coin-payout-shared.mjs`。游戏绘制10边 `THREE.CylinderGeometry` 与精确物理参考均复用 `COIN.visualThickness=.31`、`COIN.scale=.135`，厚度 `.04185`，相当于直径约 **10.3%**（按模型直径 .405），不再是 3.3% 的纸片。真实半径是 `.212921`，有轻微 10 边多边形外接尺寸修正。
2. **下落更扎实**：共享重力 38；发射向盆内斜下方、速度更集中，随机角速度下降约一半，接触弹性改成低弹，地面摩擦与旋转阻尼提高。仍然保持**出币口 → 实体接币盆**，不会喷到屏幕外。
3. **大量金币专用 fast solver**：`motion/coin-payout-fast.mjs`，浏览器默认使用 `FastCoinPayout`。每枚金币仍有独立 XYZ 坐标、速度、四元数、自旋、解析式盆壁和盆底接触、金币之间的高度/横向冲量和密集堆叠；用 X/Z 空间哈希只检查附近币，不做大规模昂贵的凸体 SAT。**这是适用于游戏的薄圆盘近似刚体，不是物理精度与 cannon-es 完全等价的解算器**。
4. **保留精确参考**：`motion/coin-payout-rigid.mjs` 与内置 `vendor/cannon-es.js` 不删除；少量金币对照继续使用真 10 边凸体 Cylinder。精确模式迭代已从 24 降到 9/8/6，摩擦/恢复系数和厚度与游戏共享。大批量正式游戏不会加载 346 KB 精确 cannon-es 代码。
5. **GPU 减负且保留质感**：`motion/coin-payout-view.mjs` 默认低负载 `performanceProfile=smooth`；减少 WebGL 渲染像素比、关闭多余 MSAA、桌面约55Hz和手机约42Hz显示上限、阴影更新周期手机约175ms/桌面约125ms，仍保留真实 ShadowMap。可切换高画质。后处理 `motion/coin-payout-lighting.mjs` 低分辨率双尺度 HDR Bloom；柔和的宽光晕每3帧更新一次，锐利高光逐帧响应。Bloom 关闭时跳过不需要的多次 GPU 全屏模糊。
6. **原有美术不删**：仍然使用 48×48 SVG 像素金币图、10 边低模、PBR 旧漆机身、金属面板、金色像素金属度贴图、冷暖光照和辉光。

## 已实测的计算结果（不可混淆为浏览器 FPS）
- 使用 GitHub 上实时提交的快速物理源码，V8 中 120/240/420 枚都完全出币，`escapedEver=0`，并产生数万至数十万次薄圆盘接触事件。
- 本地 Node 直接运行 420 枚、730 个物理步累计物理计算约 0.4–0.5 秒（不同平台差异很大，不是“730帧的浏览器渲染耗时”）。
- 使用 GitHub 最新快速物理源码，V8 连续 120+380 枚，总数 500，`escapedEver=0, inBasin=500`，且仍有独立 XYZ 朝向与速度。
- 较早 Cannon 凸体测试 80 枚连续落币时 20 个时间步曾需数秒，性能瓶颈真实存在。不同机器上的时间不可直接当成用户设备性能基准。

## 待办与风险
- **最新 GitHub Pages 的真实 WebGL 画面和手机 FPS 仍未确认**：不要宣称已经通过图像比对或实现 60FPS。先检查 GitHub Actions 完整 QA 和 PNG/WebM，再改善机器模型、质感和堆币画面。
- fast solver 的薄圆盘模型采用近似的竖向/水平碰撞冲量，不能用于科学/工程级严谨碰撞；强碰撞可唤醒睡眠硬币，但与 10 面真实凸体求解不完全一致。
- 更新设计时切忌重新启用 500 Cannon 精确圆柱 SAT 的默认场景；性能将急剧下降。
