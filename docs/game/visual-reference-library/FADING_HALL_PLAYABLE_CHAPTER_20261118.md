# 褪色的会客厅：第一章游戏化记录（2026-11-18）

> 状态：真实 Three.js 场景上的**可玩首章原型**。这不是《极乐迪斯科》或其他游戏的源码/关卡。下一步以本文件、实机截图与 GitHub QA 为起点继续完善。

## 制作目的

旧版本 `anima-paintover-lab.html` 只有白膜、材质权重、镜头旋转，属于开发者调试器，不能称为游戏。按用户要求，**直接从托管主菜单进入可以操作的古堡房间**，由真实 3D 空间承载 Anima 人物与绘画材质；开发工具改为可通过 `?dev=1` 单独查看。

## 这一版实际完成

- **游戏 UI**：游戏画面占整个设备视口；顶部只有章节、目标和线索状态；人物附近显示与世界坐标同步投影的互动标记。调查文字使用小型剧情对话框，不再占据半屏素材控制区。
- **3D 行走**：点画面地面 → Raycaster 与 y=0.12 的世界地面相交 → 限制在已有场景走廊/地面合法区域 → 栅格 A* 避开桌子、石柱和墙 → 角色根节点 `actorSlot` 沿路径移动，脚底随台阶高度调整，`groundShadow` 同步移动。
- **人物资源**：角色仍为仓库已有 `02-blood-physician.png` Anima 原图；新增世界中的同伴使用原有 `03-trap-engineer.png`，图片按真实纵横比应用在世界空间的垂直平面，不重新生成角色。
- **简单调查任务**：调查桌上手札、查看彩窗，找到 2 条线索。先去门口会提示需要线索；两条都找到后门开启。
- **空间连接**：第一个房间与独立绘制的 `playable-castle-corridor`（地板、实际 3D 墙和拱、柱、灯、前后门、钟铃、封印门）按空间转场切换，人物与脚下影子真实 reparent 到另一个场景 group，而不是把一张走廊背景切成 PPT。
- **长廊故事节点**：调查钟铃得到线索，检查尽头的封印门可看到下一片区域尚未开放的提示；可以从长廊返回会客厅。
- **触摸分工**：手机单指轻点为移动，双指捏合仍可改镜头距离；鼠标轻点移动。调试旋转、白膜及权重控制仅在 `?dev=1` 开发模式保留，避免把技术参数当玩家按钮。
- **状态记录**：手札和彩窗线索保存在浏览器本地 `localStorage["paperchalk.chapter1.fading-hall.v1"]`；刷新后从会客厅重新出现，但已取得的线索保留。

## 本次关卡物理规则

- 会客厅导航基本范围：x ∈ [-6.5,6.5], z ∈ [-5.18,4.05]，障碍包括书桌 `x -2.40..0.95, z -4.6..-2.94`，另有主要石柱与近景障碍。
- 真实场景背景 y≈0，后部抬高舞台 z < -2.85 的区域人物脚底 y≈0.39；不是让角色飘在地面外。
- 脚下 shadow sprite 和 3D 相机共享位置数据；角色实际只有 2D Anima 全身立绘，需要未来生成真正的移动帧/方向稿，当前直接平移属于**玩法验证级**。
- A* 网格边长 .36；斜向移动必须检验两侧相邻方格都可走，防止贴墙切角。
- 互动标记是 worldspace 3D 坐标投影到 HUD 的屏幕按钮，内部位置在世界坐标中；互动前角色自动走向可达站位，然后执行对应剧情。
- 门口必须读完桌面和彩窗信息才能过关；成功触发淡出→真实 3D 长廊→淡入；来回切换不刷新浏览器。

## 验收与限制

- 测试要求实际在浏览器点击**Canvas 地面**后人物坐标变化；通过游戏里可见的按钮分别调查桌面和彩窗；开门确实进入另一组真实几何；检查钟铃，返回并保留线索。
- 需要分别保存桌面 1440×900、手机 390×844、横屏 844×390 的实机 PNG 和浏览器 WebM，不能生成图片冒充截图。
- 现阶段环境纹理**仍是程序占位层**，未来需要接入 HALL-01 ~ HALL-18 的真实 Anima 单元素资源；参考 `ANIMA_ENVIRONMENT_PROMPTS_LIBRARY.md`。
- 角色目前为移动中的 2D 全身纸片，不是完整八方向走路序列；过场门扇和长廊已经有真实几何，但需要逐帧润色。
- **当前验收状态必须以最新工作流结果为准**。仅源码提交不是最终视觉品质/性能验收。WebGL 软件仿真帧数低不等于真机帧数；不宣称已达 60 FPS。
- 不允许为了做游戏交互把手绘素材更换成合成的整张房间图，也不允许删除已有 Anima 原图或放大导致拉伸。

## 截图复盘：新长廊的剖面式 3D 构图修正（2026-11-18）

第一轮 GitHub Actions `44136658565` 代码/实机流程已通过，证明会客厅→手札→彩窗→开门→走廊→钟铃→回到会客厅在桌面及手机都能实际交互。但检查其 `05-real-3d-corridor-after-opening-door.png` 时发现：长廊 camera 处于 +X/+Z 外侧，而原始 3D 模型同时建了 +X 右侧完整墙、+Z 入口整面墙。结果画面主要是两面墙外立面，人物、地面与走廊物件全被实体遮挡。**浏览器流程通过不等于画面合格。**

修正源码：`site/card-battle/engine/anima-hall-gameplay.js` 的 `createFadingHallGame` 里 corridor 几何：
- 保留 `-X` 远侧长墙和 `-Z` 尽头墙的真实厚度、纹理和深度；
- `+X` 近侧墙改为低石墙/门槛，不遮挡角色；
- `+Z` 摄像机入口近墙改为小石台门槛并保留左右门柱、顶部拱；
- 去掉横挡全走廊的实体入口门板，因会客厅门已在上一场景进行开门动画；
- 增加暖色中景点光，让角色站位与石材受光明确；
- 仍为**真实 3D 几何**和真实遮挡，不用一张 2D 绘图替换整片走廊；
- 修改后必须再次检查三个尺寸的长廊截图，并逐帧复核角色能走进视觉上真正可读的路面。

`44136658565` 证明流程功能，**修正后的视觉验收**以新一轮 Actions 的实际截图为准。
