# 雪境行旅：每次改动必须有原版 ↔ 实机动态证据

**生效规则（2026-11-17）**：每次修改 `site/card-battle/**` 中的场景、布局、角色、材质、卡牌、动画、数值显示、攻击、召唤、死亡、购物等表现代码，都运行对应 GitHub Actions。**仅“看起来差不多”、仅静态截图或仅代码计时均不算通过。**

## 自动执行

- [完整游戏回归及参考对比](../../.github/workflows/snowbound-journey-qa.yml)：桌面与手机的真实交互，七种 viewport 的尺寸检查；真实录像、截图、官方 GIF / 视频时间轴。
- [独立动态对比工作流](../../.github/workflows/snowbound-side-by-side-qa.yml)：修改比较程序时必须重新录制并核对；任何比较失败都应让对应 job 标记为失败。
- [真实浏览器点击并录像](../../tests/snowbound-motion-side-by-side-browser.mjs)：实际进入关卡，**玩家点击换牌**；攻击由同一游戏的真实战场及动画导演实例演示（这种孤立攻击测试不是另一次真实鼠标攻击，必须明确披露）。
- [原版逐帧比对器](../../tests/snowbound-motion-side-by-side-audit.py)：下载并解析出版社原始 GIF 35 帧、《Slots & Daggers》视频 60fps 原片中 16 帧；针对每一个源画格记录实际游戏最接近的已录画格、误差与亮度变化。分镜图和展示 GIF 只使用少量原版低清画格，不重新分发完整原片。
- [真实 WebM 校准](../../tests/snowbound_motion_video_alignment.py)：如果桌面端截图通道因性能原因无法捕获短促攻击，则通过玩家实际点击的换牌动作将原始 25fps WebM 与浏览器绝对时间对齐，再提取攻击对应的 **真实录像画格**，不插值、也不凭空造帧。

## 每次必须保留的验收资料

1. **官方参考来源**：游戏名、制作方/发行方、原始 URL、素材 SHA256、原片 fps、选中片段起止秒数；严禁把预告剪辑当游戏操作时延。
2. **真实游戏截图**：PC 战斗画面和手机竖屏画面；出现失败也保留。
3. **操作全过程视频**：Chromium WebM，含真实点击、换牌、攻击、命中和恢复。
4. **并排比较图**：左侧官方参考，右侧当前提交构建的实机截图；至少覆盖 F00、前摇、过渡、爆发、恢复、结束关键时间点。
5. **并排比较 GIF**：按照参考时长播放的诊断性 GIF；不能将八张诊断画面说成原生 60fps 录制。
6. **全帧数字报告**：35 帧的 Balatro 原始 GIF，以及 16 帧的 Slots 原始攻击片段，列出同一秒数附近的实机画格、帧重复与录制采样率；不能用同一张实机截图冒充多个真实采样帧。
7. **实测时间**：浏览器 WAAPI 合成器 delay/duration + `performance.now()` 的 1×、2× 时间轴；时序匹配和视觉匹配分别记录。

## 发现问题后的处理

- **未通过**：标明 FAIL，附 GitHub Actions 运行编号、具体阶段、原版帧／实机帧；继续修改后重新运行。
- **采样不足**：说明真实浏览器录制 fps、丢失帧和重复映射；使用有校准的真实 WebM，而不是捏造中间帧。采样率低不能声称原版像素级还原。
- **视觉差距**：指出具体对象（手牌退出／入场、弹性、翻面、枪口爆闪、画面震动、音效等）在什么时间不一致，不以“总时长一致”代表完成。
- **通过**：必须有可下载的 `artifacts/snowbound-motion-side-by-side/` 录像、并排截图、GIF、audit.json；且全流程回归无阻断。
- **著作权**：仅利用参考游戏片段研究时间关系与交互原理，不把第三方游戏立绘、整段音视频或卡牌图片用于我们游戏。

## 当前仍需提升的表现

对照 2026-11-17 的真实手牌比较截图，《小丑牌》新牌约 F13 开始进场，F34 已经完成翻面；我们出现过中途长时间空手牌和翻面结束不完整。属于**视觉未达标**，即使基准 2800ms 播放时钟已经测准，也不能宣布整体还原完成。

**以后每次汇报的最低格式**：GitHub commit → 通过/失败的 Actions run → PC 实机截图 → 手机实机截图 → 原版 ↔ 实机逐帧对比图/GIF → WebM 录像 → 已发现的差距与下一步修复。任何缺项都要明确写“尚未完成”，不能假装已验证。
