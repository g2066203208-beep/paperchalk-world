# 城际总图 / 城市独立交通图 — 地图分层规范 V21

2026-11-08 用户确定：**所有城市内部的地铁绝不能混在一张总图**。之前的“整个世界点阵网格按缩放自动叠加地铁”设计错误，已废弃。

## 唯一正确的两级 UI

**一级「城际交通总图」**：游戏地图默认进入这里。画出十座城市门户及跨市真实交通（区域铁路、城际大巴、高速公路、渡轮）。此层绝对禁止渲染任何城市内部的地铁、城市公交、电车、内部接驳路、任何城市具体地点照片。缩放和拖动不会自动进入城市，更不会让内部线路突然显现。城市图文门户可以点击。

**二级「X 市 · 市内交通」**：点击某座城市的图文门户，直接进入该城市独立交通图。只显示所选 `cityId` 下的本地地铁（若该城实际拥有线路）、市内公交／电车、接驳路和该城市地点／站点照片。其他九座城市的内部线路、地点、图钉及城际总图路线全部不显示。图上的地点图钉仍需连在真实本地交通路线上，图片不得裁掉头尾、边缘要做避让。

**固定返回按钮**：「← 城际地图」，只能显式返回；`全域` 按钮只调整当前层的视野，不能跨层；`定位` 可以进入玩家当前所在城市，`Escape` 在没有弹窗时返回城际层。

### 数据与性能

- 同一份 `world-atlas.js` 和 `destination-network.js` 原始实名地点、真实站点位置、双向路线服务继续复用。仅地图**呈现层**分开；避免复制 10 份图数据库、避免生成假的编号地铁站。
- 可见层由 `activeCity===null`（城际）或实际城市 ID（市内）决定，**绝不可再用 zoom 阈值推断层级**。
- `site/game/transit-map-ui.js` 位置更新时应对 `regional` / `municipal` / `access` / `urban` / `stops` / `cityCards` / `POIs` 做显式过滤，同时 `site/game/transit-map-ui.css` 使用 `data-scope` 作双重防串层校验。
- 城市内部有真实地铁时才渲染地铁；只有巴士服务的城镇就画巴士，不要臆造地铁。
- 城市门户卡片在一级，所选市内照片卡片在二级；照片按需加载，靠站点图钉固定。保持无大地图背景，只展示线路规划。
- 游戏实际旅行时间与去回路线仍由双向交通图计算，不要改成瞬移。

### 实机验收

`tests/world-map-browser.mjs` 在真实 Chromium 内至少验证：城际总图 10 城图文门户、无任何内部线路；放大总图也不出现市内线；进入霧浜能看到其运营中的完整地铁；进入穗森只显示其本地巴士；进入汐凪只显示其本地地铁／港湾路线；所有十城逐一切换时不混入其他城市的内部线和 POI；返回按钮／城市内全域／手机端仍然正确。实机截图保留原分辨率。

> 任何后续工作不得再把十城内部地铁叠回城际图，也不得通过缩放自动切换城际与市内层。这是明确用户决策。
