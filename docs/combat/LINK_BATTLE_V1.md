# 卡牌连携战斗 V1｜已实现系统规范

## 测试入口

- 游戏主菜单 → **卡牌战斗**。
- 游戏内菜单 → **卡牌战斗**。
- 直达：`https://g2066203208-beep.github.io/paperchalk-world/?combat=1`。
- 可重复的测试牌序：附加 `&combatSeed=42`。正常开局和再战会重新洗牌。

## 核心战斗循环

- 当前测试阵容 **2 名我方（女主、女二）对 3 名敌人（无正式人物设定的战斗替身）**。不擅自创建新的正史角色。
- 玩家回合：4 能量，抽 5 张，逐张出牌并点目标；回合结束弃掉剩余手牌，执行敌方公布的意图。
- 卡牌属于特定队员。倒下队员的卡不允许继续行动；伤害、护盾、标记、易伤、回复都有统一规则。
- 每名存活队员在己方回合初获得 **1 次连携响应**，上限 2 次；部分战术卡能恢复响应。
- **主攻→队友响应：** 主动攻击后，所有仍有响应次数的同队存活成员，按队伍顺序依次发动独立的援击。每名成员扣除 1 次响应；援击不再递归触发援击，避免无限链。目标已经倒下时停止连携。
- **敌方完全一样：** 敌人主攻、后续同伙援击、护盾/标记加成与次数限制均调用相同的 `attack()`、`reactionChain()`、`damage()`。不可把敌方连击写成没有计算的演出。
- 标记对援击伤害 +3，易伤增加受击伤害；目标的护盾先抵挡，剩余才进入生命计算。
- 敌人在玩家回合开始已显示本回合的攻击/标记/防御意图与预计目标，人数发生变化时 UI 更新是否还能连携。
- 胜利或全灭显示回合数和双方累计连携次数。整个战斗是独立练习，不会擅自修改原游戏的生命、饥饿、理智或剧情存档。

## 视觉与人物源

- `site/game/combat-ui.js` 只读取两个原有 L2D 渲染槽的实时 Canvas；开战时暂时载入女主正面及女二正面，退出后恢复原有绑定与显示状态。
- 调用 `PaperchalkCharacterDev.assign(slot,id,'front',false)`，**不写回任何存档**，不修改女二的 PSD 分层、独立纹理、网格、骨骼与待机设置。
- 攻击顺序依照引擎事件逐个播放：主攻、第一位响应者、第二位响应者……显示对应来源/目标与真实伤害。
- 暂无专用敌人 L2D 素材，敌方显示中性的几何敌人标识，不能冒充完整人物动画。

## 架构与测试

- 纯确定性数值逻辑：`site/game/combat-engine.js`，支持注入自定义双方小队和固定随机种子。
- 可操作 UI：`site/game/combat-ui.js`；风格与响应式布局：`site/game/combat.css`。
- Node 规则与 40 场完整对战回归：`tests/test_card_combat.js`。
- GitHub Actions Playwright 截图/验收：`tests/test_card_combat_browser.js`。
- 引擎支持多个队员响应，包含三名我方队员顺序追加的自动测试；目前正式可见 L2D 阵容仍只有两个已有的人物，后续增加已验收角色后再扩充 UI 人数，不以重复原画冒充第三人。
