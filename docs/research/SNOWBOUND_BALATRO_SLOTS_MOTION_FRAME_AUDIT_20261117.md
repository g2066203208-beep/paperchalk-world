## Slots & Daggers：真正 60fps 连续攻击帧（Game explainer）

来源时间 10.380–10.630s，16 个连续画格，每帧约 16.667ms。

| 源画格 | 时间 | 观察 |
| --- | --- | --- |
| F00–F03 | 10.380–10.430s | 机器显示框上缘灯逐颗增强，敌人的剪影基本还站在原地 |
| F04–F05 | 10.447–10.463s | 灯沿边缘形成明确光带，视觉即将转向屏幕中部 |
| F06–F07 | 10.480–10.497s | 金黄色强烈突闪，斜向剑光进入机器显示框；是明显的**亮度峰值** |
| F08–F10 | 10.513–10.547s | 主剑光斜线保持并向右下移动，亮色拖尾溢出屏幕区域 |
| F11–F15 | 10.563–10.630s | 强闪回落，剑光形体移至屏幕右下，动作由主体攻击转换成后续外部视觉反馈 |

不是“每帧把全部元素一起亮”。**事件触发被分解为不同空间层：边框提示 → 实际武器 → 光学扩散 → 收尾**。具体发声毫秒需另用音轨包络对齐，当前画帧无法证明声源时刻。

## Slots & Daggers：另一个 60fps 攻击段（Reveal）

21.880–22.130s 的 16 个连续画格：

- F00–F03（21.880–21.930s）：轮廓、敌人、功能 UI 保持稳定，边缘只有低强度灯光变化。
- F04–F09（21.947–22.030s）：上边框灯光逐渐串亮并形成预告，主体未立即强烈晃动。
- F10–F13（22.047–22.097s）：主剑光和爆闪出现，视觉最高强度集中在屏幕右半。
- F14–F15（22.113–22.130s）：剑光继续下移、离开主体中心，环境光回到可读状态。

两段展示了**一致可复用的材质反应机制**：机器表面有固定金属边缘和灯泡位置、光照响应局部出现，视觉饱和度逐渐解开，再用武器做方向性动作。

## 我们的原创雪林游戏应该迁移的不是像素风，而是演出机制

1. **安静的场景常驻微动**：雪林 2.5D 的树前、中、后景独立运动，雾与风雪连续但小幅；视差以镜头位置变化为主，而非统一整屏位移。
2. **人物立绘与 UI 独立层**：演员体积与脚下阴影分离于 UI，攻击时人物局部推进；角色状态数值在场景图层之上，不跟随背景泛光而失去清晰度。
3. **一次只给一个大动作**：攻击动作按“角色预备 → 强触发 → 命中确认 → 数值结算 → 撤退恢复”依序排队；高强度闪光绝不能同时覆盖角色和手牌。
4. **状态更新与画面结算分离**：战斗引擎先算完整的事件序列，视觉导演再按依赖关系消费；每个来源的奖励、减血、晕眩等要能一一对照。
5. **同一套空间质感**：雪地是柔和漫反射、木制 UI 有摩擦／弹性、金属部件短促的高频反光、玻璃型元素少量辉光。不是给整屏加 CRT 扫描线。
6. **声音同一拍**：启动、机械停顿、挥动、命中、硬币/奖励和数值跃迁各自独立声效事件，且明确混音优先级；不能用浏览器单音 oscillator 代替完整材质音效。
7. **反复测量、而非凭主观修 CSS**：在游戏录屏上逐帧对比相应事件，记录“第几帧起动、第几帧峰值、第几帧可重新操作”，每次改动自动录制桌面、手机对应片段。

**可用于我们的起始实验参数（完全是设计提案，不是 Balatro / Slots & Daggers 原版参数）**：

- 角色预备：7–12 帧 @60fps。
- 强光／武器触发：2–4 帧，紧凑、峰值明确。
- 命中冻结：1–3 帧；大招可短暂加长，普通攻击不能拖沓。
- 受击位移：4–7 帧；回复：10–18 帧。
- 数值和状态连锁：一跳一跳显示，按可读性动态调节节奏，提供 0.5× / 1× / 2× 的选项。

## 实施对象

已有的原始素材、战斗机制、Anima 人物不变。首先重做：

- `site/card-battle/motion/snowbound-motion.js`：明确全局动作编排器和事件队列，支持帧级中断、skip、安全检查点。
- `site/card-battle/ui/snowbound-journey-ui.js`：永久保留人物 DOM 节点，避免状态更新时重建舞台，从而防止动画跳帧、焦点丢失。
- `site/card-battle/ui/snowbound-forest-reference.css`：角色层、透明剪影、雪地接地、镜头景深与 UI 质感实现分层，不继续向单个 CSS 文件无限叠加覆盖。
- 添加“真实游戏播放记录与参考逐帧对比”浏览器测试：实际动作来自点击，不用硬编码动画效果冒充实机。

**当前完成的只是原始参考素材的帧级研究和提案，不代表这些表现已经在游戏中实施完毕。** 新的视觉开发需按上述顺序用真实录屏检验。
