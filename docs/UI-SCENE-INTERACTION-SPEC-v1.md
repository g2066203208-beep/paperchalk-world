## 1. 你要的开局（剧情、氛围与镜头决策）

世界：架空港联邦秩序衰败，居民面对失业、暴力与官商失职，但个体警察、公职人员和商户必须有人性与不同利益。玩家与阿凯从孤儿院相识、曾住打工阁楼；这是**已经发生的背景**，绝不把孤儿院或打工阁楼当成游戏第一关。两人之前蒙面曝光欺压码头工人的小地头蛇马顺的黑账、帮助工人讨回工钱，事件在道上传开；二人真实身份仍未暴露，与四大家族没有直接关系。购置第一处小型毛坯办公室已经完成，剩余现金190元。

**游戏第一帧必须直接出现刚买下的毛坯办公室。** 水泥墙未粉刷、地面有灰、窗漏风、旧台灯、二手木桌和两把破椅子；地契和关于蒙面人的报纸躺在桌上。阿凯在屋内，主角采用室内近第一人称/肩侧交替镜头（默认看不到一个固定第一人称大头像）。主角与阿凯**不是成熟的黑帮老大**，没有地盘、员工、产业和高级办公室。以后通过**游戏内真实购置建造系统**逐步装修，资产随故事和财政变化。

首段90秒节拍：`00.00–00.05` 黑屏后晨光穿破窗进入办公室；`00.05–00.14` 镜头缓推裸墙→木箱垫脚的桌子；`00.14–00.23` 阿凯把地契放到桌上，短声“总算是我们的了”；`00.23–00.31` 玩家可移动视角，报纸被风掀起露出“两名蒙面人”传闻；`00.31–00.50` 玩家自由点击地契、报纸或阿凯，选哪一项并不强制；`00.50–01.30` 阿凯提出街坊有急事，门外真实敲门声，玩家点门打开可看缩略场景的路线图，再出门。**重要：过场可打断；首段不得用全屏滚动文字或连点十个“继续”按钮。**

第一个重大事件已经在开局之前发生；玩家的第一次真正决定是“是否利用流言做生意 / 怎样帮助社区”，不是让玩家执行一段暗杀教学。出场新闻只知道有蒙面人，不揭晓真名。**旧版每日办公租金必须随着办公室已购入状态取消**，改为水电/破损维护成本；也不能把地契作为领取一次性奖励反复加钱。

## 2. 唯一的坐标、渲染、响应式标准

- 设计世界：`1200×670`；原点左上，x向右，y向下；精确场景矩形写作 `(x, y, w, h)`。所有背景、可独立点击物件、人物、遮挡层按同一个世界坐标定位。
- 初稿原始背景和最终素材：`1200×670` 是逻辑尺寸，原画至少 `2400×1340`，以 sRGB 输出；分层透明 WebP/PNG 必须附导出锚点（pivot）、alpha、z、遮挡区域与 hit polygon。**不允许每个模块凭百分比另起一套坐标。**
- 场景摄像机是正交 2D 镜头，`screen = uniformScale × (world - cameraOrigin) + viewportOffset`。x和y必须用同一个缩放系数；不许把整幅场景非等比拉宽拉高。
- PC 16:9 / 16:10：完整主场景为主，超宽两侧延伸景别/装饰，不拉伸。安全区域：上边12 CSS px，底部24 CSS px；重要台词不能放在系统手势条下。
- 手机**竖屏390×844**：在实际可用内容区内显示约400世界单位的横向视野，分“桌面—阿凯—门口”三个摄影机机位，世界 x 焦点为 `0、400、800`，以230ms缓动切换；滑屏在不可交互背景上触发，点击任何道具不能误触镜头滑动；最后一档必须可触到出口。禁止直接把完整1200px画面压缩成390px或让人物拉长。
- 手机横屏844×390：全局完整镜头，可用时针对对话与地图局部推镜；最低场景高250 CSS px。镜头变化不能打断正在走动的 NPC。
- Hit testing：**可见alpha多边形**为主、至少扩展8 CSS px命中边缘。移动端触发区最小`44×44 CSS px`，建议`56×56`；相邻热区要按 z 和屏幕覆盖裁决，不能让桌子透明覆盖手机/地图。
- 层级：`0–3背景`、`4–5前景遮挡与环境`、`5–6角色`、`7–10实际桌面物品`、`11气泡`、`12镜头蒙版`、`13焦点物件`、`14选择纸条`；层级可通过定义映射，但语义固定。

### NPC空间对齐算法

行人脚底pivot是物理落脚点；位置是**后台长期世界状态**，表现为 scene-local sprite。玩家打开纸、和NPC说话、拿起地图时，不允许整张场景重新构建让人瞬移。行人更新只改变自己的 animation controller 与目标路径，连续运动；不同角色利用 z 与脚底 y 自动深度排序。每个时段真实人数来自 `population`，单场景首先绘制最多5名有角色身份的行人，余下远景用合批剪影，不能一次渲染80个完整 DOM 木偶。

### 关键操作的时间轴（必须按顺序而不是一起弹）

**电话：** `t=0` 点击电话机真实轮廓→`t≤16ms` 机身压低/高光→`t=40ms` 轻微塑料敲击音→`t=40–220ms` 听筒从座机抬起（独立 sprite，Pivot 在握持端）→`t=190–330ms` 镜头微推与联系人气泡→`t≥330ms` 开始对话。挂机逆过程不长于200ms。响铃每920ms一轮、两轮后降噪，默认音量不过响。

**地图：** `t=0` 指尖触纸→`t≤16ms` 纸角轻翘→`t=40–360ms` 三折纸依次展开，地图实际连贯出现在桌面上→`t=360ms` 可点击城区，地图不可在动画尚未完成时接收错误触控→选区钉入图钉110ms→规划路径按每段85ms描线（总200～850ms）→派遣时将成员照片/签字推至目标区，地图贴纸反馈不额外弹toast。

**地契/账本：** `t=0` 点击真实纸页→`t=0–90ms` 纸角上翘→`t=90–270ms` 接近180°的页面翻动（应模拟纸片翻折或逐帧，不只是整体fade）→`t=270ms` 数值/签名可阅读。点击已签署契约直接反应，无重复付款。

**阿凯对话：** `t=0` 点击人物→`t≤16ms` 眼神锁向玩家→`t=0–180ms` 胸肩向正面转、原地呼吸，**NPC口部与眼睛分别动**→`t=180–310ms` 气泡从头部附近上浮12px并展开→文本34字符/秒，逗号/句号停160ms；玩家点击气泡完成全部文字，下一次点击或选择才进入下一句→选择结果从人物表情和世界事件体现，不要在下方再独立弹一条“+声望”面板。快速连续点击不得重复选择。

**开门旅行：** 点击门锁→真实门把轻转（80ms）→门扇转动210ms→走向出口380ms、人物身形被门框遮挡→遮光蒙版180ms→下一场景布景与NPC保留连续性→到达镜头420ms。合计目标约700ms，允许转场阶段适当重叠但不得直接瞬移或显示5个网页按钮。

**发生冲突：** 先出现角色异常与场景群众反应：台词中断/路人回头（150–250ms）→相关角色进入对峙pose（300ms）→玩家可介入/对话或退出→后果记入真实事件与新闻。不要让每次冲突都播放相同的全屏红色斜切闪光。重大事件才有独立时长不超2.5s的短演出；不展示现实犯罪教程。

## 6. 木偶角色素材必须怎么拆

每个人物基础**19层**：shadow、后发、近腿、远腿、躯干、外套后片、左大臂、左小臂、左手、右大臂、右小臂、右手、颈、头、眼睛、眉、嘴、前发、饰品。每层带相对骨骼pivot；身体不应只是一个完整SVG整体在晃动。

首批必做主角（根据镜头需要部分出现）和阿凯角色包，随后是楼下婶婶、林姨、就业所职员、码头工友、巡查员与失业求职者。统一线条与色块粗细、鞋底接地、阴影方向、发丝转动约束，杜绝不同人物像来自不同画师。

动画状态：`idle, talk, listen, look, reach, take, handOver, walk, turn, startled, angry, sad, leave`，表情 `neutral, smile, thinking, worried, angry, surprised, sad`。角色状态机采用可打断的过渡：`walk→talk` 最多120ms完成朝向切换；手里持有卷宗时不可错误触发另一套空手交付动作；说话嘴形随实际文字播报进行，不许无限循环假说话。睁眼→闭眼→睁眼有固定95/100ms动作，但眨眼间隔在2.7–5.7s间根据稳定seed轻微变化；呼吸周期3.2s仅移动躯干约2px。

每个动作需要 `rig manifest + pivot + layer id + state clip + bounds + hitboxes`；一份人物动作可复用于其他NPC，但每人保留自己的个性参数与动作速度差异。**正式绘制采用原创分层GPTIMG美术，当前程序色块SVG只允许作为功能验证占位。**

## 7. 音效、环境音与沉浸反馈

- 室内毛坯办公室：风穿窗（低强度环境Loop）、风吹地契纸、偶尔楼外远车声；房间为空，混响轻微但不得持续回声。
- 背街：远处争吵/脚步/自行车铃，声音随NPC位置衰减。
- 集市：吆喝/推车轮/菜篮轻碰；不能所有NPC同时高音量说话。
- 就业所：钟、纸张翻动、鞋底回响、远处谈话。
- 码头：海风、船鸣、吊机、货箱，远近层次分开。
- UI声音一一对应实体：纸、电话按键、门把、木桌、鞋底、水泥；音频默认尊重移动浏览器用户手势解锁和静音。音效起始目标`≤45ms`，同时触发同类音效用优先级与短暂冷却避免刺耳叠音。暂停或切到背景必须停止/淡出Loop，不可暴走。

## 8. 最容易出戏的“UI禁止事项”

不允许在行人头上常驻漂浮“交谈”按钮，也不允许地图/建筑/招聘全做成卡片矩阵占满屏幕。没有提示时，用微光、指向动画或人物自然看向物体让玩家发现互动；悬停/聚焦才显示短标签。真实叙事通过纸张、电话、街头对话传播，数值在玩家主动打开账本/档案时显示。街道不出现HUD的“保护费+10、生命+5”等游戏化表演。

不开局就有高背老板椅、手枪摆件和豪华办公室装修；后续若玩家决定升级房产，桌面和房间应根据 `officeCondition/renovationLevel` 使用**同一场景**的升级素材层，不能直接替换世界观。

## 9. 场景与交互工程约束

```text
scene contract (JSON / art metadata)
         ↓
SceneDirector        CameraDirector         InputRouter
         ↓                 ↓                    ↓
SpriteLayer/rig ←→ World↔Screen transform ←→ precise alpha/polygon hit
         ↓
AnimationStateMachine → AudioCueQueue → DialogueBubbleRenderer
         ↓
DomainCommandBus → Simulation state / event log → save (atomic)
```

- `SceneDirector` 只在**真正换地点**时销毁/加载场景。点击人物、开报纸、读档案不得重新渲染整条街并重置路人位置。
- `InputRouter` 先按屏幕命中alpha轮廓→转世界坐标→按z和物件交互优先级选择对象，调用有限状态机，防重复提交/重复收费。单次指针只能激活一个物件。
- `CameraDirector` 单独负责宽屏/竖屏镜头布局；NPC和世界坐标不因镜头平移而发生跳变。
- `DialogueBubbleRenderer` 挂在人物骨骼头部锚点，做屏幕边缘检测；对话文本允许被中断，退出场景前记录最终状态。
- `AnimationStateMachine` 全部通过动作参数或时间轴数据驱动，不能在 `app.js` 写十几种临时`setTimeout`。
- `AudioCueQueue` 仅消费游戏事件，不改资金、人物关系或剧情节点；表现层永远不得给玩家加钱。
- 世界事件可由模拟器发布，但**播放动画必须等事件发出后才触发**；动画失败不可影响已经结算的游戏逻辑。必须保证可存档、可重放、可跳过非关键动画。

## 11. 每一个素材的交付要求与生产顺序

每个对象至少需有：`assetId, sourceFilename, sceneId, x/y/w/h, opacityAlpha, pivot, hitPolygon, zIndex, animationClipRefs, renderingPriority, adult/child safety metadata where relevant`。角色每个骨骼片段独立透明；文件、门、电话等交互物件至少有 normal/hover或focus/pressed/opening/open/closing 视觉状态。背景为独立分层（远景、近景、遮挡），大画面可按相机和具体场景合图优化，但不能把可交互道具烘焙死在背景图里。

首批**必须先生产和验证**：毛坯办公室6个背景/遮挡层 → 阿凯19层角色包 → 桌面地契/电话/地图/卷宗/报纸5件 → 开门与地图过场 → 背街与林姨集市 → 就业所成年候选人。这些完成后才开始大规模生成几十种商铺、黑帮领地和更多街头冲突，不然素材风格和引擎接口会失控。

## 12. 一次完成一张真游戏画面的验收清单

1. **规格一致性**：所有对象有合法世界矩形、层级、pivot和asset路径；跨图的同物件复用同一ID与尺寸定义。
2. **场景构图**：毛坯办公室实机截图与标注规格逐一对应；门在右上，阿凯在桌后偏右，地契在桌左侧，无豪华装修。
3. **透明素材**：每件桌面物品独立图片，不被背景烘焙；同一场景移动镜头时相对位置不漂移。
4. **命中反馈**：桌面至少20次手机连续点地图/电话/地契无错点；热点重叠时前景优先。
5. **人物演出**：阿凯说话至少同时有朝向、嘴、眼、手臂三部分动作，气泡锚点随人物位置变化。
6. **路人连续性**：走动中的路人触发对话/卷宗后不瞬间回初始坐标；真实换地点才卸载场景。
7. **旅行流程**：只有点击门/街口实际物件可移动；门→纸质目的地图→可达地点→开门过场→出现场景，至少要有可验证的遮挡与脚步动作。
8. **纸张手感**：地图三折、卷宗翻页、电话听筒均有明确0–360ms动作，不是纯opacity切换。
9. **真实经济**：打开地契不会重复领190；已购买的办公室不继续每日日租；做生意通过账本显示真正收益。
10. **文戏完整**：玩家不是在孤儿院、阁楼开局；两名蒙面人的传闻存在但二人身份未公开；第一天只有两个人。
11. **手机**：390×844三机位全部必点对象可访问；不变形、不藏关键对话。
12. **主站门槛**：Node校验数据→桌面/横屏/竖屏真实Chromium点击与帧截图→审查故事/美术/热区→再合并main。任何一步失败不得说“已经好了”。

## 14. 交互命中多边形、音效与单对象动作绑定

`scene-interaction-contract.v1.json` 现在不只写矩形：每一个有交互动作的实体素材都有 `hit.localPoints` 的局部多边形点列（相对于素材左上角的像素）、`alphaCutoff=0.25`、`minTapCssPx=44`、`preferredTapCssPx=56`、`expandCssPx=8`、`animationPresets[]`、`soundCue`、首帧响应预算及防连续重复触发的冷却时间。没有动作的背景层 `hit=null`，**不能莫名吸收点击**。未来有了最终美术，可从 alpha 实轮廓替换粗略命中多边形，但必须保留至少44px手机可触范围与对象稳定 ID。

命中优先顺序：`当前镜头真实可见范围 → 点映射到世界坐标 → 场景物件局部坐标 → alpha阈值/多边形判断 → z层决议 → 状态机检验 → 单次命令提交`。点击放在两个物件重叠处，必须选择视觉上靠前且真正有点击功能的对象；透明背景不拦截。

每个 `ui` 还明确包含 `inMs`、`outMs`、是否 `focusTrap`、以及是否保留可见场景背景。焦点对象出现后，应暂停其下层交互或按场景规则转移焦点；按Esc后焦点回到原实物。这里的入场/退场时间是设计契约，后续动作代码须按它读取，不得在不同文件随机硬编码300ms。

**实施工作单的规范格式**：一个交互必须同时提交 ①asset分层文件 ②场景物件布局项 ③命中多边形 ④动作时间轴 ⑤音效 cue ⑥domain command ⑦自动化截图与事件日志。缺任意一项，判为未完成。只有真实点击响应与截图符合这些数据，才可把这份设计表的“目标”列转为“已实现”。
