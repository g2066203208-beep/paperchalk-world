# 沉浸式场景修复 / 2026-10-29
## 用户反馈对应的缺陷
- 点击任意事物整张 `explore-root.innerHTML` 重建，所有行人回到初始位置。
- 人物只有一次性 `origin.talk` 文本，分支对话需要进入外置管理页。
- 出门依赖各页面边缘箭头，缺失“点门 → 地图选地 → 出门”的一致流程。
- 旧打工阁楼擅自加入了可游玩场景；开局应为两人购买的毛坯办公室。
- UI 过度展示顶栏、标签和面板，抢占场景视觉。

## 这次实际代码
- `scenes/explore.js`：按地点构建场景一次；普通指令只更新数据与本地会谈；居民角色以 ID 键控，不因为点击重建。移动动画走 CSS，不是“点击时重新定位”。
- `scene-dialogues.js` 与 `systems/dialogue.js`：具有明确角色设定/个人语言的场景对话，提供多种回答分支并记录到模拟器。普通居民也能聊天，且只和当前地点及时间范围内的人交谈。
- 地点出口变为可点击门，打开地图选择五处可游玩目的地（办公室、旧港背街、市集、就业所、码头），再模拟开门/转场/进入目标场景。删除可游玩的旧阁楼。
- `scene-navigation.css`：带场景预览的实体路线地图、低侵入场景内对话气泡、布局简化、行人连续行走、换场动效、手机横竖屏。
- 不再自动强制用整屏“汇报”面板覆盖新的一天；经营卷宗是可选的桌面物件。取消由人物交谈触发的重复 toast 和台词浮层。

## 真实程度边界
这些是带持久 DOM 生命周期的二维人物动画，不是已实现的全城连续寻路 AI；目前路人有 80 人的抽象住址/工作/休闲数据，单场景只渲染若干人，移动用时段内的场景步行演出。更进一步的逐路网迁移、避障、店铺进出、NPC 关系与对话记忆仍应按系统模块实现，不能宣传已完成。

## 验收
- 实机 UI：打开阿凯对话并选分支，结束后回到办公室场景。
- 点场景门 → 地图 5 个实际地点 → 选择市场 → 转场到市场。
- 点击林姨谈话/帮助期间，当前路人 DOM 仍保持身份标记不被重建，持续动画不回退。
- 点击出口前往就业所，同样能当面谈话并保存。
- 390×844 手机竖屏打开路线地图选择码头，检查溢出、场景和行人。
- 回归旧电话、地图、卷宗、账本，以及原有模拟测试。正式主站仅在所有验证成功后部署。
