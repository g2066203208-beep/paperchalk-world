# PAPERWORLD · 世界美术重构 v2（原创四色）

> 本文是对真实游戏截图的像素密度、体块和 UI 占用问题的工程复盘。研究其他作品的**原则**，不移植、不描摹其角色、纹理、建筑或场景素材。

## 实机问题（2026-10-31）
- **视觉信息密度过高**：旧版道路每约 2 米重复一套 16×16 噪点；建筑 6 个面大量硬黑描边，导致强烈摩尔纹和黑色线网。
- **建筑缺少形体**：屋顶由三层不同宽度的长方体堆叠，远看像机器外壳。
- **树冠缺少形体**：大小方盒错位，视觉上更像货物堆。
- **游戏本身被 UI 遮蔽**：手机体感调试栏压住约三分之一的画面。
- **质量验证缺失**：按“贴图数”“三角面数”判定好看是错误指标，应该查看不同分辨率的实机截图。

## 研究参考，非复制素材
1. **Adam Robinson-Yu，《A Short Hike》** — 原作者讲述：平面统一明暗、不使用抗锯齿、轻柔而必要的外形轮廓、低分辨率仍然可读。[原作者制作复盘](https://blog.playstation.com/2021/08/05/crafting-a-tiny-open-world-a-look-behind-the-scenes-at-the-creation-of-a-short-hike/)。
2. **Samuel Cohen，《Summer Sunset: 3D Pixel-Art Diorama》** — 在建模前制定场景色彩与构图草图，实测移动屏幕的像素密度，先验证材质比例和 UV，再继续建模。[作者过程记录](https://samuelcohen.artstation.com/projects/6aWwVV)。
3. **Glumberland，《Ooblets》** — 分析官方制作日志的立面层级：门、窗、屋檐、檐篷和前后街区的色块构成清晰店铺剪影。[官方开发日志](https://ooblets.com/2018/01/january-2018-devlog-a-new-town-on-the-water-nooblets-machines-shops-and-gleamies/)。
4. **Jannis Petersen，《Blockbench》** — 利用低多边形几何与受控 UV 而不在每一面强贴复杂纹理；可作为后续导入外部原创模型的工具思路。[官方文档](https://blockbench.net/)。

## PAPERWORLD 自己的美术约束
- 任何资产可见像素只能使用 **#393657、#F2A5C2、#A9BAE9、#FFF5E6**；不增加第三方游戏的色表。
- 远景与大型平面优先为**大色块**：路面主色覆盖 97%+，草地 94%+，奶白墙面 94%+。局部点缀必须是成组轮廓而非独立杂点。
- **线条不默认绘制**：不对所有三角面描边，只保留屋顶脊线、屋檐等有识别意义的外形线。旧版超过 1 万条黑线，新版地形测试为 270 左右。
- **有实质体积的建筑**：使用上有脊、两侧倾斜、两端山墙的几何真屋顶；门、门框、窗按结构区分，避免用同一贴图铺满整栋楼。
- **树木有生长方向**：细树干+八向低多边形树冠，外轮廓优先；不用方块叠方块的装饰。
- 道路从画面最近处通向建筑，能够在缩小画面下仍读懂主路/人行道/街屋；保留舒适的无细节空间。
- 屏幕上的 HUD 不盖过主角与建筑：默认展示紧凑操作，展开后才呈现三轴调试信息。
- WebGL 原生采样 **NEAREST**，不开平滑；沿用 16×16 真像素与 128×64 32 材质 Atlas。
- **存档安全**：旧版官方材质经 FNV 校验完全未修改时升级为新默认，有玩家笔画的材质原样保留。

## 验收方式
- GitHub Actions 运行精确四色单元测试、WebGL 浏览器截图测试和 3 个视口的游戏画面测试，发布截图供直接核查。
- 桌面 1440×900、手机竖屏 390×844、横屏 844×390 各检查：无破碎线网；门窗/屋顶/树冠有形体；道路易读。
- 必须区分“测试成功”和“艺术质量已达标”，真实艺术判断依据依然是截图及用户反馈。
