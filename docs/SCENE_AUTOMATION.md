# Paperchalk World｜图片驱动的全自动场景模块

## 只做一件事：上传图片

把新场景图片提交到 **`site/assets/scenes/`**，例如：

```text
site/assets/scenes/
  bedroom.webp          卧室（现有）
  entrance.webp         玄关（现有）
  living-room.webp      客厅（现有）
  basement.webp         地下室（新图片，自动出现）
  stairwell.png         楼梯间（新图片，自动出现）
```

**不需要**改 `index.html`、菜单、脚本、场景列表、UI、角色路径或专门写一条 JSON 配置。

在 GitHub 仓库中打开 `site/assets/scenes/`，选择 **Add file → Upload files → Commit changes**。之后 **Classroom - independent continuous fog stage** GitHub Actions 会验证、打包并发布 GitHub Pages。也可直接覆盖某一张原有场景图，保留同名文件；不需要新建场景模块。

## 自动完成什么

`scripts/build_scene_catalog.py` 扫描所有图片并检查图片真实可解码、大小、文件类型、文件名与重名冲突，保留图片的原始像素（**绝不重画、拉伸、裁切或重新压缩上传的图片**）。编译结果：

- `site/scene-catalog.generated.js`：提供给游戏引擎的场景登记数据。
- `site/scene-catalog.generated.json`：机器可读的场景清单，包括 ID、中文名称、真实尺寸、图片 SHA-256 版本摘要。
- `site/scene-modules.js`：统一定义房间的公共配置，不再给每个房间复制渲染代码。
- `site/index.html`：使用统一的场景模块自动生成 **主菜单场景预览** 和 **游戏内切换场景**。

每张新场景图自动继承已经设置好的：

1. 场景图片独立背景层；尽量完整展示原图，不做放大裁剪；
2. 已确认的主角**背面透明立绘**作为独立前景图层，不画进图片；
3. 实时黑色流体雾固定在屏幕空间、景深分层、场景边缘全黑遮挡；
4. 场景背景响应已有鼠标/手机感应倾斜配置；
5. 深黑转场、图片预加载与场景切换管理；
6. 手机/电脑自适应场景预览与画面显示；
7. 自动生成浏览器深链接 `?scene=<图片文件名去掉扩展名>`；
8. GitHub Actions 检查图片、场景登记、页面渲染和现有角色/黑雾结构，然后发布托管站点。

**主菜单与教室剧情是内置场景。** 新图片只注册为普通环境场景；不会额外创建“主角立绘”场景，不会复活旧恐怖人物、旧动态黑斑。

## 图片要求与命名

- 文件类型：`.webp`、`.png`、`.jpg`、`.jpeg`。
- 使用小写英文字母、数字和连字符：`guest-room.webp`、`school-hall.png`。
- 建议 **16:9 的 1024×576**、1920×1080 或等比例高分辨率；其他比例也能加载，保持图片内容，不替你擅自裁图。
- 最短边至少 128 像素，最大单边 8192 像素，单个文件不超过 25MB。
- 同一场景 ID 只能存在一个图片扩展名；不可同时使用 `kitchen.webp` 与 `kitchen.png`。
- `menu`、`classroom`、`protagonist` 是保留 ID，不用它们给普通房间命名。
- 已内置常见中文名称（卧室、玄关、客厅、厨房、楼梯间等）；其他合法文件名自动变成可读标题。

## 测试和故障定位

新增场景会先接受 **严格格式校验**，损坏图片、错误扩展名、重名会导致 Action 明确报错，不会默默发布一张空白图。自动化覆盖：

- 使用虚拟新 PNG、WebP 证明“只上传一张图”即可注册；
- 损坏图片、重复 ID 的构建拒绝；
- 运行时模块继承正确图层及前景立绘；
- **遍历当次所有场景**，检查它们都出现在主菜单预览、图片能解码且尺寸与清单一致；
- 现有客厅、卧室、玄关的完整切换、转场、黑雾和角色分层回归测试。

构建动作：`python3 scripts/build_scene_catalog.py`（需要 Python Pillow），然后 `node tests/scene-modules.test.cjs`。

## 保留用户既有设置

**不修改**原来的本地存储键、雾参数、鼠标倾斜、手机传感器校准、DEV 景深数值、已有图像或角色素材。新场景使用同一套已实现的渲染器和设置，切换场景不会创建第二套黑雾。浏览器里保存的个人调参仍然保存在该浏览器本机：**单凭 GitHub 不能读取或备份你浏览器里的 localStorage**，因此这些个人参数不会自动同步到仓库，也不会谎称已经上传。

## 自动化的边界

上传图片能够自动完成**标准场景模块**（背景、固定特效、主角分层、预览、切换、测试、部署），但不能仅靠画面安全推断“谁居住在房间里”“房门有什么互动”“下一句剧情是什么”。后续若要剧情、门锁、敲门、NPC、交互热点，应该作为独立游戏逻辑模块设计，**默认不会凭空添加道具或人物**。
