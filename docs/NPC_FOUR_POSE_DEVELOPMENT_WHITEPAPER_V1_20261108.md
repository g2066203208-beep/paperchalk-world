# 地铁路人 NPC 四格 Anima 制作开发白皮书 V1
**日期：2026-11-08｜适用范围：地铁 / 站台 / 城市 2.5D 路人 NPC 人物集**

> 本白皮书是根据 2026-11-08 可见的 NPC 开发对话要求、已经提交的 GitHub 图鉴与提交历史整理的工作契约；不把未取得的旧会话完整逐字记录冒充原文。角色设计任务负责美术，场景实装任务负责日程与 2.5D 摆放，彼此不得越权。

## 0. 唯一原则

**同一个 NPC = 唯一 ID + 固定外貌/服装母版 + 四格角色图 + 人工批准 + 透明素材 + 明确的行为/场景许可。**
图像“看着差不多”不等于可用；一个角色照片、三格立绘或程序画的小人不能自动被宣布实装。

四格不可变顺序：
1. **Front:** 0° 纯正面，双脚静止着地，双臂放松；
2. **Side:** 朝画面左边的**严格 90° 纯侧面**，双脚静止着地；
3. **Back:** 180° **纯背面**，绝不露正脸，双脚静止着地；
4. **Special:** 属于此人物的一个真实生活动作，**默认纯正面**，只有用户单独批准才允许改变角度。

前三格只提供不同朝向的基础美术，**不是三张走路帧**。真正行走、转身、靠近镜头、坐下等动画由独立动作系统、过渡与世界空间运动制作，不能通过把站姿改成迈步来混淆。

## 2. 美术风格锁与 NPC 观感

- 保留项目已批准的克制日系动画/2.5D 美术：`@akipekostyle` 与实际安装的 `akipekoanima_v1_1` 别名。路人是环境中的**普通市民**，不是精细华丽的可玩主角，不用极端五官、夸张姿态、战斗演出。
- 人物尽量降低抢镜程度，但**不能靠源图故意模糊或压缩**；画面清晰，游戏里靠合理的世界比例、相机和灯光融合。
- 基础图不要画方向性光影、地面投影、强烈边缘光、环境背景；光照、阴影、透视由场景实现。
- 不能因为第四格做了活动就擅自变更职业、住址、出行线路或出现地点；这些属于 `scene-assignments.v1.json` 和日程系统。
- 必须保留唯一身份，不能让其他 NPC 复制同一张脸、衣服组合和生活动作，仅靠缩放/调色当成新角色。

## 3. Anima 官方规范与本项目配置

官方模型卡：https://huggingface.co/circlestone-labs/Anima

1. 标签可使用 Danbooru/Gelbooru 小写、空格分词的形式，配合完整英文自然语言。推荐正向前缀：`masterpiece, best quality, score_7, safe`。不要堆无效标签，`score_7` 是下划线例外。
2. Anima **Base** 官方推荐 30–50 steps、CFG 4–5；`er_sde` 偏平涂、硬朗线条。工作室首测可从 **ER SDE / 35 steps / CFG 4.5 / 1536×1024** 开始。这个值是项目起点，不是经逐图测试的万能最优。
3. Turbo 如果单独试验，需采用其低步数、低 CFG 配方，**不能**把 Turbo 8–12 steps/CFG1 和 Base 35/CFG4.5 混成一个设置。Turbo CFG1 对负向控制可能很弱。
4. 四格单张横排先以官方允许的分辨率工作；最终素材既可透明拆格，也可批准后由受控后处理高质量放大。**不能仅把图像插值放大就声称真实高清重画。**
5. 项目现有常规风格 LoRA：`@akipekostyle <lora:akipekoanima_v1_1:0.65>`；真实本机 alias 与文件需核对。除非批准，首测不同时叠加美化、滑杆、转视角、额外角色表 LoRA。
6. Forge Neo 的 `anima-reference-forge-neo` 与 ImageStitch Integrated 可以用于**同一个 NPC**的姿态修复：使用明确匹配的本人参考原图 + `<lora:anima_ref_adapter_pilot_r32:1>`，参考方法只能选一个，切勿同时开原生 Anima Edit 的 Reference。插件页：https://github.com/eduardoabreu81/anima-reference-forge-neo 。
7. 模型描述“transparent background”不等于生成文件有 Alpha。暂时 RGB 图片即便看似白底纯色也不能用作正式游戏透明素材；最终输出必须检查**真实 RGBA 通道、透明区域、发丝/鞋边抗锯齿**，不能画棋盘格来伪装透明。
8. 仅在角色真实原图、LoRA 版本、seed 和参数受控的情况下进行局部 inpaint；不要为修侧面顺手改变四格人物的脸或外套。

## 4. 每位新 NPC 的唯一资料规范

至少需要 `id`、`category`、`visualCanon`、`special`、`production.positivePrompt`、`production.negativePrompt`、`production.viewOrder`、`render` 和当前人工审核状态。

外貌锁要求记录：年龄段与体型、头身比例、发型与头发颜色、正脸眼鼻口风格、上衣外套的开合方式、内搭露出范围、下装版型、鞋型、关键小配件、各服装颜色。

**重点：每一格都必须是“同一套服装的另一个观察方向”而不是重画四套概念设计。** 第四格只能添加这一动作确实需要的手持物（如 M003 报纸）；椅子、车窗、站台、阴影等属于场景资源。

## 5. 不可跳过的生产流程（门禁制）

| 门槛 | 产物 | 通过条件 |
| --- | --- | --- |
| G0 角色规划 | 唯一编号、与旧图不冲突的人物卡 | 没有覆盖重要角色、已批准 NPC 或重名 ID |
| G1 提示词 | 完整正向、完整负向、四格方向与服装锁、首测参数 | 直接整段复制，不要求用户自己拼接 |
| G2 Anima 原图 | PNG 原样留存、PNG Info、seed、checkpoint/LoRA 版本 | 全身和四格方向达标，同一人同一衣服 |
| G3 用户美术批准 | 可追溯原图路径/哈希、明确审核状态 | 没有用户批准就不能称定稿 |
| G4 透明化/拆格 | 真实 RGBA 图集 + 4 份同序独立 PNG | Alpha 有效、无背景/椅子、无裁边、手/脚齐全 |
| G5 身体尺寸校准 | 脚底锚点、世界身高、各帧一致的像素→米换算 | 坐姿不变成矮子，侧身不漂移 |
| G6 分工交接 | 美术任务写生产清单；实装任务写位置/日程 | ID 匹配，场景许可与人生线路可解释 |
| G7 游戏实测 | 车厢/站台 WebGL 截图、开关灯/乘车运动/站点进出验证 | 不浮空、透视合理、不挡重要视线、不开不该出现的 NPC |

若 G0–G4 任何一项不通过，必须保持 `artApproved=false` 或未入 active records，禁止让运行时用旧图兜底；若 G5–G7 不通过，则只可声称**美术准备好**，不能声称已经实装。

## 6. 2.5D 场景实装与真实人生边界

- 美术来源：`site/data/npc/metro-character-gallery.v1.json` 与具体 `metro-commuter-npc-m00X*.json`。
- 双任务系统：`site/data/npc/production-manifest.v1.json`（美术审批、路径）与 `site/data/npc/scene-assignments.v1.json`（地点、线路、乘车许可）严格分离。
- 真实行为依托 `site/game/npc-life-sim.js`、`site/game/npc-scene-presence.js` 和 `site/game/metro-npc-staging.js`；只能在人物实际沿可行线路到场、方向和区间匹配时显示。不会仅因为图片叫 commuter 就随机进地铁。
- 地铁需统一相机投影、脚底锚点、透视和遮挡；NPC 是环境路人而不是前景主角。车内外真实 3D 硬件（座椅/门窗/扶手）与人物独立，通勤特殊动作根据世界状态播放。
- 回归测试入口：`tests/metro-npc-four-pose-gallery.test.cjs`、`tests/npc-scene-presence.test.cjs`、`tests/metro-npc-world-staging.test.cjs`。测试存在或通过**不能替代浏览器实时截图验收**。

## 8. 每次提交 GitHub 的产物与不可造假的验收说明

1. **用户只提供人物需求时**：提交完整四格 Anima 提示词、负向、参数与资料，状态必须是 `REDRAW_REQUIRED_FOUR_POSE` / `awaiting_anima`，不能提交空路径或伪造批准 PNG。
2. **用户提供实际生成图时**：确认完整外貌与用户意图，原图与哈希入库，视图、衣服、头鞋、尺寸逐项验收，不得擅自覆盖 M003 的批准源图。
3. **确实完成透明加工时**：保留 RGB 原图，另存真实 RGBA atlas 和四份 sprite，写入 blob/文件路径，测试图集读取和 Alpha。
4. **真正运行时接通时**：测试允许出现的场景、行程、灯光、遮挡、透视，提供游戏本体截图并标出版本；不以贴图查看器代替实际游戏。
5. 每次在图鉴 README 和 JSON 中写明“已计划 / 已作图 / 已批准 / 已入库 / 已实装”的哪一步，禁止用“完成”统称不同阶段。

## 9. 一人一生活：用户追加的强制修正规则（2026-11-08）

以前的工作把 NPC 当成通用站桩模板，第四格只机械换成坐姿，这是错误的。**每个人必须有独立的生活状态、性格、习惯、情绪、微动作以及可辨识的专属第四格**，不能只换脸、服装和手持物。前三格继续严格正面/侧面/背面静止站姿，以便运行时朝向渲染；前三格也可有合乎人物的微妙自然体态，但不能变成不同动作。第四格专属设计以此人生活小传为驱动，清晰告诉玩家“他在干什么、他为什么这样、与别人如何不同”。

已批准 M003：老人平静端坐阅读报纸，动作、身份和情绪相符。下一位 M001 V5 候选：晚班下班、安静、节俭、有礼却困顿的年轻男子，第四格纯正面**站在原地**揉酸痛后颈、轻轻打哈欠、另一手提旧饭袋，肩膀不对称、眼皮沉重；与老人坐姿读报和 M002 看手机的姿势轮廓完全不同。这个人物小传是**未获用户最终审核的提案**，不把其职业/住处/路线写为游戏事实。提示词见 [M001 V5](NPC-M001_ANIMA_FOUR_POSE_PERSONALITY_V5_20261108.md)。

## 10. 2026-11-08 追加纠错：无眼睛、前三格动作统一，只有第四格专属待机

用户明确纠正前面 V3–V5 的错误：**不画眼睛**（含眼球、闭眼弧线、睫毛、瞳孔、眼线）；同一人物第一格纯正面站、第二格严格向左 90° 站、第三格纯背面站，三格站立动作完全一样、双臂自然下垂，只变方向。不得在第三格加揉颈、不得让第二格重复正面。第四格才根据个人生活设定做一个个性化待机动作，M003 坐着读报，M001 坐着打瞌睡，M002 原计划玩手机。第四格仍保持服装、人物一致，不画场景家具。过去把 M001 改成第四格揉颈打哈欠、脱外套或换衣的尝试是失败候选，不准再当默认。正式修订见 [M001 V6](NPC-M001_ANIMA_FOUR_POSE_NO_EYES_V6_20261108.md)。该要求来自用户明确反馈，不得被其他任务的通用人设规划覆盖。
