# 雪境行旅：第一阶段战斗截图像素审计（2026-11-16）

说明：这是由实际 Chromium 截图、检测程序输出的尺寸与公开 Wildfrost 游戏画面共同制定的布局审稿，不代表已逐像素复制原作美术。项目只能使用自有 Anima 原画和原创场景。

## 截图前后实测值

V2 来自前一次 Playwright / artifacts/snowbound-phase1/result.json；V3 来自新一轮 Pixel QA / artifacts/snowbound-pixel-audit/metrics.json。数据是浏览器实际 CSS 像素：

| 设备 | V2 单位卡宽×高 | V3 单位卡宽×高 | 修正重点 |
|---|---|---|---|
| 桌面 1920×1080 | 177×235 | 218×258 | 宽度 +23.2%，人物面积更大 |
| 笔记本 1366×768 | 174×235 | 180×244 | 适度增大，避免超界 |
| 手机横屏 844×390 | 107×100 | 94×104 | 收窄横向列距，保留左右两军同屏 |
| 手机竖屏 390×844 | 59×162 | 110×126 | 宽度约 +86%，每条战线分段展示 |
| 平板 1024×768 | 133×235 | 136×226 | 减小上下重叠风险 |
| 小安卓 360×740 | 未测试 | 107×105 | 新覆盖尺寸 |
| 大手机 430×932 | 未测试 | 110×140 | 新覆盖尺寸 |

桌面正式卡片的比例已增大；手机竖屏优先可读宽度而非保持过窄的 6 列。竖屏每条战线显示友军三格和敌军三格，游戏内部依旧保留一致的 row-major slot 编号和同行最前排寻敌规则。最新的前排镜像修正使竖屏双方前排面对面垂直对齐，避免对角错觉。

## 浏览器回归约束

项目 GitHub workflow：.github/workflows/snowbound-journey-qa.yml

- tests/snowbound-full-run.test.cjs：三幕六战、商店、招募、饰品到结算的逻辑模拟。
- tests/snowbound-journey-browser.mjs：五尺寸完整菜单到首领链路、阵位坐标、图片与交互。
- tests/snowbound-phase1-interaction-browser.mjs：五尺寸真实 Pointer 拖动换行、拖牌攻击。
- tests/snowbound-pixel-geometry-browser.mjs：七尺寸逐像素边界：最小角色宽高、单位之间无重叠、单位不侵入桌面、手牌可见、单位名不小于 8 CSS px，所有图像真实加载，12 单位密度压力快照。

每次脚本提交后必须重新截图并重新跑全部回归，不可引用上一版结果报喜。Chromium 设备模拟不能代替每台真机的触摸/安全区测试。

## 本阶段尚未通过的美术品质关卡

- 真正由 Anima 绘制的高质量雪森林及可拆分的远景、中景、地面、前景；当前场景是自绘 SVG，重复树木仍明显。
- 多类道具牌完整原创插图、正式纹理卡框及不同组织材质细节。
- 战斗完整动画演出、镜头反馈、连贯伤害与攻击动作、丰富音效。
- 手机竖屏虽然角色清晰许多，但两侧信息、手牌层级和沉浸感仍需进一步美术审稿。

只接受“参考→截图→真实尺寸→改动→再截图→测试”的循环；没有正式画作和审核就不能声称已像素级复刻。
