# 《错位日常》大世界地区等级与地铁容量规划 V1（2026-11-08）

> **规划提案 / 非运营数据 / 非用户已最终验收**。本轮只固定可讨论的地区分级与路线容量目标，不创建虚构已开通地铁，不修改原版场景、角色、已登记站点和游戏出行逻辑。配套机器可读草案：`site/data/world-settlement-tier-plan.v1.json`。
>
> 硬要求：初始「霧浜市」是 **A 级大型城市**；另有比其规模更大的 **S 级特大都市**；每座城市拥有独立地铁网络；地铁地图严格只画地铁；其他城镇无须强行拥有地铁。未来每个**实际地铁站**对应独立可进入局部场景，但这一阶段不制作场景。

## 1. 两套层级不能混淆

- **大世界/区域层级**：多个都市圈、山地农业区、沿海半岛和群岛；跨城市使用地方铁路、城际铁路、公路、客运与渡轮。当前十个已登记行政地点只是第一片可玩的广域区域，并非全游戏所有城市。
- **行政聚落等级**：S 特大都市、A 大城市、B 中等城市、C 小城市、D 镇、E 村/离岛聚落。等级取决于规模、人口密度、产业与交通需求，而不只由行政名称或人口决定。
- **市内线路层级**：仅该城市真正备案的运营地铁线、实际地铁站、换乘关系。公交、轻轨、有轨电车、普通铁路和步道放在其他交通图层，不得偷换成地铁。
- **地点/场景层级**：从站点进入地铁站局部场景，再通过独立「站点周边地点」规划去校园、商场、住宅、神社等；不把附近建筑冒充地铁站。

**现实尺度参考（不照搬布局）**：东京 Metro 运营 9 条线、180 站（https://www.tokyometro.jp/lang_en/corporate/enterprise/transportation/conditions/index.html）；福冈市地铁运营 3 条线（https://subway.city.fukuoka.lg.jp/eng/route/）。这说明大都会与中型城市的线路密度应该不同。

- **后续地域：更远的山地、农业带、海岸线和群岛**：按剧情和交通连通性扩展，不在第一版随意添加数十个未命名假城市。

「大世界」指世界在逻辑上有**多个真实独立的城市行政与交通系统**；不等于在一屏画全城地铁。区域总图可切换到选定城市，每座城市只有自己的城市地图。

## 6. 地铁站表与场景继续建设的刚性验收

1. **先定区域/城市等级**，再定各城市地区结构、实际通勤走廊、线路数量，最后为每条线编制按顺序的独立站点 ID、站名和换乘关联；这一步不先画任何局部场景。
2. 每个地铁站未来有固定 `stationId`、`cityId`、`districtId`、`name`、`servedLineIds` 和预留 `sceneId`。相邻站之间具备轨道边，换乘通过同一物理车站关联，不用重复 ID。
3. 线路编号和城市 ID 命名空间隔离；地铁寻路严格限制所选城市。跨城只能到真正的城际换乘节点，不允许在地铁图上跨市瞬移。
4. 独立站数与「各线路停站出现次数之和」必须分别统计；有换乘才会有重复，不要为了凑站数重复造同名站。
5. 每条实际运营线路往返可达、没有孤立站、无自行交叉伪换乘，无不合理空白站段。不能用 `world-atlas.js` 旧自动生成的编号示意站冒充正式运营地铁。
6. 地铁站的可用性与附近校园、商店营业时间**解耦**；末班车时刻、检修和剧情封锁才应影响运营。
7. **状态分开**：`planned`（规划容量）、`authored`（已编制线路站表）、`operational`（游戏真实可登车）、`sceneReady`（局部场景可进入）。霧浜 70 站已经成为真实站点节点、乘车/下车可寻路，但不因此宣称 70 套独立站点场景已完成。
8. 每个站点未来对应自己可进入的局部站台/站厅场景；这轮只预留数据标识，不绘制站台或每站场景。
9. 地图放大后读站名、缩小后读线网；大城市线路规模不能通过压缩成小小的示意画凑数。性能上每城网络分包、站名标签视窗裁剪和渐进加载，不能一次渲染大世界所有车站。
