## 2. 当前已经明确的基础（从既有规则与已表达意图整理）

1. **两种世界**：表世界保留正常城市、学校、工作、社会关系；普通人在表世界不使用里世界强化；夜间另有危险的环形里世界。
2. **入夜规则**：被选中者 22:00 仍清醒则被强制带入；22:00 前正常睡着可以避免当晚进入。日历、其他人和怪物压力不会因为主角睡觉而暂停。
3. **长期危机**：怪物持续积累；普通清剿只缓解库存，需逐环推进并处理 Boss 级问题，长期放任最终溢出现实。怪物主动攻击清道夫是既定设计方向。
4. **社会演进**：前期异常作为城市流言/事故隐于日常，随游戏日期逐步引来公开研究、新闻、政府应对，后期可能进入全民危机。
5. **女主角色特点**：冷淡、毒舌；对怪物无惧且享受战斗。SAN 初始 50，下限 50，上限 100，有效击杀上升，非战斗不自动回落。她不需要被强加悲惨童年或救赎愿望。
6. **日常叙事入口**：手机有女二未接来电与催交作业消息；可出门前往学校、商店、兼职等地点。日常不应一开场就堆砌怪物信息或廉价跳吓。
7. **女主 × 女二关系与手机合影**：两人关系非常好，属于非常亲密的好友；女主手机封面/背景是两人合影，作为既有生活关系与后续天使交易的情感锚点。合影图片尚未在手机资源库确认，不能写成已上线。

## 3. 已有“开场设计意图”和当前代码的区别

- **完整游戏的既有开场意图**：先进入里世界的肉鸽战斗冷开场；若首次死亡，**真相是灵魂入天使金币库、现实失踪多年**，女二未来为救她交易并将继任；通过**拟议的复活＋时间倒流**回到卧室日常。也允许高水平玩家无死亡直接通关里世界（极难）。当前代码仍是简化展示，不代表真实多年时间线已做成游戏。
- **当前网页实际表现**：战斗冷开场、多年后剧情和回溯均未完成；新游戏直接从卧室醒来，`site/game/story-content.js` 只有少量占位对白，此外是简单地点进入对白。
- **需协同解决的叙事差异**：V5 世界总纲旧的「序章晚上十点：白天日常后首次召回」骨架，与「先里世界战斗、首次死亡回卧室」的实际计划存在顺序与因果解释差异。先由用户审定新开场，再回写总纲，不能暗中认定其中之一为最终故事。

## 4. 我们要共同写的正式剧本层级（仅目录规划）

- **A. 故事圣经**：确认过的事实、世界运作真相、玩家初期可知的信息、禁止提前剧透的内容。保留事实/提案/待定三级。
- **B. 主线结构**：开场、现实第一天、首次调查、环层突破、逐步公开的社会事件、终幕与结局分歧。具体事件及章节数量待议。
- **C. 人物线**：每人当下欲望、白天真实生活、夜间/交易立场、与主线的关系、个人弧光、支线结局。不能给所有人安排同一种悲剧。
- **D. 城市恐怖支线**：地铁、学校、山林、公路、隧道、乡村、废弃村庄等地点可做互相关联的都市怪谈；调查 → 证据 → 人物选择 → 后果，不能只填满地图图钉。
- **E. 可实装场景脚本**：每个场景有唯一 ID、进入条件、时间/地点、出场角色、镜头/音效/对白、选择、状态变化、手机消息、可跳过规则、复访差异及测试要求。
