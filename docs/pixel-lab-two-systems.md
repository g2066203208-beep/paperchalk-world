# Pixel Lab｜两个系统，一套游戏美术标准

2026-10-30 整理规范。此处是结构契约，不是模型质量已经达到最终目标的声明。

## 唯二主系统

### 01 真像素转换（REPIXEL / Conversion）

**输入**：已有角色、场景、道具的草稿/伪像素图像。

**输出**：固定逻辑像素网格上的原生 PNG；当前默认 D「雾樱玻璃」，精确四色
`#393657`、`#F2A5C2`、`#A9BAE9`、`#FFF5E6`。

**处理**：合法色彩映射 → 区域投票 → 原生像素输出 → 网格采样/检查 → 导出。
神经去噪模型在同一类别下研发；**如果模型不优于保真规则，就不替代规则输出**。

**必要验收**：原生网格尺寸、精确 RGB 数量、Alpha、逐格取色、网格开关不污染导出、角色构图保持，以及人工视觉检查。误差、边缘或细节质量不能仅凭“四色正确”宣称完美。

对应：
- 前端：`site/pixel-lab/repixelize.html`（唯一转换工作台）
- 公共检查器：`site/pixel-lab/repixel-inspector.js`、`site/pixel-lab/native-grid.js`
- 算法：`ml/repixelize/engine.py`（规则转换）、`ml/repixelize/train.py`（同作品噪点模型实验）
- D 样本：`ml/repixelize/publish_d_standing.py`、`site/pixel-lab/d-standing.html`（转换样本/验证页，不是第三个主系统）

### 02 像素绘画学习（LEARN / Asset Creation）

**输入**：版权清楚、标注清楚的像素样本，角色/场景/道具设计图及人工认可的原创资产。

**目标**：模型先学习轮廓、像素簇、构图、尺寸、调色板和大色块布局；再逐步生成符合统一 D 风格的游戏资产。
细分类别：人物、建筑与自然场景、道具、角色动作/动画。

**当前阶段**：真实运行小型 16×16 像素补全、角色样本/潜变量、描画策略与 4 色实验。这些不能等同已经会原创绘制优质人物立绘、完整场景或成套游戏资源。

**阶段性质量门槛**：合法样本 → 训练/留出集区分 → 生成示例 → 固定尺度与四颜色 → 人工对比参考母版 → 场景内显示 → 采纳或退回。制作角色先定义人设和服装整体形状，避免随机堆砌装饰。

对应：
- 前端：`site/pixel-lab/learn.html`（唯一绘画学习入口）
- 训练：`ml/train.py`、`ml/train_characters.py`、`ml/train_flat4.py`、`ml/train_rl.py`
- 原有浏览器样本：`site/pixel-lab/characters.html`、`flat4.html`、`flat4-learning.html`、`flat4-redraw.html` 等属于内部子工具，不是独立主系统

## 留下、合并、收起

| 处理方式 | 内容 | 原因 |
| --- | --- | --- |
| 保留主入口 | `index.html` 只有 01 / 02 | 避免十几个主页入口混乱 |
| 合并到 01 | 上传、四色转换、网格、PNG、D 站姿样本、去噪试验 | 全部服务“变成真正的原生像素” |
| 合并到 02 | 数据集、角色/道具/场景研究、像素补全、VAE、强化学习画笔 | 全部服务“学会创作游戏资产” |
| 保留但收起 | 过去的编辑器、母版、报告、30 套候选配色 | 兼容之前网页和训练记录，避免删除有效成果 |
| 不新增 | 每个角色对应一个独立 ML 主系统 | 新角色只是一个资产或测试样本 |
| 不宣称 | “完美像素”和“已经会画专业游戏美术” | 当前测试只证明技术条件，不证明审美达到目标 |

## D 风格统一验收

- 目前批准的默认风格：**D 雾樱玻璃**。30 套候选仅做对照研究，不自动切换正式游戏风格。
- 色板严格是四种精确 RGB；无渐变、无额外色、无半透明。
- 立绘呈现帧 384×512 是当前验证规格；游戏中的具体角色、建筑和道具像素尺寸应另行根据游戏摄影机/瓦片比例定标，不能将所有资产都强塞进同尺寸画布。
- 正面自然站姿、足底落地、结构完整、服装大色块统一，不随意堆装饰。
- 放大检查器每一格对应源 PNG 的真实一个像素；网格默认开，显示层与导出分离。
- 最终须和原有风格母版放在同一游戏画面比较，人工决定是否通过美术质量。

## 防止功能再次膨胀

新实验先回答：它服务 01 转换还是 02 绘画学习？归属明确后才可进入已有工作台。单个算法或单张图片不能再创建第三个主系统。
