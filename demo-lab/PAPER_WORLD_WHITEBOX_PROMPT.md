# 贺卡式白纸游戏转场 Demo —— 详细制作提示词

## 一、核心目标

制作一个用于横版 2.5D 游戏的“贺卡式翻页转场 Demo”。这不是折纸教程，不是纸机械模拟器，也不是一堆纸条扫屏。整个转场必须让玩家在第一眼就理解：**眼前的城市是一张立体贺卡封面，触发后封面整页翻开，里面藏着另一个地铁世界；内页随后像立体贺卡一样弹起成立。**

唯一需要现实中“像纸”的，是材质、厚度、边缘、阴影、翻页语言和层级关系。动作不需要满足真实纸工程。游戏镜头、人物可读性、节奏和画面冲击优先。

Demo 阶段全部使用暖白卡纸、灰白纸背、深灰切边、石墨色印刷线和暖白灯光。不要正式城市贴图，不要彩色霓虹，不要粒子，不要全屏淡入淡出。唯一保留正式素材的是游戏主角，用来判断真实比例、遮挡、镜头和转场是否成立。

---

## 二、必须形成的画面关系

### 1. 0%：一张“合上的城市贺卡”

玩家仍然处于正常横版游戏镜头。人物站在稳定的游戏地面上，角色世界坐标不受转场影响。

人物后方是一张尺寸足够大的白色卡纸“封面页”。城市天际线、楼房、商店、窗户、路沿等全部作为浅浮雕纸卡贴在这张封面上。它们不是独立乱飞的场景对象，而是在视觉上明确属于**同一张城市封面**。

封面页后面存在地铁内页，但必须完全被遮住。玩家在 0% 绝对不能提前看到柱子、长椅、站牌、地铁墙或灯光。

封面底部必须有明确但克制的折线/纸边，让玩家潜意识知道这是一张可以翻开的卡片。折线不需要做成工程图，只要纸张厚度、边缘和阴影能读出来。

### 2. 8%—25%：封面开始翻

触发后，封面沿底部水平折线开始整页向后翻。不要先让建筑散开，不要让楼房单独旋转，不要让地面飞走。**第一视觉信息必须是“一整页正在翻”。**

25% 时，封面约翻开 25%—30%，从游戏镜头看应明显出现透视变化：封面上缘开始向后退，纸页厚度和背面逐渐可见，城市纸景随着整页一起改变透视。

主角继续站在前景，绝不能跟着封面旋转。角色脚底接触阴影不变，地面仍保持可行走的游戏坐标。

### 3. 25%—50%：内页第一次露出

封面翻到足够角度后，后方的地铁内页才开始显现。不要让地铁像普通 3D 场景平移进来。必须让玩家感觉“它原来就在贺卡里面，只是刚刚被封面盖住”。

50% 是整个转场最关键的一帧。要求：

- 城市封面仍在画面中，处于明显的翻页中段；
- 能看到封面纸背；
- 地铁内页已经露出一部分；
- 地铁的第一排纸墙刚开始立起来；
- 角色仍然清楚位于前景；
- 不能有大块物体遮住角色脸和身体；
- 画面同时具备“旧页正在离开”和“新页正在出现”的信息。

这张 50% 截图如果不好看，整个转场都不算通过。

### 4. 50%—75%：立体贺卡弹起

封面继续翻到画面后方并退出主要视线。地铁内页正式接管画面。

地铁场景内部采用分层弹起：

第一层：后墙 / 站台大背景；
第二层：柱子 / 站牌结构；
第三层：长椅 / 售票机 / 路线牌；
第四层：灯与列车提示。

这些元素可以像立体贺卡一样从接近水平或压低状态逐渐站起，也可以加入少量 scaleY 和轻微 overshoot。不要追求真实 V-fold、纸铰链和结构力学，只需要让视觉上有“从平面卡纸里立起来”的感觉。

每层之间保持 40—90ms 的节拍差。大结构动作更稳，小物件动作稍快、稍有回弹，但不要随机乱抖。

75% 时，地铁已经基本成立，封面页不应再占据主要画面。

### 5. 75%—100%：灯光完成贺卡

结构基本完成后再亮灯。中心灯先亮，左右依次展开。灯光是最后的“生命信号”，不是拿来遮掩转场的手段。

最终可以让远处列车白纸轮廓轻微进入，或者仅出现车窗深色带作为远景信息，但不能抢走角色和场景主体。

100% 的画面应该像“一张完全打开的立体贺卡”：人物站在正常游戏地面上，后方是完整展开的白纸地铁空间；城市封面已经翻到视线外或折在后方。

## 三、游戏镜头规则

默认必须使用正式游戏接近的横版透视镜头，FOV 约 34°—38°。角色始终处于画面中央偏下。

禁止为了展示翻页而做环绕相机、模型展示转台、360° 镜头。转场过程中相机最多允许做非常小的纵向或景深补偿，目的是维持角色和新场景构图，不是制造炫技效果。

必须额外提供一个 Breakdown 检查视角，仅用于调试页面角度和弹起层级。这个视角绝不能作为默认展示效果。

---

## 四、人物规则

使用项目真实 protagonist.webp。

人物在 0%、25%、50%、75%、100% 五个关键帧中都必须完整、清晰、没有被大面积纸页挡住。

人物不跟着封面翻、不瞬移、不漂浮、不被强制放到特殊“机械舌片”上。游戏逻辑上人物一直处于正常世界坐标，转场只是围绕人物发生的视觉场景页切换。

接触阴影一直存在，用来判断脚底有没有漂浮。

## 五、大地图 / 很多场景的扩展方式

不能让整个城市地图一起翻页。

世界仍按 chunk 分段，例如每 18 个世界单位一个 chunk。玩家当前所在 chunk 才生成完整的“贺卡转场单元”：城市封面页、地铁内页和 pop-up 细节。

左右邻接 chunk 仅展示低成本白纸代理。大量重复楼房、背景块和路面使用 Three.js InstancedMesh。官方文档明确指出，InstancedMesh 适合大量相同几何和材质、不同变换的对象，可以减少 draw calls，因此用于邻接块最合适。

玩家跨 chunk 后，只把新的当前 chunk 提升为高细节贺卡单元，旧 chunk 降回代理。角色世界坐标不变。

Demo 必须提供角色 X 滑杆，并实时显示：
- 当前 chunk；
- 邻接代理数量；
- renderer draw calls。

验收要求：把角色从 chunk 0 拖到 chunk 2 后，高细节贺卡单元正确跟随；邻接代理仍保持固定数量；draw calls 不随地图长度线性增长。

## 六、Three.js 技术实现建议

### 1. 封面页
使用 THREE.Group 作为封面 pivot，pivot 位于封面底边。封面和城市浮雕都 parent 到这个 Group。整个转场最重要的动作只有：

coverPivot.rotation.x

封面 BoxGeometry 使用正面暖白、背面略灰、边缘深灰的多材质结构，让翻页中段可以清楚看到纸背和厚度。

### 2. 内页
内页是一张固定在后方的卡纸面板。开始时通过遮挡关系完全藏在封面后面，不需要透明度淡入。

封面翻到足够角度后才设置 innerPage.visible = true，让新场景像被真正揭开。

### 3. Pop-up 层
地铁墙、柱、道具分别放在多个 pivot Group 中。从接近水平/压低状态过渡到竖直状态。只要视觉成立即可，不要求真实纸工程。

### 4. 大地图代理
使用 THREE.InstancedMesh 渲染邻接 chunk 的重复白纸建筑和路面。实例只更新 matrix，不给邻接块创建完整动画对象。

### 5. 时间轴
当前 Demo 使用一个 0—1 的统一 progress，分别驱动：
- cover
- innerReveal
- backWall
- columns
- props
- lights
- settle

结构思想可参考 Theatre.js 的高精度属性 choreography：一个统一时间线驱动多个属性轨道。但当前 Demo 不必引入额外依赖。Theatre.js 的 core 采用 Apache-2.0，可作为以后复杂镜头/场景编排的备选。

### 6. Clipping / stencil
如果以后要做更高级的纸边切开、局部翻页或“页面只在某条边后出现”，可参考 Three.js 官方 clipping / stencil 示例。但这一版贺卡 Demo 首先靠真实 3D 遮挡关系完成，不要过度复杂化。

## 七、明确禁止

- 禁止纸条扫屏；
- 禁止多张巨大白板横向穿屏；
- 禁止城市建筑各自乱飞；
- 禁止全场景同时统一旋转；
- 禁止把转场做成真实折纸/纸机械教学；
- 禁止 V-fold 工程结构成为画面重点；
- 禁止整张地图一起翻；
- 禁止人物跟着页面翻；
- 禁止黑屏；
- 禁止 fade to black；
- 禁止白闪；
- 禁止粒子爆炸；
- 禁止强 motion blur；
- 禁止 0% 提前泄露地铁；
- 禁止 50% 已经把封面完全翻完；
- 禁止 50% 看不懂旧场景与新场景的关系；
- 禁止只看测试不看截图。

## 八、自动验收

CI 必须自动生成：
- 0% 城市封面；
- 25% 开始翻页；
- 50% 内页露出；
- 75% 地铁弹起；
- 100% 完全打开；
- chunk 2 大地图截图；
- 50% breakdown 检查截图。

浏览器测试必须验证：
- 真实人物已经加载；
- 0% inner page 不可见；
- 25% cover rotation 已达到明确翻页角度；
- 50% cover 仍存在且处于中间角度；
- 50% inner page 与第一层 popup 已出现；
- 75% cover 已退出主要画面；
- 100% popup 全部稳定；
- 灯光完成；
- chunk 2 切换成功；
- 邻接代理固定；
- draw calls 保持有界。

每次版本只有在**实际下载并查看关键帧截图**后，才允许标记为可看 Demo。
