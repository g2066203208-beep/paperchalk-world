# Paper World 白纸游戏转场 Demo —— 详细制作提示词

## 总目标

制作一个**真正用于横版 2.5D 游戏的“白纸世界转场 Demo”**。这不是纸艺机械模拟器，不要求现实中真的能够折出来，也不要求每一个物体都有真实铰链、V-fold、支撑杆或结构力学解释。唯一目标是：玩家在正常游戏镜头里看到这一幕时，会自然地相信“这个世界就是纸做的，所以场景会用纸的方式发生魔法般变化”，并且人物始终清楚、镜头舒服、节奏高级、转场不会打断游玩感。

整个 Demo 暂时**只使用白色/暖白色纸张、灰色切边、石墨色印刷线、真实阴影**。不要正式城市贴图，不要彩色建筑，不要粒子堆砌，不要发光科技感。唯一允许保留正式素材的是主角纸片角色，用来判断真实游戏比例、遮挡、镜头构图和场景变化是否压住人物。白纸阶段都不好看，绝对不能进入正式美术。

## 核心艺术方向

参考 Media Molecule 的 Tearaway：纸张不是一张贴在 3D 模型上的纹理，而是整个世界共同遵守的视觉语言。纸可以折、卷、滑、压扁、撕开、层叠、像卡片一样从景深中站起来，也可以做现实纸张无法完成的连续变形。不要把“真实纸工程”当规则，**纸感是视觉规则，不是物理规则**。

参考白卡纸建筑模型、白色 pop-up prototype 的优点：没有颜色以后，玩家仍应仅靠纸张厚度、切边、折线、阴影、层级关系和前后遮挡看懂空间。所有白纸表面保持哑光、高粗糙度；正面略暖白，背面略灰；切边比正面深 15%—25%；不要塑料高光，不要金属反射，不要布料质感。

## 游戏镜头

默认必须是实际横版游戏镜头，不是模型展示镜头。使用与正式游戏接近的 36° PerspectiveCamera，角色位于画面中央略偏下，摄像机只允许在转场过程中做非常轻微的纵向/景深补偿，不做大幅推拉、不环绕、不炫技旋转。转场真正的主角必须是“世界自己变化”，而不是摄影机替玩家转场。

主角的世界坐标在整个转场中保持不变。不要为了合理化纸片结构强迫角色站在特殊机械舌片上，也不要让角色跟着地面翻飞。游戏坐标系统优先：旧场景和新场景可以共享同一条 gameplay ground Y，视觉上通过背景、前景、光影、纸层和镜头轻微偏移制造“从城市进入地下”的感觉。

## 城市 → 地铁的转场节奏

总时长控制在约 1.35—1.55 秒。必须一气呵成，不出现黑屏，不 fade to black，不白闪，不使用全屏 UI 遮罩。

**0%—15%：保持与预备。**  
玩家进入触发区后角色输入短暂锁定，但角色仍有呼吸/待机。城市不要立刻消失。最靠近玩家的纸片建筑先产生非常轻微的“脱离景深”动作：向 Z 轴错开 0.1—0.3，像舞台卡片开始松动。地面边缘出现一条极淡的纸张切边高光，告诉玩家世界即将变化。

**15%—40%：城市纸景散开。**  
不要整张城市一起折。近景建筑以玩家为中心向左右两侧错开，类似纸卡被一只看不见的手快速拨开；中景建筑向后压扁并稍微缩小；远景天际线向上滑并压缩成几层白色纸带。不同层的动作方向不同，产生“纸片景深被重新洗牌”的感觉。每层有 30—80ms 的错峰，禁止所有物体同步运动。

**25%—55%：主纸影掠过。**  
一张宽大的白纸带从画面斜后方快速穿过，不是为了模拟真实翻页，而是作为视觉节拍。它应该像纸张在舞台上扫过，短暂遮住部分旧场景，但始终不要完全遮住角色。纸带经过时让旧城市的剩余部分在其后消失，让新场景的第一层轮廓在纸带前方出现。可以使用 Three.js clipping plane / stencil 或几何遮挡实现，不能用纯 HTML 蒙版。

**35%—72%：地铁场景从景深中建立。**  
地铁不是从地下机械升起来，而是像插画分层一样从 Z=-8 到 Z=-2 逐层进入。先出现最远的后墙和隧道轮廓，再是柱子与站牌，再是长椅、售票机、灯箱等中层元素。每一层同时带一点 Y 方向上移、scaleY 从 0.82 到 1 的“纸卡站起来”感觉，但不追求真实折叠。左右元素可有相反的微小旋转，增强手工舞台感。

**55%—85%：细节接力。**  
不要一次性显示所有道具。长椅、站牌、售票机、柱子、轨道边缘以 40—70ms 间隔依次进入稳定位置。小物件允许有 3%—6% 的轻微 overshoot，大建筑仅 1%—2%。这种差异代表“轻纸片比大纸板更活”，但不需要物理模拟。

**76%—100%：灯光与完成。**  
场景结构已经基本完成后，灯光才成为最后一个节拍。白纸环境中只允许暖白灯，不出现彩色霓虹。先亮玩家附近的一盏，再向左右各自传播。最后远处隧道出现两点很弱的列车灯或列车轮廓，作为“新场景开始活起来”的信号。角色从头到尾保持可见；完成时恢复玩家控制。

## 大地图与很多场景的实现方式

绝对不要让整张大地图参与转场动画。世界采用**分块 + 局部舞台窗口**。

把横向世界按固定宽度切成 chunk，例如每格 16—20 世界单位。玩家当前所在 chunk 为高细节 Active Cell，左右各 1 格保留中等细节，左右第 2 格只保留低成本轮廓，再远直接卸载或休眠。转场动画只操作 Active Cell 中的“可视舞台层”，不会影响几百米外的场景。

大量重复建筑、窗户、路灯、柱子使用 Three.js InstancedMesh，共享 BufferGeometry 和 Material，降低 draw calls。高细节 Active Cell 可以使用普通 Mesh 以便独立动画；邻接块只展示不可交互的静态代理。玩家跨过 chunk 边界时，只切换哪一格被提升为高细节，世界坐标本身不改变。Demo 必须提供角色 X 坐标滑杆，能从 chunk 0 移到 chunk 2 或更远，并显示当前 Active Cell、邻接代理数量和 renderer draw calls，证明方案能扩展，而不是只做一间小舞台。

## 技术约束

基础渲染继续使用项目已有的 Three.js，不新增大型框架。可参考 Three.js 官方 clipping/stencil 示例做纸带局部遮挡；重复纸片物体使用 InstancedMesh；动画使用轻量属性时间轴函数，结构上参考 Theatre.js 的“一个进度驱动多个属性轨道”的思想，但 Demo 运行时不强依赖 Theatre.js。角色继续使用项目真实 protagonist.webp，并保留 alphaTest、纸片阴影和接触阴影。

所有 Demo 状态必须可确定性复现：0%、25%、50%、75%、100% 五个关键帧相同输入必须得到相同画面；提供 0.25×、0.5×、1× 播放；提供逐帧前进后退；默认关闭调试折线，只在需要检查层级时打开 breakdown 模式。

## 明确禁止

禁止把场景做成真实纸机械教学模型；禁止满屏铰链、V-fold、工程线；禁止为了“真实”牺牲人物和构图；禁止大块纸板永久挡在镜头前；禁止新场景一开始就露出来；禁止整张地图一起运动；禁止所有建筑同时统一旋转；禁止黑屏、全屏淡入淡出、白闪、粒子爆炸、强 motion blur；禁止塑料材质；禁止正式美术颜色污染白纸阶段。

## 验收标准

第一眼必须像“游戏里的白纸世界正在变形”，而不是“3D 模型在播放机械动画”。主角在五个关键帧中都要清晰可读，任何纸片不得长期遮住脸和身体。25% 能明确看出旧世界正在散开；50% 必须同时看到旧城市残留与新地铁层级建立，是最精彩的一帧；75% 新场景基本成立但仍有细节接力；100% 构图稳定、角色落在新场景中，且画面仍是纯白纸原型。

Demo 完成前必须自动生成游戏视角 0/25/50/75/100% 五张截图，以及至少一张玩家移动到远处 chunk 后的截图。必须实际检查这些截图后才能宣布“可看版本”。

## 参考与开源技术

- Media Molecule / Tearaway：纸世界作为统一视觉与交互语言，不把纸仅当材质贴图。
  https://www.mediamolecule.com/games
  https://blog.playstation.com/archive/2012/08/14/media-molecule-presents-tearaway
- 白卡纸 pop-up prototype：仅参考白模层级、纸边与阴影的可读性，不照搬真实机械。
- Three.js InstancedMesh：大规模重复纸片建筑/窗/灯具实例化，降低 draw calls。
  https://threejs.org/docs/pages/InstancedMesh.html
- Three.js clipping / stencil：用于局部纸带扫过、切开、揭示新层级。
  https://github.com/mrdoob/three.js/blob/dev/examples/webgl_clipping_stencil.html
- Theatre.js Core：参考高精度属性时间轴编排思想；Core 为 Apache-2.0。
  https://github.com/theatre-js/theatre
