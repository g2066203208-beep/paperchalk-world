# 小杂货店实机界面与演出设计 v1

更新时间：2026-10-27。依据用户在主菜单验收后的明确设定。本文是待实施设计，不能把列出的规划功能当作已完成。

## 一、必须保持的设定

1. 开局是一间小小的杂货店：一处服务窗/店门、一张操作台、有限货格、少量商品。画面要有真实营业的生活感，规模增长必须靠玩家经营取得。
2. 主菜单展示存档中的**当前店面**。扩建、装修、摆设、营业项目、换店均改变主菜单；禁止把冬季窗口效果图永久固定成与存档无关的片头。
3. 菜单与实际经营属于同一家店、同一个场景定义。菜单是店外/窗前的观察视角；经营是操作台后的工作视角。
4. 继续采用用户认可的棚布、公告纸、柜台、顾客与店员互相回应的构图关系。画风为统一扁平色块、硬边阴影，角色五官沿用指定参考的画法，但所有身份、发型与服装原创。
5. 所有人物先制作完整全身透明母版，再制作动作/表情与遮挡层；窗口和柜台不能成为只生成半身稿的理由。
6. 主要玩法是持续拓展**真正不同的新业务**，目标支持数百至数千类扩展。商品换名称/换颜色不算新业务；每项业务必须有操作、设施、成本、收入与容量/服务限制。
7. 场景可交互物要丰富。操作依附真实物件，信息随人物、票据与设备出现；不能把几十个功能堆成浮动按钮或底部提示条。
8. 演出必须由真实状态触发，表现拿起、放下、开关、交接、付款、补货、顾客反应；不能靠整张人物立绘反复上下漂移冒充营业过程。
9. 保留 1–4 人同店协作、房主权威、旧存档可继续、APK 联网获取最新网页资源与横竖屏适配。

## 二、开局画面的实际组织

### 2.1 店内主视角

玩家从操作台后看向服务窗。顾客是中上方的视觉中心；货架、吊柜、抽屉和台面形成围合的小空间。外面只露出一小段街景和排队者，不在开局摆出大型便利店、餐饮区或多房间。

| 区域 | 初始内容 | 作用与显示原则 |
|---|---|---|
| 窗外与门口 | 一位正在服务的顾客、后续等候位置、窄街景 | 顾客有到达/停下/交谈/接货/离开连续动作；队列不能压住当前顾客气泡 |
| 服务窗口 | 窗闩、独立窗扇、窗台、营业牌 | 开关确实改变窗口开口、风声与对话可达性；营业牌可翻面 |
| 两侧小货架 | 左右各三层，可见的有限库存 | 每件物品对应实际格位；拿走后出现空位，补货真实填回，不画假库存 |
| 吊柜与抽屉 | 左右吊柜、左右抽屉 | 门板/抽屉为独立对象，打开露出内容，关闭遮挡内容；内部货物不能穿过关闭的门操作 |
| 操作台 | 交接垫、钱盘、少量日常摆件 | 交接垫同时只有规则允许的物件；钱与物品不允许重复复制 |
| 后勤角落 | 小进货本/货单、储物位、尚未启用的位置 | 用实际票据说明补货；未解锁设施不提前塞满画面 |

与现有原型的映射：`FIXTURES` 已有六层货架、两个吊柜、两个抽屉；`GOODS` 当前为热茶、面包、电池、可可。它们是首轮设计的起点，不表示商品和业务已经足够完整。

### 2.2 手机竖屏

上部保留顾客、服务窗和气泡；中部是货架与主要交接区域；下部是操作台前缘、抽屉、钱盘等实物。不能把桌面横屏全景等比缩小到字和物件都点不准。可对左右货架做轻量视角移位，切换手势不得与拿取冲突。当前订单气泡能在保持当前顾客可见时收短，不作为固定底栏。

### 2.3 手机横屏

增加左右可见空间，顾客保持正常人物比例；两侧货架更容易同时操作。不能通过拉宽脸、压矮柜子来填满屏幕。横竖屏共用同一店铺和库存状态，旋转不重开营业、不重置动作。

## 三、操作设计：丰富但有清楚的主次

以下分为首轮必需与后续扩展。首轮不把后续设施全部展示为可用。

| 对象 | 输入 | 状态变化 | 对应演出 | 阶段 |
|---|---|---|---|---|
| 窗闩 | 点按 | 开/关 | 手接触窗闩、窗扇沿铰点运动；关闭有止动 | 首轮 |
| 窗扇 | 与窗闩联动 | 开口与遮挡变化 | 街景只经实际窗口可见，窗框遮挡人物下缘 | 首轮 |
| 营业牌 | 点按/翻面 | 营业/休息申请 | 牌子转动，队列与顾客等待行为响应 | 后续，不能先做假开关 |
| 顾客 | 点按 | 交谈、显示需求 | 视线转向玩家、张嘴/停顿、角色旁气泡 | 首轮 |
| 正在递出的商品 | 点按 | 接收/撤回，按权限验证 | 顾客手向前，物件沿交接路径移动 | 首轮 |
| 货架商品 | 点按 | 格位数量减少、进入玩家手持 | 从真实格位离架，手跟随抓取；原位置露空 | 首轮 |
| 原货格 | 手持时点按 | 合法归还 | 原物件回位；格满或不同 SKU 有就地阻止反馈 | 首轮 |
| 货架/打开的柜内货格 | 长按 | 准备补货 | 在该位置出现小货单/进货本，不出现远处浮动按钮 | 已有规则，需完善演出 |
| 空货格 | 带补货选择点按 | 购买并占位 | 外箱拆开/补货落位；钱与库存只结算一次 | 首轮 |
| 吊柜门 | 点按门把 | 开/关 | 按铰链旋转，开合速度有起止，不是瞬间贴图互换 | 首轮 |
| 抽屉 | 点按把手 | 拉开/合上 | 抽屉沿滑轨前后移动，内部物件随抽屉整体移动 | 首轮 |
| 交接垫 | 手持时点按 | 手持→台面 | 放下、接触、轻微回弹，阴影与遮挡相应变化 | 首轮 |
| 台面商品 | 空手点按 | 台面→手持 | 从商品位置抓取；多人同抢只允许一人成功 | 首轮 |
| 钱盘 | 交易满足条件后点按 | 结算 | 顾客递钱、钱落盘、商品交出、零钱找回 | 首轮；先与既有收款规则一致 |
| 错误商品 | 顾客确认时 | 不扣错货/按既有规则处理 | 顾客看商品、轻推回或摇头，气泡说清需要什么 | 首轮 |
| 订单已缺货 | 顾客/进货本 | 显示缺货与补货途径 | 指向空货位，玩家可请求稍等；不自动生成商品 | 后续完整订单调度 |
| 货单/进货本 | 点按 | 查看进货选择/成本 | 本子在台面翻开，条目可滚动，关闭回到原位置 | 下一阶段 |
| 钱盒/收银抽屉 | 交易触发/点按 | 开合/查看 | 盖板打开与硬币声，实际余额与票据对应 | 下一阶段 |
| 票据 | 点按 | 查看订单/价格/记录 | 票据从机器/夹子取出，文字实时排版 | 下一阶段 |
| 客人留下的小纸条 | 点按 | 查看/收起/保留 | 顾客放下后才可查看，收起进入实际保存位置 | 后续 |
| 回收收纳位 | 回收业务已解锁后操作 | 接收/入柜/批次转运 | 顾客递旧电池，玩家接住，放到指定抽屉，批次取走 | 已有业务规则，需完整演出 |
| 新业务设施 | 解锁后摆放、点按 | 开办/操作/升级 | 真实增加一个设备、位置与操作链，改变店内与店外展示 | 后续 |
| 装修/扩建牌 | 点按实际工单 | 展示费用与改造内容 | 选择后先预览可复原方案，再提交权威交易 | 后续 |
| 送货箱 | 到货时点按 | 拆箱、暂存、上架 | 箱子出现→开封→取出→逐件入格，有容量与占用 | 后续 |
| 街上排队者 | 非当前服务时 | 旁观/有限交谈 | 不越过当前顾客直接完成交易，等待姿势有变化 | 后续 |

交互数量不能只靠增加点击次数。每个对象至少要回答：玩家为何操作、权威状态改了什么、其他玩家能看见什么、失败如何就地说明。

## 四、首轮演出清单

### 4.1 一次真实交易

顾客走近 → 停在服务点 → 看向店员 → 说需求 → 玩家从具体货格取货 → 拿到台面 → 顾客视线落到商品 → 正确时接货/付款，错误时退回/解释 → 店员收款/找零 → 顾客道谢并离开 → 下一位进入。

不能把所有动作同时触发。动作必须有明确接触点：货架抓取点、台面落点、顾客接货手、钱盘落点；同一件物品在任一时刻只有一个归属。

### 4.2 环境持续运动

- 店内：杯口蒸汽、灯具轻摆、窗帘/棚布受风的少量运动；店员视线随顾客/手持物改变。
- 店外：缓慢落雪、路人经过、排队者搓手或换重心。
- 营业反馈：柜门抽屉各自开合、钱币与纸袋落地/落台有接触反馈、收款与票据动作连贯。
- 安静时：人物整理围巾、擦台面、整理一件商品。只在不会改变玩家库存的装饰层做环境演出；影响库存的整理必须走规则。
- 禁止所有物件同频摇动、整个人悬浮呼吸、杯子与握杯手分离、脚底滑行、对不存在的顾客说话。

### 4.3 人物素材要求

每个新人物的交付包含：完整全身母版、睁/闭眼、口型/情绪、至少一种与业务相关的手势、正确的前后发和手臂遮挡关系、支点/接触点。先确认一套人物比例与五官规范，再扩展顾客。主菜单与经营视角使用同一人物身份，不随机换脸。

## 五、主菜单 = 当前店面

### 5.1 需要共享的数据（拟定，不是已接入的字段）

```text
storeProfile:
  storeId / definitionId     当前店铺实例 / 店型
  layoutId / appearanceId   布局与外观
  expansionStage            空间扩建阶段
  fixtures                  设施实例、摆位、开合状态
  decorations               棚布、招牌、灯、陈设等
  businessIds               已开办业务
  revision                  店面配置修订号
```

库存、资金、订单继续使用现有权威模型；不要在菜单复制第二套经济系统。旧 v3 存档没有 storeProfile 时，映射为 starter_grocery 默认配置，保持既有库存/现金/进度。迁移方案实施前必须添加回归验证。

### 5.2 两个视角，一个场景投影

`StoreSnapshot → StoreSceneProjection → menuCamera / workCamera`

- 菜单：显示当前招牌、棚布、店型、已摆设施、业务标识及可见库存的合理外观投影；公告纸只承载进入/联机/设置。
- 营业：显示同一设施、同一格位与库存、同一装修；切入后物件身份连续，不凭转场随机更换摆件。
- 菜单中的营业小演出使用只读预演状态；不产生额外收入、消耗库存、推进顾客队列或向联机发送虚假交易。
- 存档后扩容，菜单应看到真实新增货格；新业务开办后出现相应设备/标识；换店后采用新店完整外观，旧店图不能继续冒充当前店。
- 老店/新店可保留各自装饰与布局。换店是明确交易与状态切换，不是单纯替换背景图。

## 六、业务与成长的节奏

开局先把小杂货店的一笔交易做得可操作、连贯、有反馈，再引入新业务。以下是候选路线，不是已完成内容或已验证数值。

| 阶段 | 店面变化 | 新的操作与经营问题 |
|---|---|---|
| 小杂货店起步 | 现有窄窗口、有限货位 | 取货、交接、收款、补货、容量与缺货 |
| 开办第一项服务 | 增加明确收纳位或小设备 | 如回收：接收、分类、存放、批次转运，区别于零售 |
| 小店扩容 | 真实增加货格/台面/设备位置 | 新设施争夺空间与资金，菜单同时出现扩建结果 |
| 多种邻里业务 | 出现业务专属物件与招牌 | 寄取件、包装、维修等须各有独立操作链，按制作进度逐个验收 |
| 换到更大的店 | 外立面、入口、操作区、容量改变 | 菜单与经营同时更换，原库存和业务迁移必须受规则控制 |
| 后续扩展 | 更丰富店型/设施组合 | 用注册表和业务流程驱动扩展，不能靠几千个名称假装几千种玩法 |

每项新业务的最小定义：解锁条件、设施与占用、输入物、操作步骤、等待/产能、成本、收费、交付物、失败/取消、多人权限、场景演出与升级变化。

## 七、实施顺序与验收

1. **已完成的当前基础**：主菜单原创人物分层、基本联机入口、四种尺寸菜单检查、发布与 APK 构建链路。当前菜单外观仍为固定原型，尚未关联店铺成长。
2. **本轮先提交的设计**：本文件、转场规范、Game Direction 的权威设定更新。
3. **紧接着完善**：开始/继续/返回的镜头推进、公告纸收起与遮挡转场，输入互斥、减少动态模式、不得重置联机。
4. **接入共享店面**：StoreSnapshot 与默认小店映射，菜单与营业读取同一店面；先验证一种扩容映射，再扩展装修/换店。
5. **完善真实营业界面**：逐区域推进窗口→货柜→操作台→手持与交接→顾客；每次以实机画面验收，保持用户确认的风格。
6. **完成一次可玩的营业片段**：一位顾客、一种商品、完整付款反馈、一次补货，再完成双人协作。
7. **新增业务与换店**：每次交付真实设施+操作+盈利+升级+菜单外观变化。

验收必须覆盖：手机横竖屏/刘海与导航区、至少44px触控、长气泡/长物品名称、库存与现金只改变一次、两人同时拿货、联机过程中打开/关闭菜单、转场中重复点击、后台恢复、旧存档与断网单人。


## 第一小店可玩版本（2026-10-27）

已接入：四种商品、六层独立货架、两吊柜和两抽屉、开关营业窗、取放商品、可取回的交接台、独立收银机、点进货簿选商品再摆货、扩架与保温改造、五单打烊结算、下一天与旧存档续玩。邻里委托与旧电池接收→入右抽屉→三节封箱回收使用真实库存和房主裁决。四套原创完整全身顾客母版在窗内自然遮挡。

旧裁图室内渲染已退出实际游玩路径；新室内用独立扁平货柜与商品几何，货架和柜门依据同一库存状态绘制。竖屏使用左右货架；横屏将抽屉移到侧面，交接台留在中间，不再把整个店缩成窄画面。Canvas 逻辑单位直接使用 CSS 像素，DPR 仅提高背板清晰度，点击目标不随分辨率缩小。Android 使用实际内容区域边距避开系统栏，避免 WebView 内边距与网页视口错位。

浏览器验收：320×568 / DPR1、390×844 / DPR3、568×320 / DPR2、844×390 / DPR3、1280×720 / DPR1，均通过真实点击的错货换回、委托、进货补货、回收入库、五单销售、结算、下一天、刷新恢复。另有独立开柜状态触控几何回归，最小 44×44 CSS 像素。菜单四尺寸及转场保留回归。

仍未实现：成长驱动的菜单店面共享投影、搬迁到第二店、大规模新业务。年长顾客已接入嘴/眼/眉的局部说话、微笑和担忧贴片，其余顾客的局部表情与完整动作演出需继续完善，不能把已有入场、交货和离场称作完整角色动作系统。尚无实体 Android 手机验收记录；自动构建不代替实机验收。
