## A. 最终产品，不得改成别的游戏
游戏尚未命名；不再擅自定标题。玩法设定：玩家共同值夜班，经营一间临街的深夜小店。顾客可能是人、受害者、善意说谎者、伪装者，也可能携带引发古怪现象的物品。核心乐趣不是查身份证找拼写错误，更不是《以撒》战斗：**接待、交易、询问、动手检查物件、整合矛盾线索、决定如何应对，行为影响店铺和熟客的后续关系**。
1–4 人同店联机，一人完整可玩；合作必须来自各玩家在多个工作位做出的独立操作及其因果，而非四个头像、共享文字、齐点按钮。反对无成本无限窥探；为误判提供有意义后果和回访。
明确事实与设定的区别：不要把纯随机生成的“伪人特征”当作推理。必须有一致的世界线、店务原始记录、连续人物关系、可调查证物、合理假线索和至少两条可交叉验证的证据链。

## B. 主美与素材生产纪律
上一版二次元厚涂赛博霓虹、一次性合成整个 UI 的生图、僵硬简化的 SVG 人偶，均不视为最终资产。主美用全新、克制、能感知生活细节的街角小店视觉系统，重点是独特剪影、节奏、空间层次与叙事的物件，而非无意义纹理、乱糟糟的饰品、伪造汉字。
- 建立 3 个小型方向探索：生活感手绘扁平绘本 / 现代胶印插画 / 温暖复古的简笔 2.5D；都需可在 390×844 手机保持清晰的 UI。选出一种最可读、最具角色性的一致方向，记录为什么选。方向只是探索，不准照抄特定游戏的 UI/角色。
- 使用 GPTIMG 制作原创高品质像素素材，按角色/商品/柜台/窗户/灯光/街景/动作逐个裁切成透明背景可独立替换精灵；程序化像素仅作为过渡与辅助，严禁把整张概念图铺成游戏。
- assets 分开：店内远景/雨街/橱窗/前景柜台/灯具/货架/各小物件/多套完整顾客角色/表情与手势/UI 框体/可点图标；提供元数据和可复用坐标锚点。角色至少有视线、等待、递物、被拒绝的状态反馈；避免穿模、白边、人物与前景错误重叠。保证屏幕内场景而非满屏文件说明。
- 禁止引入未授权素材、非自有游戏角色；开源参考需核实并记录许可证。

## C. 真正可玩且可测试的多人玩法
1. 游戏由房主权威结算；客户端只能提交顺序化操作，所有动作有 seq/idempotency 去重、防刷和速率限制。网络发送所有动作，不允许后发包覆盖尚未消费的前一动作；加入、退出、断线、房间已满有明确反馈。
2. 多岗位：柜台收银/问询、窗边观察环境、货架物品比对、旧账及电话。每个岗位都必须产生具体的可视化操作或可拿取物件，操作改变后续可用信息、资源或人物反应。多人同步看见店铺结果，但独立的本地调查视图和滚动位置不得被别人的点击覆盖。
3. 每个顾客有稳定身份与关系图；后续对话真实引用前面的决定。设计 12+ 可反复检验的完整事件并加入分支；至少一个「看似伪人实为普通人」和一个「看似正常实为伪装者」，不靠刻板外表决策。
4. 共享线索、提议、改变意见、投票；2 人分歧不可推进且有可执行继续取证路径。每个判决都要保留判断依据、影响街坊信任/物资/危险/后续客人。
5. 从单人 20 分钟连续流程开始做性能、UI、叙事验收，逐步扩展 4 人 30 分钟稳定联机；真人断线后队伍状态可恢复，不重复结算。展示实际两个客户端录像/截图，而不是画一张联机示意图。

## D. 手机端、APK、更新与存档
- Android 竖屏优先，适配 320×640、360×800、390×844、412×915、平板；动态视口/安全区域，系统手势、输入法、字号、屏幕旋转行为都验收。首屏可理解：顾客、操作岗位、线索、动作；全交互目标≥44 CSS px，重大操作需二次确认或撤销窗口。不能为了“手机适配”缩小桌面版到看不清。
- 优先加载最新**网页资源**，提供版本号、更新提示、离线缓存回退。区分代码更新与 APK 壳安装更新：后者由系统要求用户确认；不能承诺普通设备静默升级。
- 本地个人存档必须持久化：版本化 schema、损坏回退、可导出/导入、断线继续、自动保存、迁移测试；线上更新不清理私有存档，不随角色/资产更新改动 storage origin。多人存档由房主保存；客人记录本地个人进度，不冒充同一份多人权威世界状态。
- Android 必须经过 GitHub Actions assembleDebug + 安装测试；正式持续升级要固定 keystore 签名（通过 secrets 配置），不同 CI debug 证书不能当稳定升级策略。请以真实构建产物为准。
