# 每小时执行台账 / Hourly Delivery Ledger

## 2026-10-26 第 1 轮：P0 联机连续点击丢操作修复

**问题证据**：旧版 `RoomNetwork.accept()` 为每位客人用 `Map.set(peerId, newestInput)` 保存最新一次输入。手机连续切换工作位、调查或快速发送操作时，房主 150ms 处理周期内的前一个操作会被覆盖，导致多人 UI、调查进度不一致。

**验收标准**：
- 同一客户端连续发送 100 次岗位操作，房主按照 seq 顺序逐一处理，后续事件不会覆盖前序事件。
- 重复/重放 seq、无效 type 拒绝，不能越权更改房主状态；单客户端最多 128 条、全局最多 512 条待处理，避免恶意队列占用。
- 单元测试验证消息排队、重放保护与内存上限。
- 双 Chromium 390×844 客户端真实 WebRTC 联机，验证 100 连发动作 + 最终岗位同步、共同调查、投票及存档恢复。
- 原有 URL、存档 schema `lampkeep-local-v1`、Android package ID 不变。不能因换游戏方向清理数据。

**执行**：新增 `src/network.test.js`；修改 `src/network.js`、`src/client.js`、`tests/browser-e2e.mjs`。测试结果和 Actions/提交须以 GitHub 实际记录为准，不能提前写成功。

**后续优先事项**：测试对短暂丢线的提示与手机交互误触；为不同岗位添加真正能改变货架/雨窗/旧账和客人反应的独立操作；画风以独立美术资产和真实 APK 截图逐层优化，不以随机 SVG 人偶或整屏生图替代。
