# 未命名冬季窗口小店｜当前有效美术及 UI 方向（2026-10-27）
**这份规范替换之前“只允许程序化像素、二色套印、旧书版画”及“生成图片不可进入游戏”限定。用户最新明确选定由 GPT 生成并在本对话展示的冬季窗口便利店画面。所有新测试和每小时开发必须遵守本文件。**
## 唯一已确认的视觉基准
以本对话先前生成的 941×1672《冬日雪窗便利店收银界面》为比例/氛围/造型/色彩基准（不能将完整参考图假扮为可玩场景）。画风为可爱的精致日系 2D 平涂角色与精细物件，冬季蓝白海军蓝 + 暖橙木质，灯光暖外雪冷，不模仿第三方角色、名称或商标。旧色块人偶、旧像素顾客、单调几何柜台不能作为最终玩家可见美术。
## 场景及可编辑资产
玩家是狭小售货亭内部第一人称。正中一扇可开启并能看到顾客的真实窗口；左右各有能储物且实际计算容量的货架；吊柜关/开、抽屉关/开两套图；前景柜台和真实交接垫；商品、各顾客、灯、雪景、升级牌、按钮分离，各自由游戏状态控制。**默认背景**须用纯计算实现缓慢呼吸的斜条、方块、圆角矩形和光带循环，不是扁平大 PNG。
现有 `assets/anime/*.webp` 是从用户批准 GPT 原图表拆分的运行资源；导入器仅能下载 200×150 缩略图源，必须继续补全**高清**、干净边缘和精准裁切，视觉未达到参考图前不得标为“最终美术完成”。源表保留在用户会话素材库；资源要可逐一替换、不影响经济存档。
## UI
固定一屏，安卓 320×568、360×800、390×844、412×915、844×390 手机横屏、1280×720 桌面适配。顶部只显示店铺天数、资金、口碑/店长，主体至少 65% 视觉面积，底部触摸按钮尺寸不小于 44 CSS px，分层操作交谈、交接、收款、补货和委托。所有文字由程序排版，不使用 AI 图片上的伪字。
## 测试
每轮先核对 main 最新 SHA、上一轮失败及 Actions。Node 测试+Chromium 手机竖横屏 screenshot+双端 WebRTC+旧 v3 localStorage 恢复+Android Actions。不得通过美术静态贴图替代交互：柜门开/关、窗口、每个货架、物品位置、容量、第一人称手持、顾客移动、多人同步仍要可点可验收。
必须公开真实截图供用户逐步验收；不能把 Chromium 脚本当真人长时间试玩，也不能把 WebView 测试壳称原生游戏引擎。自动下载 APK 固定 prerelease 标签只更新**下载链接**，不能静默升级用户手机已安装 APK；正式保数据升级要稳定签名 keystore。
## 当前核心玩法
保留现有售货、联机店长/店员、顾客会话、邻里委托、每日结算、存档、暖气/货架升级、口碑。下一阶段构建更多经营内容，而非回退到“抓伪人”按钮投票为主。
