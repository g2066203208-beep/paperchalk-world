# 未命名游戏 · 真正可玩验收门槛

此文档是开发验证标准，不是宣传文案。当前原型的线索按钮和投票不是用户要求的完整多人互动，不得以 CI 通过代替游戏体验合格。

## 首个可玩三分钟垂直切片（P0）
玩家进入同一间深夜小店，第一位客人**可见地进门、来到柜台、拿出商品或购物清单**。游戏必须做到：
1. 货架商品是独立物件。玩家可触摸拿起、检查、放回或移到柜台，画面与库存状态同步变化，不是按「观察」显示一段文字。
2. 柜台可真实进行一次交易、找零或核对物品，错误会导致可观察到的损失或顾客反应。
3. 窗边可操作灯、窗帘或门铃；改变后能在场景中观察到异样，而不是纯文本提示。
4. 账本里的订单与实际商品有可关联字段。玩家真正选择两条记录进行比对，将对应物件或记录放上线索板。
5. 客人有等待、催促、递物、犹豫、转身或离店等独立反馈，表情/动作受到玩家行为影响。
6. 单人可以切换各工作台完成全套流程；从开始到结果至少有可重复玩的连续 3 分钟内容。

## 多人合作验收
双玩家时一人处理商品、另一人操作其他工作台，两个行为产生真正的依赖与互相影响；不同玩家的触摸不能覆写队友未处理的操作。共享事实与状态由房主统一结算，操作要有去重与重放保护。多人之间不能只看同一张文字线索板投票。

## 美术和手机验收
- 场景、柜台、窗户、货架、灯、商品、人物、表情、手势、UI 必须是独立资源或独立渲染层；不是整张游戏截图。
- 先经过美术风格探索和手机截图验证，禁止沿用用户已经否定的视觉方向。
- 人物至少有待机、递物、等待、被拒绝四种与玩法对应的可读状态。
- 支持 320×640、360×800、390×844、412×915，操作目标 44 CSS px 起，核心交互不被底部系统手势区遮挡。

## 存档与发布不可退化
保留 GitHub Pages 的发布 URL、WebView 数据 origin、Android applicationId 与 signing scheme、现有本地存档键以及联机兼容协议。这些是内部技术标识，不代表游戏标题。未经真实安卓设备和跨签名/跨版本验证，不宣称 APK 可以无损自动安装升级。
